# Cloudflare Free plan: DNS, CDN/caching, speed, traffic management, network settings, Web Analytics and Zaraz (state as of 2026-10-14)

*Method note: nearly all facts below come from the raw Markdown of developers.cloudflare.com pages pulled on 2026-10-14 (each page's own "Last updated" date is given where it matters), the official plan comparison at cloudflare.com/plans/network-cdn, the Cloudflare Service-Specific Terms (Application Services, "Last updated: September 28, 2026") and Cloudflare changelog posts. Labels used for every item: [FREE-FOREVER] = free allowance with no end date; [FREE-BETA] = free while in beta; [TRIAL/CREDITS] = free trial or credits; [PAID-ONLY] = no Free-plan availability (paid plan or paid add-on required). Items marked "(search-tool)" were read through the Cloudflare documentation search tool, which returns the same docs text. Rules products (Cache/Config/Origin/Transform/Redirect/Compression Rules, Page Rules, Snippets), Cloudflare for SaaS, security/SSL, Zero Trust and developer-platform products are deliberately not covered here.*

## 1. Authoritative DNS on Free (record limit, types, proxied vs DNS-only, CNAME flattening, DNSSEC and multi-signer, analytics, comments/tags, BIND import/export, zones per account, paid boundary, domain registered elsewhere)

### Takeaway
Cloudflare authoritative DNS is [FREE-FOREVER] on every plan with no query cap and no per-query charge. A Free zone gets a 200-record quota (1,000 only if the zone was created before 2024-09-01), the primary (full) setup only, apex CNAME flattening by default, one-click DNSSEC, record comments, batch edits, BIND import/export, 30-day DNS analytics, and a free API. Secondary DNS, CNAME (partial) setup, subdomain setup, custom/account nameservers, Foundation DNS, NSEC3, flatten-all/per-record CNAME flattening, record tags and DNS Firewall are [PAID-ONLY] (Business or Enterprise). The number of zones allowed per Free account is not documented anywhere I could find.

### Cited Findings
#### Free-forever DNS allowances
- [FREE-FOREVER, GA] "Cloudflare offers free DNS services to customers on all plans." Cloudflare "never limits or caps DNS queries"; Free, Pro and Business are not charged for DNS queries; Enterprise pricing uses monthly query volume as an input. Cloudflare DNS needs no change of hosting or registrar, only a change of authoritative nameservers. At limit: there is no query limit to hit. — [DNS FAQ](https://developers.cloudflare.com/dns/faq/)
- DNS product page: "Available on all plans"; features listed are DNS records, DNSSEC (with Multi-signer DNSSEC) and CNAME flattening. Internal DNS and "private origins (Beta)" are Enterprise-only. — [Cloudflare DNS](https://developers.cloudflare.com/dns/)
- Cloudflare markets DNS as free with "Free API access", DNSSEC support and Terraform/Ansible-style infrastructure-as-code control. — [Cloudflare DNS product page](https://www.cloudflare.com/dns/)
- Per-zone DNS record quota (docs updated 2026-10-06): Free zones created before 2024-09-01 UTC = 1,000; Free zones created on or after 2024-09-01 UTC = 200; Pro = 3,500; Business = 3,500; Enterprise = no per-zone limit (account-level quota, default 1,000,000 public plus 1,000,000 internal records, counted separately). — [DNS records quota](https://developers.cloudflare.com/dns/manage-dns-records/#dns-records-quota)
- At limit: "To create new records yourself through the dashboard or API, your zone must still be within its record limit" (creation is refused). Records that other Cloudflare services create for you (example: TXT and MX added by Email Routing) also count, enforced with "a small buffer". Dashboard warns at 85% of quota (added 2026-10-06). Quota and usage readable via API. — [DNS records quota](https://developers.cloudflare.com/dns/manage-dns-records/#dns-records-quota); [Changelog 2026-10-06](https://developers.cloudflare.com/changelog/post/2026-10-06-dns-records-quota-warning/)
- SUPERSEDED: the old "1,000 records per Free zone" figure no longer applies to zones created on/after 2024-09-01 (now 200). A May-2026 third-party blog claims 3,000/1,000 and unlimited domains; that contradicts the official numbers above and should not be used. — [DNS records quota](https://developers.cloudflare.com/dns/manage-dns-records/#dns-records-quota); contradicted by [eastondev blog](https://eastondev.com/blog/en/posts/dev/20260526-cloudflare-free-limits/) (secondary source, via search)
- Record comments: Free = Yes, 100 characters, 1 per record (Pro/Business/Enterprise 500 chars). Record tags: Free = No ([PAID-ONLY]; Pro+ has name 32 chars, value 100 chars, 20 tags/record). Comments/tags only on primary (full) and partial zones. — [Record attributes](https://developers.cloudflare.com/dns/manage-dns-records/reference/record-attributes/)
- Record types documented: A, AAAA, CNAME (the only proxiable types); MX; TXT; CAA; SRV; SVCB and HTTPS; PTR; SOA (auto-created; editing SOA values is Enterprise-only); NS; DS and DNSKEY; plus URI, NAPTR, SSHFP, TLSA, SMIMEA and CERT. Limits: 4,096 bytes wire format per record; records sharing name and type may total at most 8,192 characters; at most 10 NS records per delegation name (7 recommended). Underscores and any octets are valid in labels; FQDN max 253 characters, label max 63. — [DNS record types](https://developers.cloudflare.com/dns/manage-dns-records/reference/dns-record-types/)
- Wildcard records: "Customers on all plans can create and proxy wildcard DNS records." — [Wildcard DNS records](https://developers.cloudflare.com/dns/manage-dns-records/reference/wildcard-dns-records/)
- TTL: proxied records are fixed at Auto = 300 seconds (not editable); DNS-only records can use 60 seconds (non-Enterprise; 30 s Enterprise) to 1 day; Auto = 300 s. — [TTL](https://developers.cloudflare.com/dns/manage-dns-records/reference/ttl/)
- Proxied vs DNS-only: only A, AAAA and CNAME serving HTTP/HTTPS can be proxied (orange cloud); proxied names answer with Cloudflare anycast IPs and get CDN, WAF and caching; DNS-only names return your real origin IP and only get DNS analytics (no HTTP analytics). If any A/AAAA at a name is proxied, all are treated as proxied. Proxying is on by default when onboarding via dashboard. — [Proxy status](https://developers.cloudflare.com/dns/proxy-status/)
- Proxy limitations: non-standard ports or TCP/UDP apps need Spectrum; zones in "pending" state answer DNS-only until ownership is verified (up to 24 hours); Windows NTLM/Kerberos is incompatible; some CNAME targets (e.g. dkim.amazonses.com, *.onmicrosoft.com, dkim2.mcsv.net) cannot be proxied. — [Proxying limitations](https://developers.cloudflare.com/dns/proxy-status/limitations/)
- HTTPS (SVCB) records are auto-generated on the fly for proxied names when HTTP/2 or HTTP/3 and Universal SSL are on; manual HTTPS records on proxied names are not served; manual HTTPS records work only if every record at that name is DNS-only. — [DNS record types](https://developers.cloudflare.com/dns/manage-dns-records/reference/dns-record-types/#svcb-and-https)
- CNAME flattening: "occurs by default for all plans" when the zone apex (@) is a CNAME. Proxied CNAMEs are flattened by default. If the CNAME target is in the same zone, flattening proceeds regardless of the setting. — [CNAME flattening setup](https://developers.cloudflare.com/dns/cname-flattening/set-up-cname-flattening/)
- [PAID-ONLY] "CNAME flattening for all CNAME records" (`flatten_all_cnames`) and per-record flatten (`flatten_cname`, `cf-flatten-cname` tag) require a paid zone. Gotchas: cross-account CNAME to a proxied record = Error 1014; flatten-all can break third-party CNAME verification; a dangling CNAME returns NODATA. — [CNAME flattening setup](https://developers.cloudflare.com/dns/cname-flattening/set-up-cname-flattening/); [CNAME flattening](https://developers.cloudflare.com/dns/cname-flattening/)
- DNSSEC: part of the "all plans" DNS product. One-click "Enable DNSSEC" on DNS Settings; Cloudflare signs the zone and generates a DS record to add at the registrar; preferred algorithm 13 (ECDSA P-256 / SHA-256). DS is added automatically for Cloudflare Registrar domains and .ch/.cz; Cloudflare publishes CDS and CDNSKEY records so RFC 8078 registrars can auto-update DS. When moving an existing signed domain, disable DNSSEC at the old registrar first (wait out the DS TTL, often 24-48 h) or resolvers return SERVFAIL. — [DNSSEC](https://developers.cloudflare.com/dns/dnssec/); [Validation and keys](https://developers.cloudflare.com/dns/dnssec/validation-and-key-management/)
- Multi-signer DNSSEC (RFC 8901 models 1 and 2; model 2 recommended) plus the "Multi-provider DNS" setting for primary zones: the docs state no plan restriction, but the full setup "can only be completed using the API" and the other DNS provider must support multi-signer. — [Multi-signer about](https://developers.cloudflare.com/dns/dnssec/multi-signer-dnssec/about/); [Multi-signer setup](https://developers.cloudflare.com/dns/dnssec/multi-signer-dnssec/setup/); [Nameserver options](https://developers.cloudflare.com/dns/nameservers/nameserver-options/)
- [PAID-ONLY] NSEC3: "only available for zones on the Enterprise plan" (default is compact denial of existence). — [NSEC3](https://developers.cloudflare.com/dns/dnssec/enable-nsec3/)
- DNS analytics, Free column (page updated 2026-10-02): available; max time interval per zone 30 days, per account 7 days; historical data per zone 31 days, per account 8 days (Pro/Business 31/7/31/8; Enterprise 62 days). Dimensions: query name, query type, response code, data center, source IP, destination IP, protocol, IP version. GraphQL datasets `dnsAnalyticsAdaptive` and `dnsAnalyticsAdaptiveGroups`. — [DNS analytics and logs](https://developers.cloudflare.com/dns/additional-options/analytics/)
- SUPERSEDED: before 2026-10-02 "Free and Pro domains could see between 24 hours and 8 days of history depending on the dataset." — [Changelog 2026-10-02](https://developers.cloudflare.com/changelog/post/2026-10-02-30-days-analytics-on-every-plan/)
- Batch DNS record changes: all plans; operations per action Free = 200 (Pro/Business/Enterprise 3,500); not atomic across the network. — [Batch record changes](https://developers.cloudflare.com/dns/manage-dns-records/how-to/batch-record-changes/)
- BIND zone file import/export (dashboard or API `POST/GET /zones/{id}/dns_records/import|export`): zone file max 256 KiB (262,144 bytes); API limit three requests per minute per user; `$ORIGIN`, `$TTL`, `$GENERATE` supported; `$INCLUDE` rejected with a parsing error; `cf-proxied` tag overrides the "proxy imported records" default; `cf-flatten-cname` only meaningful on paid zones. No Free-specific restriction is stated. — [Import and export records](https://developers.cloudflare.com/dns/manage-dns-records/how-to/import-and-export/)
- Shadowed-record warnings (records hidden under a subdomain delegation) are now shown for all zones (2026-09-14). Account-level "enforce DNS-only" kill switch (API-only, turns every proxied record in the account to DNS-only, exposes origin IPs) was added 2026-04-28; no plan restriction stated. New dashboard DNS records page rolled out 2026-05-20 to 2026-07-03 (Free first). — [Changelog 2026-09-14](https://developers.cloudflare.com/changelog/post/2026-09-14-shadowed-record-warnings/); [Enforce DNS-only](https://developers.cloudflare.com/dns/proxy-status/enforce-dns-only/); [Changelog 2026-05-20](https://developers.cloudflare.com/changelog/post/2026-05-20-new-dns-records-ux/)
#### Using Cloudflare DNS for a domain registered elsewhere (full setup prerequisites)
- Steps: create account; own a domain; dashboard "Onboard a domain"; choose plan; add/scan DNS records; change nameservers at the registrar to the two assigned `<name>.ns.cloudflare.com` servers. "A primary setup (also known as full) is the most common and the only one available for Free or Pro plans." Domain must be one level below a Public Suffix List TLD (lower-level subdomains need Enterprise subdomain setup). Zone stays Pending (DNS-only) until verified. Nameserver names are fixed at zone creation (even Support cannot change them) and you can no longer preset Cloudflare nameservers at the registrar before creating the zone. Domains bought at Cloudflare Registrar must remain on Cloudflare nameservers. Cloudflare Registrar sells at cost ("Starting at $7.85") and is optional. — [Set up a primary zone](https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/) (search-tool); [Nameserver options](https://developers.cloudflare.com/dns/nameservers/nameserver-options/); [Plans: Network & CDN](https://www.cloudflare.com/plans/network-cdn.md)
- Account creation: since 2026-08-04 a user can create up to 5 standalone Free accounts from the dashboard (user needs at least 7 days tenure). — [Changelog 2026-08-04](https://developers.cloudflare.com/changelog/post/2026-08-04-free-dashboard-button/)
#### Paid-only DNS boundary
- [PAID-ONLY] CNAME (partial) setup: Free No, Pro No, Business Yes, Enterprise Yes (not supported on Cloudflare Registrar domains). — [Partial setup](https://developers.cloudflare.com/dns/zone-setups/partial-setup/)
- [PAID-ONLY] Zone transfers / Secondary DNS (Cloudflare as primary or secondary over AXFR/IXFR): Enterprise only. — [Zone transfers](https://developers.cloudflare.com/dns/zone-setups/zone-transfers/); [Cloudflare as secondary](https://developers.cloudflare.com/dns/zone-setups/zone-transfers/cloudflare-as-secondary/)
- [PAID-ONLY] Subdomain setup: Enterprise only. — [Subdomain setup](https://developers.cloudflare.com/dns/zone-setups/subdomain-setup/)
- [PAID-ONLY] Custom nameservers: zone custom nameservers = Business or Enterprise; account custom nameservers = Enterprise self-serve or Business after contacting Support. Advanced nameservers / Foundation DNS (advanced nameservers on foundationdns.com/.net/.org, account-unique DNSSEC keys, custom SOA/NS TTL, DNS zone defaults) = Enterprise only. Nameserver sets (beta, announced 2026-10-14) = Enterprise. — [Custom nameservers](https://developers.cloudflare.com/dns/nameservers/custom-nameservers/); [DNS FAQ](https://developers.cloudflare.com/dns/faq/); [Foundation DNS](https://developers.cloudflare.com/dns/foundation-dns/) (summarizing fetch quoting "only available to Enterprise customers"); [Changelog 2026-10-14](https://developers.cloudflare.com/changelog/post/2026-10-14-nameserver-sets/)
- [PAID-ONLY] DNS Firewall: "Enterprise-only paid add-on". Internal DNS (GA 2026-07-15) and private origins (beta): Enterprise. — [DNS Firewall](https://developers.cloudflare.com/dns/dns-firewall/); [Changelog 2026-07-15](https://developers.cloudflare.com/changelog/post/2026-07-15-internal-dns-ga/)
- Reverse zones / PTR: only for customers who own an IP prefix; use the Free plan for fewer than 200 PTR records. — [Reverse zones](https://developers.cloudflare.com/dns/additional-options/reverse-zones/)

### Inferences
- Idea: run the website, API and app subdomains in one Free zone (200 records is ample: apex flattened CNAME, www, api, app, MX/SPF/DKIM/DMARC TXT), turn on DNSSEC, keep mail and verification records DNS-only, and manage everything with the free DNS API/Terraform plus BIND export as a backup.
- Idea: add record comments (100 chars) as lightweight documentation; use batch endpoints (200 ops) for deploy-time record swaps.
- A zone created before 2024-09-01 may still hold the 1,000 quota; check each zone's quota through the DNS usage API instead of assuming 200.
- Because partial (CNAME) setup is Business+, a Free-plan site must delegate the entire domain to Cloudflare; "use Cloudflare only for app.example.com while DNS stays elsewhere" is a paid pattern.

### Gaps
- Number of zones (domains) allowed per Free account: the old Account-limits page returns 404 and no current official cap was found (only a third-party claim of "unlimited", unreliable).
- Multi-signer DNSSEC / Multi-provider DNS: no plan restriction is stated in the docs, but I found no positive confirmation of Free availability; treat as "not stated".
- Foundation DNS and the DNS-index "Enterprise" statements were read through summarizing fetches of the live page; the plan labels agree with the Nameservers/FAQ pages.

## 2. CDN and caching on Free (bandwidth terms, default behavior, file types, size limits, Tiered Cache, Cache Reserve, Always Online, Crawler Hints, purge, Development Mode, Browser Cache TTL, cache analytics, Argo/Smart Shield)

### Takeaway
The CDN itself is [FREE-FOREVER] on Free with no documented bandwidth cap, but the Service-Specific Terms bar serving video or a disproportionate share of large files through the CDN without Paid Services (Stream, Images, Developer Platform). Free gets all five purge methods (since 2025-04-01) under account-level rate limits (single-URL 800 URLs/s; hostname/tag/prefix/everything 5 requests/minute), Smart Tiered Cache, Always Online (30-day crawl), Crawler Hints, Early Hints, Development Mode (3 h), 512 MB max cacheable file and 100 MB max upload. Cache Analytics, Query String Sort, Regional/Generic-Global Tiered Cache, Cache Reserve and Argo are not on Free.

### Cited Findings
#### Bandwidth and legal boundary
- Plan comparison lists CDN as "Included" on Free alongside DNS, Universal SSL, WAF and free managed ruleset; no bandwidth figure appears. Cloudflare's CDN page says "Bandwidth costs are bundled" and no per-GB CDN price is listed for Free. — [Plans: Network & CDN](https://www.cloudflare.com/plans/network-cdn.md); [CDN page](https://www.cloudflare.com/cdn/)
- Service-Specific Terms, "Content Delivery Network (Free, Pro, or Business)": the CDN "can be used to cache and serve web pages and websites. Unless you are an Enterprise customer, Cloudflare offers specific Paid Services (e.g., the Developer Platform, Images, and Stream) that you must use in order to serve video and other large files via the CDN." Cloudflare may disable or limit CDN access if you serve video or "a disproportionate percentage of pictures, audio files, or other large files" without those services, and "will use reasonable efforts to provide you with notice". — [Service-Specific Terms](https://www.cloudflare.com/service-specific-terms-application-services/)
#### Default behavior and limits
- Cloudflare does NOT cache when Cache-Control is `private`, `no-store`, `no-cache` or `max-age=0`, when Set-Cookie is present, or for non-GET methods; it DOES cache with `Cache-Control: public` plus max-age > 0 or a future `Expires` (max-age wins). Caching is by file extension, not MIME type; HTML and JSON are not cached by default; robots.txt is. Default extensions: 7Z, AVI, AVIF, APK, BIN, BMP, BZ2, CLASS, CSS, CSV, DOC, DOCX, DMG, EJS, EOT, EPS, EXE, FLAC, GIF, GZ, ICO, ISO, JAR, JPG, JPEG, JS, MID, MIDI, MKV, MP3, MP4, OGG, OTF, PDF, PICT, PLS, PNG, PPT, PPTX, PS, RAR, SVG, SVGZ, SWF, TAR, TIF, TIFF, TTF, WEBM, WEBP, WOFF, WOFF2, XLS, XLSX, ZIP, ZST. Default edge TTLs without cache headers: 200/206/301 = 120 min; 302/303 = 20 min; 404/410 = 3 min; other codes not cached. Origin Cache Control is on by default for Free/Pro/Business. Request collapsing (cache lock) sends one origin request per asset per data center on a miss. — [Default cache behavior](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)
- Max cacheable file: Free, Pro, Business = 512 MB (Enterprise default 5 GB). Max upload (request body): Free 100 MB, Pro 100 MB, Business 200 MB, Enterprise up to 5 GB (self-serve since 2026-09-04; Enterprise default 500 MB). Over the limit = HTTP 413. Workarounds: chunk uploads, use a DNS-only record, or upgrade. "Maximum Upload Size" is adjustable on the zone Network page. — [Default cache behavior](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/#upload-limits); [Error 413](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/4xx-client-error/error-413/) (search-tool); [Changelog 2026-09-04](https://developers.cloudflare.com/changelog/post/2026-09-04-enterprise-self-serve-upload-limits/)
- Edge Cache TTL: Free = Yes, minimum 2 hours (Pro 1 hour; Business/Enterprise 1 second). Browser Cache TTL: Free = Yes; default 4 hours; minimum 1 second via the setting (2 minutes via Page Rules); "Respect Existing Headers" option; purging the CDN does not clear browsers. — [Edge and Browser Cache TTL](https://developers.cloudflare.com/cache/how-to/edge-browser-cache-ttl/)
- Caching level (No Query String / Ignore Query String / Standard) is a basic zone setting; Query String Sort: Free No, Pro No, Business No, Enterprise Yes ([PAID-ONLY]). — [Caching levels](https://developers.cloudflare.com/cache/how-to/set-caching-levels/); [Query String Sort](https://developers.cloudflare.com/cache/advanced-configuration/query-string-sort/)
#### Purge and invalidation
- Purge (page updated 2026-09-29): Free = Yes with options URL, Hostname, Tag, Prefix and Purge Everything. Limits are per ACCOUNT and shared by all zones on the same plan, token-bucket. Single-file: Free 800 URLs per second, max 100 operations per request (Pro/Business 1,500/s; Enterprise 3,000/s, 500 ops). Hostname/tag/prefix/everything: Free 5 requests per minute, bucket size 25, max 100 operations per request (Pro 5/s, Business 10/s, Enterprise 50/s). At limit: requests wait for tokens (rate-limited). A 200 response only confirms receipt. — [Purge cache](https://developers.cloudflare.com/cache/how-to/purge-cache/)
- SUPERSEDED: tag/prefix/hostname/everything purge were previously Enterprise-only; since 2025-04-01 "All cache purge methods now available for all plans". — [Changelog 2025-04-01](https://developers.cloudflare.com/changelog/post/2025-04-01-purge-for-all/)
- NEW 2026-09-28: invalidation (soft purge) via `POST /zones/{id}/invalidate_cache` or "Invalidate Cache" on Caching > Configuration; marks content stale and revalidates with the origin (needs ETag or Last-Modified); same selectors as purge; counts toward the same rate limits; no plan restriction stated. — [Changelog 2026-09-28](https://developers.cloudflare.com/changelog/post/2026-09-28-cache-invalidation/); [Invalidate cached content](https://developers.cloudflare.com/cache/guides/invalidate-cache/)
#### Tiered Cache, Smart Shield, Cache Reserve, Argo
- Tiered Cache availability: Tiered Cache Yes, Smart Topology Yes on Free ([FREE-FOREVER]); Generic Global, Regional and Custom topologies = Enterprise only. Smart Tiered Cache picks the closest upper tier per origin automatically; cloud region hints (AWS, GCP, Azure, Oracle Cloud) are available on all plans at no extra cost (2026-04-17). — [Tiered Cache](https://developers.cloudflare.com/cache/how-to/tiered-cache/); [Changelog 2026-04-17](https://developers.cloudflare.com/changelog/post/2026-04-17-smart-tiered-cache-for-public-cloud/)
- Smart Shield (Argo, Tiered Cache, Cache Reserve, Health Checks now bundled): "available to all customers as an opt-in configuration"; proxied records required. Base "Smart Shield" package = Smart Tiered Cache + Connection Reuse (onboarding button reads "Get started for free", but the docs also say Free/Pro/Business "can purchase" Smart Shield and Smart Shield + Argo, price of base package not stated). "Smart Shield + Argo" adds Argo Smart Routing ("Starting at $5/mo", usage-billed, billing profile required). "Smart Shield Advanced" (adds Regional Tiered Cache and Cache Reserve with 2 TB storage) "is not currently available for Free, Pro, and Business customers". — [Smart Shield get started](https://developers.cloudflare.com/smart-shield/get-started/); [Plans: Network & CDN](https://www.cloudflare.com/plans/network-cdn.md); [Argo get started](https://developers.cloudflare.com/argo-smart-routing/get-started/)
- [PAID-ONLY] Cache Reserve: "requires a paid plan" / "A paid Cache Reserve plan is required"; usage pricing $0.015/GB-month storage, $4.50 per million Class A (writes), $0.36 per million Class B (reads), billable quantity rounded up to the next million; 30-day default retention; assets need TTL of at least 10 hours and a Content-Length header. The plans page still lists it as a "usage-based" add-on, while the Smart Shield docs place it in Enterprise-only Smart Shield Advanced (conflict; Free access unconfirmed). — [Cache Reserve](https://developers.cloudflare.com/cache/advanced-configuration/cache-reserve/); [Smart Shield Cache Reserve](https://developers.cloudflare.com/smart-shield/configuration/cache-reserve/)
- [PAID-ONLY] Argo Smart Routing: add-on, usage-based billing, requires a billing profile, not compatible with WebSockets. — [Argo get started](https://developers.cloudflare.com/argo-smart-routing/get-started/); [WebSockets](https://developers.cloudflare.com/network/websockets/)
#### Availability/resilience/SEO helpers
- Always Online (Internet Archive integration): Free = Yes; crawl interval Free every 30 days, Pro every 15, Business/Enterprise every 5. Serves archived static portions only when Cloudflare cannot reach the origin (5xx 520-527 conditions); shares your hostname and popular URLs from the last 5 hours with the Archive; banner shown to visitors. Terms: "as is", no SLA, not covered by support, may be discontinued without notice. — [Always Online](https://developers.cloudflare.com/cache/how-to/always-online/); [Service-Specific Terms](https://www.cloudflare.com/service-specific-terms-application-services/)
- Crawler Hints (IndexNow): Free = Yes, global zone toggle in Caching > Configuration; uses cache MISS signals. — [Crawler Hints](https://developers.cloudflare.com/cache/advanced-configuration/crawler-hints/)
- Development Mode: suspends edge caching and Polish for three hours (does not purge); toggle on Caching > Configuration. — [Development Mode](https://developers.cloudflare.com/cache/reference/development-mode/)
- Cache Analytics: Free = No ([PAID-ONLY]); Pro 7-day, Business/Enterprise 30-day retention. (The 2026-10-02 unified Analytics change lists a "Cache" tab but states plan access is unchanged; Free access to that tab unconfirmed.) — [Cache Analytics](https://developers.cloudflare.com/cache/performance-review/cache-analytics/); [Changelog 2026-10-02](https://developers.cloudflare.com/changelog/post/2026-10-02-30-days-analytics-on-every-plan/)
#### 2025-2026 cache platform changes affecting Free
- Cache now runs on a Pingora-based proxy (2026-05-04): unbuffered bypass by default, `Vary: *` forces bypass, Set-Cookie stripped on MISS and EXPIRED, fractional TTLs rounded down. Asynchronous stale-while-revalidate live for all Free/Pro/Business zones (2026-02-26). Audit logs for cache purge events (2025-11-25). — [Changelog 2026-05-04](https://developers.cloudflare.com/changelog/post/2026-05-04-pingora-powers-cache/); [Changelog 2026-02-26](https://developers.cloudflare.com/changelog/post/2026-02-26-async-stale-while-revalidate/); [Cache changelog](https://developers.cloudflare.com/changelog/product/cache/)

### Inferences
- Idea: ship static assets with `Cache-Control: public, max-age=31536000, immutable`, tag responses with `Cache-Tag`, and purge or invalidate by tag at deploy time while staying under 5 hostname/tag/prefix/everything purge calls per minute (use single-URL purge, 800 URLs/s, for bulk).
- Idea: put video, large downloads and user uploads on object storage/Stream/Images (the Terms push these to Paid Services) and keep the CDN for pages, JS/CSS/images and API caching; stay well under 100 MB per proxied upload or use chunking/pre-signed uploads.
- Idea: Always Online plus stale-while-revalidate/stale-if-error is a free, partial safety net for origin outages (static pages only, 30-day crawl).
- Idea: if the origin sits on AWS/GCP/Azure/OCI, set the Smart Tiered Cache cloud region hint (free) to lift hit rates.

### Gaps
- Whether Cache Reserve can actually be bought on a Free-plan zone (plans page vs Smart Shield docs conflict).

### Inferences
- A "use every free offering" build on Free should combine: Free DNS + DNSSEC, proxied CDN with Smart Tiered Cache, Early Hints/HTTP3/Speed Brain/Zstd, Always Online and Crawler Hints, Web Analytics + 31-day zone analytics, Zaraz (<1M events) + Google tag gateway, WebSockets/gRPC and CF-IPCountry; leave Waiting Room, Load Balancing, Health Checks, Cache Reserve, Argo, Polish and APO as the paid upgrade path.
