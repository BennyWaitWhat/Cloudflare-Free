# Cloudflare Free Plan: Application Security, Bot and AI-Crawler Controls, Turnstile and SSL/TLS (state as of 2026-10-14)

_Method and legend. Everything below was read from developers.cloudflare.com (docs pages mostly "Last updated" Apr to Oct 2026), the Cloudflare blog and the Cloudflare changelog on 2026-10-14. Labels used: [FREE-FOREVER] = included on the Free plan with no expiry; [FREE-BETA] = free but beta/limited release; [FREE-TRIAL] = free until a stated date; [PAID-ONLY] = no Free tier. "Over limit" says what happens when the cap is hit; where the docs are silent I say "not stated". Fetch tools sometimes paraphrase tables, so every number below was either seen in two places or is flagged. Conflicts between Cloudflare pages are listed in the last section. Out of scope here (other researchers): DNS/CDN/cache/speed/Rules products, Zero Trust, developer platform. Cloudflare for SaaS and Logpush appear only as pointers because they touch SSL and security data._

## 1. DDoS protection on Free (unmetered L3/4/L7, what is configurable)

### Takeaway
Unmetered L3-L7 DDoS protection is included on every plan including Free, with no traffic cap or bill. Free can customize the HTTP DDoS managed ruleset with exactly one override (action and sensitivity, applying to all requests) and gets error-rate-based adaptive rules and HTTP DDoS alerts; scoped/multi-override (10), the Log action, proactive false-positive detection and richer adaptive signals are Enterprise or Enterprise + Advanced DDoS add-on. One Cloudflare page contradicts the "1 override on Free" claim (see Gaps).

### Cited Findings
- [FREE-FOREVER, GA] Standard unmetered DDoS protection (L3-7), HTTP DDoS attack protection and network-layer (L3/4) DDoS protection are all marked "Yes" for Free, Pro, Business, Enterprise and Enterprise + Advanced DDoS add-on. No traffic ceiling or reset period is stated (it is "unmetered"), so there is no over-limit or auto-billing path. — [DDoS overview](https://developers.cloudflare.com/ddos-protection/)
- Customization: "Managed rules customization" is Yes on Free; Enterprise adds the Log action; the Advanced DDoS add-on adds expression fields and multi-rule support. Ruleset overrides allowed: 1 on Free, Pro, Business and Enterprise; 10 with the Enterprise Advanced DDoS Protection add-on. Without the add-on you can deploy only one override and it always applies to all incoming requests (no custom scope expression). Over limit: you cannot add a second override, you edit the existing one. — [DDoS overview](https://developers.cloudflare.com/ddos-protection/); [Configure HTTP overrides in the dashboard](https://developers.cloudflare.com/ddos-protection/managed-rulesets/http/http-overrides/configure-dashboard/)
- An HTTP override changes the action and sensitivity of rules in the HTTP DDoS Attack Protection managed ruleset; it can be set ruleset-wide, per tag (category) or per rule, with tag/rule overrides taking priority over ruleset overrides; some rules are read-only. Dashboard path: zone > Security > Security rules > DDoS protection tab > Create override. — [Configure HTTP overrides in the dashboard](https://developers.cloudflare.com/ddos-protection/managed-rulesets/http/http-overrides/configure-dashboard/)
- Overrides take effect "within one or two minutes"; sensitivity can be lowered to "Essentially Off"; the Log action is only offered "if supported by your current plan and subscriptions". Documented use cases: mobile-app traffic blocked by a DDoS rule (lower sensitivity to Medium, Low or Essentially Off), and enabling an adaptive rule in challenge/block mode when location-based traffic looks like an attack. — [HTTP override examples](https://developers.cloudflare.com/ddos-protection/managed-rulesets/http/http-overrides/override-examples/)
- Adaptive DDoS protection: Free, Pro, Business and Enterprise get "error adaptive rules only"; all adaptive rules need the add-on. Traffic-profiling signals: error rates only on Free and Pro; error rates plus historical trends on Business and Enterprise; add-on adds client country, user agent, query string and ML scores. — [DDoS overview](https://developers.cloudflare.com/ddos-protection/)
- Proactive false-positive detection for new rules is Enterprise and add-on only. Advanced TCP Protection and Advanced DNS Protection are for Magic Transit customers only. — [DDoS overview](https://developers.cloudflare.com/ddos-protection/)
- Alerts: "HTTP DDoS Attack Alert" is included with "All Cloudflare plans"; "Layer 3/4 DDoS Attack Alert" needs Magic Transit and/or BYOIP; "Advanced HTTP DDoS Attack Alert" needs Enterprise with the Advanced DDoS add-on. — [Notifications available](https://developers.cloudflare.com/notifications/notification-available/)
- Network-layer DDoS overrides are defined at the account level (L3/4 DDoS protection page). The DDoS overview table does not separate Free from other plans for network-layer overrides. — [Configure network-layer overrides](https://developers.cloudflare.com/ddos-protection/managed-rulesets/network/network-overrides/configure-dashboard/)
- Evaluation order: HTTP DDoS Attack Protection (`ddos_l7`) is the first request phase, ahead of custom rules, rate limiting, managed rules and Super Bot Fight Mode. — [Security features interoperability](https://developers.cloudflare.com/waf/feature-interoperability/)

### Inferences
- Use idea: leave DDoS on its defaults; only create the single HTTP override if a legitimate mobile-app or API client is falsely mitigated (lower that rule's sensitivity instead of disabling it), and subscribe to the free HTTP DDoS Attack Alert.
- Because the override cap is a configuration cap and protection is unmetered, the only "limit" a Free user can hit is the 1-override cap, with no billing consequence.

### Gaps
- CONFLICT: the generic Security Settings page says "DDoS attack protection overrides are only available to Enterprise customers with the Advanced DDoS Protection subscription" ([Security settings](https://developers.cloudflare.com/security/settings/)), whereas the two DDoS pages say 1 override on every plan. I treated the two dedicated DDoS pages as authoritative; verify in a live Free zone.
- Not confirmed whether a Free zone can actually create network-layer (L3/4) overrides (account-level, probably Magic Transit/Spectrum accounts).
- Not fetched: Network Analytics / DDoS reporting availability on Free.

## 2. WAF on Free (managed ruleset, custom rules, rate limiting, lists, access tools, detections, analytics)

### Takeaway
Free gets the Free Managed Ruleset (the only managed ruleset, deployed by default), 5 custom rules (no regex, all actions except Log, no custom Block response), 1 rate limiting rule (IP key, Block only, 10 s period, 10 s block), 1 IP list (10,000 items), IP Access Rules (50,000 per account), User Agent Blocking (10 rules), the `password_leaked` leaked-credentials field, and Security Analytics/Events with sampled logs and 31-day retention. Zone Lockdown is not free. Regex, Log action, custom block responses, attack score, other managed rulesets, SDD and managed IP lists are paid.

### Cited Findings
**Plan summary table**
- WAF overview availability (Free column): Attack score No (Business one field); Leaked credentials detection Yes, "one field"; Malicious uploads detection and AI Security for Apps = Enterprise paid add-ons; Custom rules Yes; Rate limiting rules Yes, "one rule"; Advanced Rate Limiting = Enterprise add-on; WAF Managed Rules = "Free Managed Ruleset only"; Sensitive Data Detection Enterprise; Account-level WAF configuration Enterprise; Custom lists Yes; Managed IP Lists Enterprise; Email Address Obfuscation, Hotlink Protection, "Replace insecure JS libraries", IP Access rules, User Agent Blocking Yes; Security Analytics (zone) Yes, (account) Business+; Security Events "sampled logs only" on Free; Security Events alerts Business+; Advanced Security Events alerts Enterprise. The same table shows Zone Lockdown "Yes" for Free (contradicted below). — [WAF overview](https://developers.cloudflare.com/waf/)
- The cloudflare.com plan page lists for Free: Unmetered DDoS Protection, WAF, Free Managed Ruleset and Universal SSL "Included"; Bot Mitigation "Simple bots"; API Schema Validation "Up to 5 schemas"; Client-Side Security "Script monitoring"; API Shield, AI Security for Apps and L3 Network DDoS (Magic Transit) shown as "—". — [Cloudflare plans (Network and CDN)](https://www.cloudflare.com/plans/network-cdn.md)

**Evaluation order**
- Ruleset Engine request phases run in this order: `ddos_l7` (HTTP DDoS), `http_request_firewall_custom` (custom rules), `http_ratelimit` (rate limiting), `http_request_firewall_managed` (managed rules), `http_request_sbfm` (Super Bot Fight Mode); a terminating action stops later phases. IP Access Rules, Zone Lockdown, User Agent Blocking, Browser Integrity Check, Hotlink Protection, Security Level and Bot Fight Mode run outside the Ruleset Engine. Custom-rule Skip can skip rate limiting, managed rules and SBFM, but not Bot Fight Mode. — [Security features interoperability](https://developers.cloudflare.com/waf/feature-interoperability/)

**Free Managed Ruleset and the paid rulesets**
- [FREE-FOREVER] Cloudflare Free Managed Ruleset: "Available on all Cloudflare plans. Provides protection against high-impact and widely exploited vulnerabilities. The rules are safe to deploy on most applications." If the paid Cloudflare Managed Ruleset is deployed you do not need it because that ruleset has broader coverage. — [Managed rules](https://developers.cloudflare.com/waf/managed-rules/)
- Docs video: "If you're on a free plan, the free managed rule set is already deployed by default, so you don't have to do anything for this step." — [Application Security get started video](https://developers.cloudflare.com/videos/app-sec-get-started/)
- Paid managed rulesets: Cloudflare Managed Ruleset (known attacks and zero-days, frequently updated, some rules disabled by default, enable by technology tag such as `wordpress`), Cloudflare OWASP Core Ruleset (scoring model with threshold), Exposed Credentials Check (deprecated) are Pro+; Sensitive Data Detection is Enterprise only. Each managed ruleset can be deployed once per zone. Managed rules inspect request bodies up to 1 MB on Free (Enterprise 128 KB; Pro/Business "lower by default"). — [Managed rules](https://developers.cloudflare.com/waf/managed-rules/); [Cloudflare Managed Ruleset](https://developers.cloudflare.com/waf/managed-rules/reference/cloudflare-managed-ruleset/)
- 2026 Free Ruleset changelog (shows live coverage): Jul 21, 2026 new Block-mode rules for WordPress SQL injection (CVE-2026-60137) and WordPress RCE (CVE-2026-63030); Jul 29, 2026 new Block-mode Generic Rules RCE, Generic Rules XSS and File Upload RCE; Aug 7 and Aug 17, 2026 metadata refinements on WordPress XSS/RCE rules (detection and action unchanged). — [WAF changelog](https://developers.cloudflare.com/changelog/product/waf/); [WAF release 2026-07-21](https://developers.cloudflare.com/changelog/post/2026-07-21-waf-release/)

**Custom rules**
- [FREE-FOREVER] Custom rules per zone: Free 5, Pro 20, Business 100, Enterprise 1,000. Supported actions: "All except Log" on Free/Pro/Business. Regex: No on Free and Pro, Yes Business/Enterprise. Zone-level custom rulesets (API only, not in the dashboard): Free 1, Pro 2, Business 5, Enterprise 10; account-level rulesets Enterprise only. The 5-rule limit counts custom rules plus rules inside zone-level custom rulesets. Over limit: creation is refused (not stated as billed). — [Custom rules](https://developers.cloudflare.com/waf/custom-rules/)
- Operators: `matches` (regex) requires Business or Enterprise; the page lists no plan note for `wildcard`, `strict wildcard`, `contains`, `in` and the comparison operators. — [Rules language operators](https://developers.cloudflare.com/ruleset-engine/rules-language/operators/)
- The Log action is Enterprise-only; on plans without Log the docs recommend starting with Managed Challenge, reviewing Security Events, then switching to Block. A custom response for the Block action (HTML/text/JSON/XML body up to 2 KB, status 400-499, default 403) is "only available on Pro plans and above". — [Create a custom rule in the dashboard](https://developers.cloudflare.com/waf/custom-rules/create-dashboard/)
- Oct 9, 2026: field `cf.appsec.request.failed_detections` is usable in custom rules, rate limiting rules and Request Header Transform rules; "You can use it on all plans" (the plan must still include the detections and rule types you use). — [WAF changelog](https://developers.cloudflare.com/changelog/product/waf/)

**Rate limiting rules**
- [FREE-FOREVER] Free: 1 rule; expression fields limited to Path and Verified Bot; counting characteristic IP only (preset); counting period 10 s only; mitigation timeout 10 s only; counting model number of requests; no custom counting expression, no response-code/header counting (Business+), no cache exclusion. Pro: 2 rules, up to 1 min period, up to 1 h timeout. Business: 5 rules, up to 10 min period, up to 1 day timeout. Enterprise (app security): 100 rules (contract dependent), up to 65,535 s. Supported period values: 10, 15, 20, 30, 40, 45, 60, 90, 120, 180, 240, 300, 480, 600, 900, 1200, 1800, 2400, 3600, 65535, 86400 seconds (not all on all plans). — [Rate limiting rules](https://developers.cloudflare.com/waf/rate-limiting-rules/)
- Action on Free: Block (docs tell Free users to select Block, with IP preset, 10 seconds period and 10 seconds duration; Pro+ can use Managed Challenge). Default block response is HTTP 429; a custom response is Pro+. Throttling is an Enterprise add-on. — [Protect sensitive forms](https://developers.cloudflare.com/use-cases/solutions/protect-sensitive-forms-fraud-abuse/); [Create a rate limiting rule](https://developers.cloudflare.com/waf/rate-limiting-rules/create-zone-dashboard/)
- Free template: for leaked credentials Free users are pointed to a suggested rate limiting rule template that blocks IPs sending a leaked password more than five times per 10 seconds. — [Leaked credentials get started](https://developers.cloudflare.com/waf/detections/leaked-credentials/get-started/)
- SUPERSEDED: legacy "Rate Limiting" (Free: 1 rule, Block only, 1 min or 1 hour duration, 10 s or 1 min period; usage-billed) is no longer available; replaced by the rules above. — [Legacy rate limiting](https://developers.cloudflare.com/waf/reference/legacy/old-rate-limiting/); [Rate limiting rules](https://developers.cloudflare.com/waf/rate-limiting-rules/)

**Lists**
- [FREE-FOREVER] Custom lists: Free 1 list; Pro 10; Business 10; Enterprise 1,000. Max items across all custom lists: Free 10,000; Pro 10,000; Business 10,000; Enterprise 500,000. IP lists on all plans; hostname and ASN lists Enterprise only (up to 40 each; 10,000 hostname items, 30,000 ASN items); Managed IP Lists Enterprise only. No per-list item cap stated. Quota follows the highest plan in the account. — [Lists](https://developers.cloudflare.com/waf/tools/lists/)

**IP Access Rules, User Agent Blocking, Zone Lockdown**
- [FREE-FOREVER] IP Access rules: all plans, 50,000 rules per account, "Block by country" only on Enterprise; Allow rules bypass custom rules, rate limiting, WAF managed rules and deprecated firewall rules (allowing a country does not bypass managed rules) and do not appear in Security Events; Cloudflare recommends custom rules instead. An IP Access rule that matches first prevents Bot Fight Mode from triggering. — [IP Access rules](https://developers.cloudflare.com/waf/tools/ip-access-rules/); [Bot Fight Mode](https://developers.cloudflare.com/bots/get-started/bot-fight-mode/)
- [FREE-FOREVER] User Agent Blocking: all plans; rules Free 10, Pro 50, Business 250, Enterprise 1,000; actions Block, Non-Interactive Challenge, Managed Challenge, Interactive Challenge; wildcards (`*`) not supported; applies to the whole domain; runs after Zone Lockdown; a custom rule (`http.user_agent eq ...`) is recommended instead. — [User Agent Blocking](https://developers.cloudflare.com/waf/tools/user-agent-blocking/)
- [PAID-ONLY] Zone Lockdown: "available on paid plans" - Free No (0 rules), Pro 3, Business 10, Enterprise 200; Cloudflare recommends custom rules or an IP list instead. Confirmed on the raw page. — [Zone Lockdown](https://developers.cloudflare.com/waf/tools/zone-lockdown/)

**Security Level, Under Attack mode, Browser Integrity Check, Challenge Passage**
- Under Attack mode presents a Managed Challenge page ("Checking your browser before accessing...", decision within five seconds) to add layer-7 DDoS checks; it is off by default, "one of the last resorts", pauses access and affects analytics and API traffic; enable via zone Overview > Quick Actions, scope to paths with a configuration rule, or to ASNs/countries/IPs with IP Access Rules. In the new dashboard, API and Terraform the security level controls Under Attack mode; the IP threat score is always 0 and should not be used. Docs state no plan restriction. — [Under Attack mode](https://developers.cloudflare.com/fundamentals/reference/under-attack-mode/); [Security level](https://developers.cloudflare.com/waf/tools/security-level/)
- Browser Integrity Check: enabled by default; checks abused HTTP headers and challenges visitors with missing/nonstandard User-Agent; disable at Security > Settings or bypass selectively with a custom-rule Skip or configuration rule; docs state no plan restriction. — [Browser Integrity Check](https://developers.cloudflare.com/waf/tools/browser-integrity-check/)
- Challenge Passage (cf_clearance lifetime): default 30 minutes; Cloudflare recommends 15 to 45 minutes; set at Security > Settings; docs list no plan restriction or min/max by plan. — [Challenge Passage](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/challenge-passage/); [Security settings](https://developers.cloudflare.com/security/settings/)

**Leaked credentials detection**
- [FREE-FOREVER] `cf.waf.credential_check.password_leaked` is "Available on all plans"; `username_and_password_leaked` needs Pro+; `username_leaked`, `username_password_similar` and `cf.waf.auth_detected` need Enterprise; custom detection locations Enterprise only. Database: HIBP matched-password dataset (passwords only), Cloudflare-collected usernames, leaked pairs. A managed transform adds an `Exposed-Credential-Check` request header (1 pair leaked, 2 username leaked, 4 password leaked). Default coverage: Drupal, Joomla, Ghost, Magento, Plone, WordPress, Microsoft Exchange OWA plus generic patterns. Passwords are not stored or logged in plaintext. The "Exposed Credentials Check" managed ruleset is deprecated. — [Leaked credentials detection](https://developers.cloudflare.com/waf/detections/leaked-credentials/)
- Aug 20, 2026: detection now also scans Basic Authentication credentials in the `Authorization` header (automatic for zones with the feature on). — [WAF changelog](https://developers.cloudflare.com/changelog/product/waf/)
- Cloudflare states: "During our Birthday Week in 2024, we gifted leaked credentials detection to all customers, including everyone on a Free plan." (Account Abuse Protection launch post, dated Mar 12, 2026.) — [Announcing Account Abuse Protection](https://blog.cloudflare.com/account-abuse-protection)

**Attack score, SDD, uploads, AI**
- WAF attack score: Free No; Business gets one field (`cf.waf.score.class`, values attack / likely_attack / likely_clean / clean, "Requires a Cloudflare Business plan or above"); the numeric `cf.waf.score*` fields require Enterprise. — [WAF get started](https://developers.cloudflare.com/waf/get-started/); [cf.waf.score.class](https://developers.cloudflare.com/ruleset-engine/rules-language/fields/reference/cf.waf.score.class/); [cf.waf.score](https://developers.cloudflare.com/ruleset-engine/rules-language/fields/reference/cf.waf.score/)
- [PAID-ONLY] Sensitive Data Detection (Enterprise), Malicious uploads detection (Enterprise add-on), AI Security for Apps (Enterprise add-on), Application Profiles (closed beta for invited Enterprise, Sep 7, 2026). — [WAF overview](https://developers.cloudflare.com/waf/); [WAF changelog](https://developers.cloudflare.com/changelog/product/waf/)

**Security Analytics and Security Events**
- Security Events retention: up to 31 days on all plans (max query window 30 days Free/Pro/Business, 31 Enterprise). Security Analytics retention: 31 days Free/Pro/Business, 90 days Enterprise. Free: sampled logs only, no account-level dashboard, no event export, no print report; Pro adds print report; Business/Enterprise add export of up to 500 events. Sampling applies for large volumes and shrinks with a smaller time range. — [Security Events](https://developers.cloudflare.com/waf/analytics/security-events/)
- Security Events alerts (WAF) need Business or Enterprise; Advanced Security Events alert needs Enterprise. — [Notifications available](https://developers.cloudflare.com/notifications/notification-available/)

### Inferences
- Use ideas: (1) one custom rule with Managed Challenge on `/login`, `/signup`, `/api/auth/*`; (2) the single rate-limit rule on the most abused POST endpoint (10 s window, Block); (3) an IP list holding admin IPs referenced from a custom rule to emulate Zone Lockdown; (4) a custom rule or the rate-limit template using `password_leaked` on login/registration; (5) a custom rule using `cf.appsec.request.failed_detections` to challenge repeat offenders.
- Free rate limiting is a short-burst tool: a 10-second block means a patient attacker is only slowed; pair with Turnstile and Bot Fight Mode.
- Over-limit behavior for all rule counts is a hard configuration cap; nothing fetched describes metering or billing for WAF rule counts on Free.

### Gaps
- CONFLICT: Zone Lockdown (overview table says Free Yes; dedicated page says Free No / 0 rules, "available on paid plans"). I treated the dedicated page as correct.
- No dedicated reference page exists for the Free Managed Ruleset (the guessed URL returned 404); its coverage is only described in prose plus changelog rules; the full rule list and whether Free can create overrides/exceptions for it were not found (docs list no Free-specific restriction).
- Plan availability for Under Attack mode, Browser Integrity Check, Security Level and Challenge Passage is never stated on their pages; they appear without plan notes in the Security Settings page, so I treated them as available on Free but did not see an explicit "Free: Yes".
- Which Block-related actions beyond Block exist for Free in IP Access Rules and which actions custom-rule "Skip" offers on Free were not itemized.
- Over-limit/billing statements for WAF caps are absent from the docs.

## 3. Bots, AI-crawler controls, AI Crawl Control, robots.txt and Content Signals

### Takeaway
Free gets Bot Fight Mode (cannot be skipped, JS detections forced on), AI bot policies for Search/Agent/Training (all plans since 2026-07-01), AI Labyrinth, managed robots.txt/Bot Preference Sync with Content Signals, and AI Crawl Control (user-agent detection, 24-hour metrics, allow/block). Super Bot Fight Mode starts at Pro; custom 402/403 block responses, referrer analytics and AI-training redirects need a paid plan; Pay per Crawl, Monetization Gateway and Pay Per Use are closed/limited betas. Precursor (session-based detection) is rolling out to all customers but its Free-plan status is unclear and it is free only until GA.

### Cited Findings
**Bot Fight Mode and JavaScript detections**
- [FREE-FOREVER, GA] Bot Fight Mode: "All Free customers"; detects "Simple bots from cloud hosting providers and headless browsers"; action is a "computationally expensive challenge"; applies to all traffic across the domain; also notifies Bandwidth Alliance partners. Free-plan additional features listed: Block AI bots, AI Labyrinth, instruct AI bot traffic with robots.txt. — [Bots plans: Free](https://developers.cloudflare.com/bots/plans/free/); [Bot Fight Mode](https://developers.cloudflare.com/bots/get-started/bot-fight-mode/)
- Limits: cannot be customized, and cannot be bypassed with WAF custom-rule Skip/Allow, Page Rules or Bypass because it does not run on the Ruleset Engine; an IP Access rule matching first stops it; it may challenge API and mobile-app traffic; for exceptions use Super Bot Fight Mode (Pro+). Verified bots are excluded in default configurations. — [Bot Fight Mode](https://developers.cloudflare.com/bots/get-started/bot-fight-mode/); [Verified bots](https://developers.cloudflare.com/bots/concepts/bot/verified-bots/)
- Enable: Security > Settings > filter "Bot traffic" > Bot fight mode. — [Stop malicious bots](https://developers.cloudflare.com/use-cases/solutions/stop-malicious-bots/)
- JavaScript Detections: on Free (Bot Fight Mode) "automatically enabled and cannot be disabled"; optional on Super Bot Fight Mode and Enterprise Bot Management; injected only into HTML page views (not AJAX/API/mobile), 15-minute lifespan, result in `cf_clearance`; strips ETags from affected HTML; skipped with `Cache-Control: no-transform`; CSP must allow `/cdn-cgi/challenge-platform/`, nonce via `<meta>` unsupported; enforcing via `cf.bot_management.js_detection.passed` needs Enterprise Bot Management. — [JavaScript detections](https://developers.cloudflare.com/bots/additional-configurations/javascript-detections/)
- Precursor (client-side, session-based behavioral detection): changelog Jul 13, 2026 says "rolling out to all customers"; enabled at Security > Settings > Precursor with modes Minimize Friction (default) and Maximize Security; supersedes JavaScript Detections (JSD is disabled when Precursor is enabled); Precursor Rules scope modes by path. The launch blog says Precursor "will be free to use until our GA release later this year" and calls Precursor and Turnstile "both features of our Enterprise Bot Management". — [Precursor changelog](https://developers.cloudflare.com/changelog/post/2026-07-13-precursor-session-based-detection/); [Precursor docs](https://developers.cloudflare.com/cloudflare-challenges/precursor/); [Introducing Precursor](https://blog.cloudflare.com/introducing-precursor)

**Super Bot Fight Mode and Bot Management (paid)**
- [PAID-ONLY] Super Bot Fight Mode: Pro, Business, and Enterprise without Bot Management. Pro can set an action for "Definitely automated" traffic, handle verified bots, static resource protection, WordPress optimization; "Likely automated" action begins at Business ("Not available on Pro"); supports Skip exceptions in custom rules. Enterprise Bot Management adds bot score, detection IDs and BotBase/Business Insights (Jul 1, 2026). — [Bots plans: Business/Enterprise](https://developers.cloudflare.com/bots/plans/biz-and-ent/); [Stop malicious bots](https://developers.cloudflare.com/use-cases/solutions/stop-malicious-bots/); [Bots changelog](https://developers.cloudflare.com/changelog/product/bots/)
- Bot Detection alerts need an account with at least one Enterprise zone. — [Notifications available](https://developers.cloudflare.com/notifications/notification-available/)

**AI bot policies (replace "Block AI bots")**
- [FREE-FOREVER, GA] Jul 1, 2026: "all customers - including those on the Free plan" can set Search, Agent and Training behaviors independently to Block (all pages), Block on pages with ads (uses Cloudflare automated ad-page detection), or Allow; each option covers Verified bots with that behavior plus additional unverified bots; configure at Security Settings > Configure AI bot policies. — [New options to manage AI traffic](https://developers.cloudflare.com/changelog/post/2026-07-01-ai-traffic-options/); [Block AI bots](https://developers.cloudflare.com/bots/additional-configurations/block-ai-bots/)
- The legacy "Block AI bots" toggle is marked "Deprecating on September 15, 2026". From September 15, 2026 new domains get updated defaults (Training and Agent blocked on pages that display ads, Search allowed), mixed-purpose Search+Training crawlers are blocked by all configurations that block AI training including the legacy option, and customers could opt out before that date. — [Block AI bots](https://developers.cloudflare.com/bots/additional-configurations/block-ai-bots/); [Bots changelog](https://developers.cloudflare.com/changelog/product/bots/)
- Search, Agent and Training are managed presets for all plans; signed agents became Verified bots on Jul 1, 2026; bots become verified via the BotBase submission form (Web Bot Auth signature, published IP list with stable UA, or reverse DNS, and respect for robots.txt). — [Verified bots](https://developers.cloudflare.com/bots/concepts/bot/verified-bots/)

**AI Labyrinth**
- [FREE-FOREVER, opt-in] Announced Mar 19, 2025 as "available on an opt-in basis to all customers, including the Free plan", single dashboard toggle (Security Settings > Bot traffic > AI Labyrinth), no pricing stated; injects invisible nofollow honeypot links, AI-generated pages (Workers AI, stored in R2) with no-index meta; logged in Security Analytics as "AI Labyrinth Served" / "AI Labyrinth Crawls" (not a block); no SEO or appearance impact; disabling stops new links immediately but existing links stay valid for a while. Cloudflare calls it a "first iteration". — [AI Labyrinth blog](https://blog.cloudflare.com/ai-labyrinth/); [AI Labyrinth docs](https://developers.cloudflare.com/bots/additional-configurations/ai-labyrinth/)

**Managed robots.txt, Bot Preference Sync, Content Signals**
- [FREE-FOREVER] "Managed robots.txt for AI crawlers is available on all plans." Bot Preference Sync generates robots.txt directives from Search/Agent/Training policies; existing robots.txt (HTTP 200) gets managed content prepended, no robots.txt gets a generated file; Training = Disallow plus Enable Bot Preference Sync also enables edge blocking for AI-training crawlers (mixed-use excluded); robots.txt is advisory. — [Managed robots.txt](https://developers.cloudflare.com/bots/additional-configurations/managed-robots-txt/)
- Content Signals Policy (Sep 24, 2025): three signals `search`, `ai-input`, `ai-train`; managed robots.txt customers (over 3.8 million domains) get `Content-Signal: search=yes, ai-train=no`; Free-plan zones with no robots.txt get only the commented policy text with no directives; zones with an existing robots.txt see no change; Free zones can turn the policy off in Security Settings; released under CC0; optional `content-use` extension in testing. — [Content Signals Policy blog](https://blog.cloudflare.com/content-signals-policy/); [Managed robots.txt](https://developers.cloudflare.com/bots/additional-configurations/managed-robots-txt/)

**AI Crawl Control (formerly AI Audit)**

## 4. Turnstile (CAPTCHA alternative)

## 8. SSL/TLS on Free (certificates, modes, edge options, paid boundary)

### Takeaway

### Cited Findings
**Universal SSL**
- [FREE-FOREVER] Available on Free, Pro, Business, Enterprise; Domain Validated; issued after the domain is active; Cloudflare handles issuance, renewal and deployment. Full setup covers the root domain and first-level subdomains; CNAME (partial) setup gives each proxied subdomain its own certificate at any depth. Served only for proxied DNS records. — [Universal SSL](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/); [Limitations](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/limitations/)

Validity: 90 days with auto-renewal starting 30 days before expiry; renewal attempts run until 24 hours before expiry; "Cloudflare only issues certificates with validity periods of three months or less"; HTTP DCV falls back to TXT after 15 days of failure for 90-day certificates. — [Universal SSL limitations](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/limitations/); [Validity periods](https://developers.cloudflare.com/ssl/reference/certificate-validity-periods/)
- CAs: Universal ECDSA is issued by Let's Encrypt, Google Trust Services or SSL.com (Sectigo only for backup certificates); Cloudflare chooses and can change the CA without notice; choosing the CA requires ordering an advanced certificate. — [Certificate authorities](https://developers.cloudflare.com/ssl/reference/certificate-authorities/); [Universal SSL limitations](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/limitations/)

## 9. Scrape Shield (Email Address Obfuscation, Hotlink Protection) and related content-protection settings

### Takeaway
Email Address Obfuscation (on by default) and Hotlink Protection are included on Free, as is "Replace insecure JavaScript libraries" (on by default on Free plans); all three live in the Security Settings "Client-side abuse" category.

### Cited Findings
- Scrape Shield is "a collection of settings meant to protect your site's content" (Email Address Obfuscation and Hotlink Protection); both are Yes on Free in the WAF overview. — [Scrape Shield](https://developers.cloudflare.com/waf/tools/scrape-shield/); [WAF overview](https://developers.cloudflare.com/waf/)
- [FREE-FOREVER] Email Address Obfuscation: "Cloudflare enables email address obfuscation automatically when you sign up"; replaces addresses in HTML with obfuscated links decoded by the deferred `email-decode.min.js` script; opt out with `<!--email_off-->...<!--/email_off-->`, JSON responses, or a configuration rule; skips attributes (except `a href`), script/noscript/textarea/xmp/head, non-HTML MIME types, `Cache-Control: no-transform` responses and code added by Workers; can misbehave with `<template>` tags. — [Email Address Obfuscation](https://developers.cloudflare.com/waf/tools/scrape-shield/email-address-obfuscation/)
- [FREE-FOREVER] Hotlink Protection: blocks image requests whose Referer does not include your domain (blank referers allowed); covers `gif`, `ico`, `jpg`, `jpeg`, `png` only; no effect on crawling but images will not render on Google Images, Pinterest or Facebook; exceptions via configuration rule or a folder named `hotlink-ok`; default state not stated; Cloudflare for SaaS custom hostnames may be blocked. — [Hotlink Protection](https://developers.cloudflare.com/waf/tools/scrape-shield/hotlink-protection/)
- [FREE-FOREVER] Replace insecure JavaScript libraries: "available in all Cloudflare plans, and is turned on by default on Free plans"; rewrites `polyfill.io` references (v2 path and all 3.* versions) to Cloudflare-hosted cdnjs copies; skipped when a CSP has `script-src` or `default-src` (including CSP in a `<meta>` tag); removes ETag and Content-Length on affected responses; cannot be turned off on `pages.dev` zones. — [Replace insecure JS libraries](https://developers.cloudflare.com/waf/tools/replace-insecure-js-libraries/)

### Inferences
- Use idea: leave Email Address Obfuscation on for contact pages; enable Hotlink Protection for image-heavy pages with a `hotlink-ok` folder for social previews (og:image).

### Gaps
- Server-side Excludes (historically part of Scrape Shield) was not found in the current docs search; its status is unconfirmed. Plan availability statements for Email Obfuscation and Hotlink Protection come only from the WAF overview table (their own pages state none).

### Cited Findings
