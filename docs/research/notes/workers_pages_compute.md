# Cloudflare Workers & Pages: free compute, build/deploy, observability and dev tooling (state as of 2026-10-14)

> v2 (full pass). Evidence base: raw Markdown of developers.cloudflare.com pages (each page's own "Last updated" date is quoted), the Workers / Containers / Pages / Artifacts changelog RSS feeds, and Cloudflare blog posts (blog dates come from page structured data). Labels: **[FREE-FOREVER]** standing free allowance on the Workers Free plan; **[FREE-BETA]** free only during beta; **[TRIAL]** trial/credits; **[PAID-ONLY]** no free tier. "Paid" = Workers Paid plan ($5 USD/month minimum per account) unless stated. Use-ideas for a website + app are inferences and sit under each section's "Inferences". Where two Cloudflare sources disagree the conflict is stated explicitly (see also section 10).

## 1. Workers Free plan: exact limits, reset behaviour, and what happens at the limit

### Takeaway
Workers Free = 100,000 requests/day (resets midnight UTC), 10 ms CPU per invocation, 128 MB per isolate, 50 external subrequests (1,000 to Cloudflare services) per invocation, 64 MiB uncompressed bundle (the 3 MB-compressed Free cap was removed 2026-09-04), 1 s startup, 100 Workers per account, 5 Cron Triggers per account, 64 env vars per Worker. Past the daily request cap Cloudflare returns Error 1027; each route chooses fail-open (bypass the Worker) or fail-closed (show the 1027 page). No bandwidth/egress charges exist on any plan, and the docs list only a Cloudflare account sign-up as a prerequisite (no payment method mentioned).

### Cited Findings
**Daily request cap, reset, behaviour at the limit [FREE-FOREVER, GA]**
- Free accounts get 100,000 requests/day, "resetting at midnight UTC"; when a Worker exceeds it Cloudflare returns Error 1027. Route mode "Fail open" bypasses the Worker (requests behave as if no Worker is configured); "Fail closed" returns a Cloudflare 1027 error page and is recommended for security-critical Workers; the mode is toggled per route. — [Workers Limits: Daily requests (updated Oct 12, 2026)](https://developers.cloudflare.com/workers/platform/limits/#daily-requests)
- Error table: 1027 = "Worker exceeded free tier daily request limit"; 1102 = Worker exceeded CPU time limit; 1101 = Worker threw a JavaScript exception. — [Workers errors (Oct 12, 2026)](https://developers.cloudflare.com/workers/observability/errors/)
- Pricing page: Free = "100,000 per day" requests, "No charge for duration", "10 milliseconds of CPU time per invocation"; subrequests are not billed; a WebSocket upgrade counts as one request and messages routed through a Worker do not; no data-transfer (egress) or bandwidth charges; Paid has a $5/month minimum. "Fine Print": only requests that hit a Worker count against limits and the bill. Cron example: a Worker run hourly by a Cron Trigger is counted as 720 requests/month, i.e. Cron invocations are requests. — [Workers Pricing (updated Oct 2, 2026)](https://developers.cloudflare.com/workers/platform/pricing/)
- The Free quota is shared with Pages Functions: "you could use 50,000 Functions requests and 50,000 Workers requests to use your full 100,000 daily request usage"; reset at midnight UTC. — [Pages Functions pricing (Sep 8, 2026)](https://developers.cloudflare.com/pages/functions/pricing/)
- Free tier plus `run_worker_first` asset patterns: once the free request limit is exceeded those requests "will receive a 429 (Too Many Requests) response instead of falling back to static asset serving"; negative patterns (`!/...`) keep serving assets without invoking the Worker. — [Static assets billing & limitations (Apr 23, 2026)](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)

**Per-invocation / per-isolate limits (Free; Paid in parentheses)** — all from [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/) unless noted
- CPU time: 10 ms per HTTP request and 10 ms per Cron Trigger (Paid 5 min, default 30 s; Cron 30 s for <1 h interval, 15 min for >=1 h). Waiting on network/I/O does not count; the average Worker uses ~2.2 ms, auth/SSR/large-payload Workers typically 10-20 ms; isolates have "built-in flexibility" for occasional overruns but consistent overrun terminates execution; exceeding returns Error 1102 "Worker exceeded resource limits" (`exceededCpu`). — [#cpu-time](https://developers.cloudflare.com/workers/platform/limits/#cpu-time)
- Memory: 128 MB per isolate on both plans (an isolate can serve many concurrent requests). At the limit in-flight requests finish and a new isolate is created; client sees Error 1102 (`exceededMemory`). — [#memory](https://developers.cloudflare.com/workers/platform/limits/#memory)
- Subrequests: 50 per invocation (external) and 1,000 to internal Cloudflare services (Paid 10,000, raisable to 10M); each hop of a redirect chain counts; a lower cap can be self-set with `[limits] subrequests` / `cpu_ms`. — [#subrequests](https://developers.cloudflare.com/workers/platform/limits/#subrequests); [Changelog 2026-02-11](https://developers.cloudflare.com/changelog/post/2026-02-11-subrequests-limit/)
- Simultaneous outgoing connections: 6 per invocation, counted only while waiting for response headers since 2026-04-09; a 7th queues. — [#simultaneous-open-connections](https://developers.cloudflare.com/workers/platform/limits/#simultaneous-open-connections); [Changelog 2026-04-09](https://developers.cloudflare.com/changelog/post/2026-04-09-relaxed-connection-limiting/)
- HTTP request duration: no limit while the client stays connected; `ctx.waitUntil()` extends up to 30 s after the response; Cron/DO alarm/Queue consumer wall time 15 min; during runtime updates existing requests/connections get up to 20 min (raised from 30 s on 2026-10-12). — [#duration](https://developers.cloudflare.com/workers/platform/limits/#duration); [Changelog 2026-10-12](https://developers.cloudflare.com/changelog/post/2026-10-12-longer-runtime-update-grace-period/)
- Cache API: Free 50 calls per request (Paid 1,000), 512 MB max object. Log data 256 KB per request (extra context dropped). URL 16 KB; request/response headers 128 KB total; response body unlimited; request body limit follows the Cloudflare zone plan (Free/Pro 100 MB, 413 above). — [Limits](https://developers.cloudflare.com/workers/platform/limits/)
- Secrets and variables: 64 per Worker on Free (secrets + text vars; Paid 128), 5 KB each, no per-account cap. — [#environment-variables](https://developers.cloudflare.com/workers/platform/limits/#environment-variables)

**Account-level counts and deploy-time limits**
- Workers per account: Free 100, Paid 500 (more via Workers for Platforms); Cron Triggers per account: Free 5, Paid 250 (the Cron page speaks of "per Worker" but the limits table says per account). — [#number-of-workers](https://developers.cloudflare.com/workers/platform/limits/#number-of-workers); [Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/)
- Worker size: 64 MiB uncompressed on Free and Paid, "no compressed size limit". — [#worker-size](https://developers.cloudflare.com/workers/platform/limits/#worker-size)
- Startup: 1 second to parse/execute global scope; deploy fails with error 10021 `Script startup exceeded CPU time limit`. — [#worker-startup-time](https://developers.cloudflare.com/workers/platform/limits/#worker-startup-time)
- Deploy-time error codes: 10027 uploaded Worker exceeded size limits; 10037 account exceeded the number of Workers; 10054 env var/secret too large; 10055 too many env vars/secrets. — [Workers errors](https://developers.cloudflare.com/workers/observability/errors/)
- Bundled/Unbound usage models are deprecated and unavailable to new accounts. — [Limits](https://developers.cloudflare.com/workers/platform/limits/#unbound-and-bundled-plan-limits)

**Domains, routes, workers.dev**
- Routes per zone 1,000 (50 with `wrangler dev --remote`), Custom Domains per zone 100, routed zones per Worker 1,000. — [#routes-and-domains](https://developers.cloudflare.com/workers/platform/limits/#routes-and-domains)
- Custom Domains require an active Cloudflare zone and a Worker; cannot be created on a hostname with an existing CNAME or on a zone you do not own; no wildcard DNS; DNS records and certificates are created automatically. Routes require an active zone plus a proxied DNS record. — [Custom Domains (Sep 29, 2026)](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/); [Routes](https://developers.cloudflare.com/workers/configuration/routing/routes/)
- workers.dev: each account has a configurable `<account-subdomain>.workers.dev`; each Worker gets `<worker-name>.<subdomain>.workers.dev` without onboarding a domain; it is "treated as a Free website" meant for personal or hobby projects; name must be <=63 chars, alphanumeric/dashes, not start/end with a dash; disable with `workers_dev = false`. — [workers.dev (Sep 22, 2026)](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)

### Inferences
- Use idea (Workers as app tier): serve the site as static assets and use a small Worker only for forms, auth callbacks and API glue, so most traffic never counts against the 100k/day cap.
- Use idea (workers.dev): ship v1 on `<name>.<subdomain>.workers.dev`; attach a Custom Domain later (needs the domain's zone on Cloudflare).
- At 10 ms CPU, heavy SSR or crypto-heavy auth can brush the Free cap; prerender where possible.
- Fail-open means that after request 100,000 an API Worker route silently disappears (requests go to the origin or 404); choose per route deliberately.
- Cron Triggers consume the same daily request pool as HTTP traffic (per the billing example), so a frequent cron on Free costs headroom.

### Gaps
- Whether fail-open/closed applies to Custom Domains and workers.dev (docs say it is toggled on routes).
- What a Worker sees when the 50-external-subrequest cap is exceeded (error text not in the pages read).

## 2. Workers Static Assets (billing, SPA/404 handling, _headers/_redirects)

### Takeaway
Static asset requests on Workers are "free and unlimited" on Free and Paid, are served without invoking the Worker, and do not count toward the Worker request cap ("only requests that hit a Worker count"); storage is free. Free limits: 20,000 files per Worker version, 25 MiB per file, `_headers` 100 rules, `_redirects` 2,000 static + 100 dynamic. SPA and 404 behaviour is explicit config (`not_found_handling`); the Free-plan trap is `run_worker_first`, which returns 429 after the daily cap.

### Cited Findings
- "Requests to static assets are free and unlimited. Requests to the Worker script ... are billed according to Workers pricing." "There is no additional cost for storing Assets." — [Static assets billing & limitations](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)
- Pricing footnote 3 "Requests to static assets are free and unlimited"; Example 2 (12M of 15M requests static) costs only the $5 subscription; Fine Print "Only requests that hit a Worker will count against your limits and your bill." — [Workers Pricing](https://developers.cloudflare.com/workers/platform/pricing/)
- Default routing: a URL matching a file in the assets directory is served "without invoking Worker code"; otherwise the Worker runs (if present) or a 404 is returned; only one collection of assets per Worker; assets cached automatically with tiered cache. — [Static Assets overview (Oct 12, 2026)](https://developers.cloudflare.com/workers/static-assets/); [Configuration and bindings](https://developers.cloudflare.com/workers/static-assets/binding/)
- `not_found_handling = "single-page-application"` returns `/index.html` with 200 for non-matching requests; with a Worker and compat date >= 2025-04-01 (flag `assets_navigation_prefers_asset_serving`) navigation requests (`Sec-Fetch-Mode: navigate`) do not invoke the Worker, which "reduces billable invocations"; API paths fetched client-side still reach the Worker, but typing an API URL in the address bar serves the HTML. `"404-page"` returns the nearest `404.html` with 404. — [SPA routing (Oct 12, 2026)](https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/); [Overview](https://developers.cloudflare.com/workers/static-assets/)
- `run_worker_first`: `true` or an array of up to 100 glob patterns with `!` negative patterns (negatives win); "Requests are only billable if a Worker script is invoked." — [Binding docs](https://developers.cloudflare.com/workers/static-assets/binding/); [SPA routing](https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/)
- `.assetsignore` (gitignore syntax) excludes files from upload; `assets.directory` replaces Pages' `pages_build_output_dir`. — [Binding docs](https://developers.cloudflare.com/workers/static-assets/binding/); [Migrate from Pages](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/)
- Limits (Free = Paid unless noted): 20,000 files per Worker version (Paid 100,000; Wrangler >= 4.34.0 for the higher count); 25 MiB per file; `_headers` 100 rules, 2,000 chars per line; `_redirects` 2,000 static + 100 dynamic = 2,100, 1,000 chars per rule. — [Workers Limits: Static Assets](https://developers.cloudflare.com/workers/platform/limits/#static-assets)
- `_headers`: default headers are `Content-Type`, `Cache-Control: public, max-age=0, must-revalidate`, `ETag`, `CF-Cache-Status`; rules support splats and placeholders and `!` header removal; "not applied to responses generated by your Worker code". — [Headers (Sep 22, 2026)](https://developers.cloudflare.com/workers/static-assets/headers/)
- `_redirects`: supports 301/302/303/307/308, splats, placeholders, and proxying (200); no rewrites with other status codes, no query-parameter matching; redirects are followed even when an asset matches; not applied to requests served by Worker code. — [Redirects (Aug 25, 2026)](https://developers.cloudflare.com/workers/static-assets/redirects/)
- Middleware via `run_worker_first` "is charged as a normal Worker invocation". Assets are always served from the location nearest the user (Smart Placement does not move them), unless fetched through the assets binding from a placed Worker. — [Migrate from Pages (matrix footnote 2)](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/); [Placement](https://developers.cloudflare.com/workers/configuration/placement/)
- When Workers Cache is enabled, requests that are normally free (static assets, worker-to-worker) are billed at the standard request rate. — [Workers Cache pricing](https://developers.cloudflare.com/workers/cache/)

### Inferences
- An SPA/static-site-first architecture is effectively unlimited on Free for page and asset views; only `/api/*`-style routes consume the 100k/day cap. Use `run_worker_first = ["/api/*"]` and keep a compat date >= 2025-04-01.
- Do not enable Workers Cache on the asset-serving Worker on Free unless needed: per the docs every request to the Worker (including assets) would then be billed as a request, which on Free presumably counts against the daily cap (docs state the billing rule, not the Free-cap consequence).
- Use idea: OAuth callbacks should be a slim HTML file or `run_worker_first` path, because navigations skip the Worker in SPA mode.

### Gaps
- No page states the Free-plan consequence of Workers Cache + static assets explicitly (inferred above).
- File-count overflow behaviour (deploy error text) not read.

## 3. Cloudflare Pages (limits, Functions, pages.dev) and the "use Workers instead" recommendation

### Takeaway
Pages Free: 500 builds/month, 1 concurrent build, 20-minute timeout, 20,000 files/site, 25 MiB/file, 100 projects/account, 100 custom domains/project, unlimited preview deployments; Pages Functions are billed as Workers (Free: shared 100,000/day). Cloudflare's current Pages docs open with "Start new projects with Workers"; there is no announced end-of-life, and the migration guide says existing projects keep working, but Pages lacks gradual deployments, the Vite plugin, Workers Logs, Tail Workers, Logpush, Cron Triggers and the Rate Limiting binding.

### Cited Findings
- Limits, Free column (page updated Sep 5, 2026): 1 build at a time (Pro 5, Business 20); 500 builds/month (Pro 5,000; Business 20,000); build timeout 20 minutes; 100 custom domains per project (Pro 250; Business/Enterprise 500); 20,000 files per site (paid 100,000 with `PAGES_WRANGLER_MAJOR_VERSION=4`); 25 MiB per asset; unlimited active preview deployments; `_headers` 100 rules / 2,000 chars per header; `_redirects` 2,000 static + 100 dynamic; unlimited dashboard users; 100 Pages projects per account ("not routinely increased"; separate from the Workers project limit); new projects are restricted during the first 48 hours of use. — [Pages Limits](https://developers.cloudflare.com/pages/platform/limits/)
- Pages Functions: "billed as Cloudflare Workers requests"; on Free they use the Workers Free quota; static asset requests are free and unlimited ("A request is considered static when it does not invoke Functions"). — [Pages Functions pricing](https://developers.cloudflare.com/pages/functions/pricing/)
- On a purely static Pages project requests are unlimited; once Functions exist all requests invoke them unless `_routes.json` excludes static routes (needs >=1 include rule, <=100 include/exclude rules, each <=100 chars). On Workers Free you can set Settings > Runtime > Fail open / closed: fail open keeps serving static assets when the Functions allowance is exhausted, fail closed returns an error page; the Functions daily limit is removed by upgrading to Workers Standard. — [Pages Functions routing](https://developers.cloudflare.com/pages/functions/routing/)
- Recommendation status: the Pages landing page (updated Aug 25, 2026) says "Are you sure you want to use Pages? Workers supports most Pages use cases and offers a broader feature set. It is Cloudflare's primary platform for building applications. Start new projects with Workers." — [Cloudflare Pages docs](https://developers.cloudflare.com/pages/)
- Migration guide (Oct 12, 2026): static asset requests are free on Workers like Pages, Pages Functions are charged at Workers rates ("a similar cost structure"), Workers adds Durable Objects, Cron Triggers and fuller observability; a migration prompt for coding agents is provided. — [Migrate from Pages to Workers](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/)
- Compatibility matrix. Workers-only: Cloudflare Vite plugin, Gradual Deployments, remote dev (`--remote`), Quick Editor, serve assets on a path, Workers Logs, Logpush, Tail Workers, Source Maps, Cron Triggers, Email Workers, Image Resizing binding, Queue consumers, Rate Limiting binding, non-root routes. Pages-only: custom domains outside Cloudflare zones (CNAME), native Early Hints, branch deploy controls, file-based routing and Pages Plugins (Workers has workarounds). Both: rollbacks, preview URLs, real-time logs, Node.js compat, KV/R2/D1/Hyperdrive/AI/Vectorize/service bindings, deploy hooks, build caching, watch paths, monorepos. — [Migrate from Pages: matrix](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/)
- Git integration supports GitHub and GitLab; a Git-integrated Pages project cannot later switch to Direct Upload; other routes are Direct Upload and C3. — [Pages Git integration (Apr 21, 2026)](https://developers.cloudflare.com/pages/get-started/git-integration/)
- Preview deployments: `<hash>.<project>.pages.dev` per push plus branch aliases `<branch>.<project>.pages.dev`; public by default, gate with Cloudflare Access; automatic `X-Robots-Tag: noindex`. — [Pages preview deployments (Oct 12, 2026)](https://developers.cloudflare.com/pages/configuration/preview-deployments/)
- Pages build image policy (page updated Sep 18, 2026): the v3 build system is the only current one ("no further build image version changes"); projects still on the v1 image were auto-moved to v3 on 2026-09-15 and v2 projects move on 2027-02-23, each with 6 months' notice; the first preinstalled-versions table lists Node.js 22.16.0 as default (the v2 and v1 tables list 18.17.1 and 12.18.0); the changelog notes Pages builds default to Node.js v22 since 2025-05-30. — [Pages build image](https://developers.cloudflare.com/pages/configuration/build-image/); [Pages changelog RSS](https://developers.cloudflare.com/changelog/rss/pages.xml)
- Changelog: Pages file limit for paid plans raised to 100,000 (2026-01-23; Free stays 20,000); Pages skips superseded queued builds (2026-08-11); the full Pages feed has only six entries since March 2025. — [Changelog 2026-01-23](https://developers.cloudflare.com/changelog/post/2026-01-23-pages-file-limit-increase/); [Pages changelog RSS](https://developers.cloudflare.com/changelog/rss/pages.xml)
- Older Cloudflare statement (blog dated 2023-05-17, modified 2026-07-15) said Pages and Workers would converge, existing projects "will continue to work", and gave no new-project recommendation. April 2025: full-stack framework adapters declared GA on Workers. — [Blog: Pages and Workers converging](https://blog.cloudflare.com/pages-and-workers-are-converging-into-one-experience/); [Changelog 2025-04-08](https://developers.cloudflare.com/changelog/post/2025-04-08-fullstack-on-workers/)

### Inferences
- For the target guide: build on Workers + static assets; mention Pages only as legacy and as the one path for a custom domain whose DNS is not on Cloudflare.
- Workers Builds Free gives 3,000 build minutes vs Pages' 500 builds/month, so a move to Workers does not shrink CI quota.
- Use idea: for an existing Pages site, migrate with `pages_build_output_dir` -> `[assets] directory`, and move `_worker.js`/Functions to a Worker script.

### Gaps
- No dated end-of-life or maintenance-mode statement for Pages found; the strength of "Start new projects with Workers" is a docs banner, not a deprecation notice.
- Behaviour when the 500 builds/month cap is hit is not documented in the pages read.

## 4. Workers Builds (Git-connected CI/CD)

### Takeaway
Workers Builds Free = 3,000 build minutes/month, 1 concurrent build, 20-minute timeout, 2 vCPU / 8 GB RAM / 20 GB disk, 64 build env vars. It connects GitHub, GitLab, Cloudflare Artifacts (paid) or Cursor Origin (not self-hosted Git), builds on each push, makes production versions on the production branch and Worker Previews for other branches.

### Cited Findings
- Limits (updated May 29, 2026): build minutes Free 3,000/month vs Paid 6,000/month then +$0.005/min; concurrent builds Free 1 vs Paid 6; timeout 20 min (both); Deploy Hooks 10/min per Worker and 100/min per account; CPU Free 2 vCPU vs Paid 4 vCPU; memory 8 GB; disk 20 GB; build env vars 64 at 5 KB each. — [Workers Builds limits & pricing](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/)
- Git providers: Artifacts, GitHub, GitLab, Cursor Origin; self-hosted GitHub/GitLab and other providers (e.g. Bitbucket) unsupported, use external CI (GitHub Actions/GitLab CI) with `wrangler deploy`. GitHub and Cursor Origin get PR comments and check runs; GitLab gets commit statuses. — [Git integration (Oct 1, 2026)](https://developers.cloudflare.com/workers/ci-cd/builds/git-integration/); [Workers CI/CD](https://developers.cloudflare.com/workers/ci-cd/)
- Behaviour: production-branch builds create a version and (if configured) promote it; other branches build Previews; new Workers use `npx wrangler preview` as the Preview command; existing Workers must run a one-time irreversible switch to Worker Previews; Worker name in the dashboard must equal `name` in the Wrangler config. — [Workers Builds (Oct 1, 2026)](https://developers.cloudflare.com/workers/ci-cd/builds/); [Build branches](https://developers.cloudflare.com/workers/ci-cd/builds/build-branches/)
- Autoconfig: connecting a repo without a Wrangler config opens a PR (config, adapter, scripts, `.gitignore`, `.assetsignore`) with a preview; name-conflict PRs fix dashboard/config name mismatches; PRs not available for Artifacts. — [Automatic pull requests (Oct 12, 2026)](https://developers.cloudflare.com/workers/ci-cd/builds/automatic-prs/)
- Build caching: npm/yarn/pnpm/bun caches plus framework caches (Astro, Docusaurus, Eleventy, Gatsby, Next.js, Nuxt, SvelteKit); 10 GB per project; purged 7 days after last read. — [Build caching (Sep 10, 2026)](https://developers.cloudflare.com/workers/ci-cd/builds/build-caching/)
- Watch paths: include/exclude globs; pushes with 3,000+ changed files or 20+ commits bypass matching and build. — [Watch paths](https://developers.cloudflare.com/workers/ci-cd/builds/build-watch-paths/)
- Deploy Hooks: unique POST URL per branch (no auth header; the URL is the secret); idempotent while a build is queued/initializing; for CMS webhooks or external cron. Build event subscriptions publish `build.started/succeeded/failed/canceled` events to a Queue. — [Deploy Hooks](https://developers.cloudflare.com/workers/ci-cd/builds/deploy-hooks/); [Event subscriptions](https://developers.cloudflare.com/workers/ci-cd/builds/event-subscriptions/)
- Build image: Ubuntu 24.04 x86_64; Node.js 24.18.0 default (22.23.2 also preinstalled), Python 3.13.3, Go 1.24.3, Ruby 3.4.7, Bun 1.2.15, Hugo extended_0.147.7, pnpm 10.11.1, yarn 4.9.1; override via env vars or version files; `SKIP_DEPENDENCY_INSTALL`; major version bumps get 3 months' notice. — [Build image (Oct 8, 2026)](https://developers.cloudflare.com/workers/ci-cd/builds/build-image/)
- Recent changelog titles (bodies not opened unless noted): 2026-10-12 preview URLs posted in seconds; 2026-09-22 Cursor Origin; 2026-07-30 Node 24 default; 2026-07-24 skip superseded queued builds; 2026-04-01 Deploy Hooks; 2026-01-09 build notifications; 2025-12-18 build image policies; 2025-09-18 more vCPU on paid; 2025-08-04 more disk. — [Workers changelog RSS](https://developers.cloudflare.com/changelog/rss/workers.xml)
- Artifacts (Git-compatible storage usable as a Workers Builds source) is open beta (2026-10-01) and "currently only available on the Workers Paid plan"; operations/storage billing begins 2026-10-14: Free = "Unavailable"; Paid = first 10,000 operations and 1 GB per month included. [PAID-ONLY] — [Artifacts pricing (Oct 1, 2026)](https://developers.cloudflare.com/artifacts/platform/pricing/); [Artifacts integration](https://developers.cloudflare.com/workers/ci-cd/builds/git-integration/artifacts-integration/)

### Inferences
- 3,000 minutes ~ 600 five-minute builds a month; with one concurrent build, pushes queue, and "skip superseded queued builds" saves minutes. Use watch paths so docs-only pushes cost nothing.
- Use idea: GitHub repo -> Workers Builds -> `main` deploys production, feature branches get Worker Previews with PR comments; Deploy Hook lets a headless CMS trigger rebuilds.

### Gaps
- What happens when Free build minutes run out (blocked vs billed) is not stated on the limits page or in docs search; a web search found no authoritative answer.
- Whether build event subscriptions on Free depend on the Queues Free allowance (event delivery uses a Queue; Queues Free is covered by another researcher).

## 5. Free deployment and runtime features

### Takeaway
All of these work on Workers Free with no separate meter unless noted: versions/gradual deployments/rollbacks, Version URLs, Worker Previews (100 per Worker on Free), Smart Placement + Placement Hints, service bindings + RPC (no extra request fee), Rate Limiting binding (GA), Cron Triggers (5), compatibility dates/flags (Node.js compat on by default for dates >= 2026-08-04), WebSockets, WebAssembly, Python Workers, Workers Cache, Deploy-to-Cloudflare buttons, templates and the Playground.

### Cited Findings
- Versions & deployments: every change makes a version; a deployment says which version(s) serve traffic; `wrangler deploy` does both, `versions upload` + `versions deploy` decouples them; Wrangler lists the 100 most recent. No plan restriction is stated. — [Versions & deployments (Sep 22, 2026)](https://developers.cloudflare.com/workers/versions-and-deployments/)
- Gradual deployments: percentage split between two versions (Wrangler >= 3.40.0), version affinity and version overrides; Durable Objects behave differently; not supported for Workers for Platforms user Workers; Pages lacks it; metrics charts annotate each rollout (2026-09-25). — [Gradual deployments (Jul 3, 2026)](https://developers.cloudflare.com/workers/versions-and-deployments/gradual-deployments/); [WfP limits](https://developers.cloudflare.com/cloudflare-for-platforms/workers-for-platforms/reference/limits/); [Changelog 2026-09-25](https://developers.cloudflare.com/changelog/post/2026-09-25-release-flows-workers-metrics/)
- Rollbacks: instant new deployment of an earlier version; limited to the 100 most recently published versions; refused if a Durable Object class lifecycle change happened between the active and target versions, or if the target version binds an R2 bucket, KV namespace or queue that no longer exists; other bound resources are not rolled back. — [Rollbacks (Jul 15, 2026)](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)

### Inferences
- Use ideas: service bindings + RPC to split a public edge Worker from a private API Worker for free; Rate Limiting binding on login/contact endpoints; Placement Hints/Smart Placement for an API Worker calling one external database; Cron Trigger for nightly reports; Worker Previews + Workers Builds for per-PR test sites; gradual deployments for canaries on the live Worker; Deploy button for sharing a starter.
- Because Previews, Workers Logs, Cron and Rate Limiting have no Pages equivalent, an "everything free" guide should be Workers-based.
- Rate Limiting binding is probably free in the sense that it is only part of Worker CPU/requests, but no source states a quota; treat as "no separate meter documented".

- Subrequest-cap exceeded error text; Workers Cache Free-plan interaction with the 100k/day cap not stated.

## 6. Observability on Free

### Takeaway
Free today: Workers Logs (200,000 events/day, 3-day retention), real-time logs / `wrangler tail` (max 10 viewers), Query Builder + dashboard, Workers metrics (3 months), source maps, Issues (open beta, free during beta) and Workers Traces (open beta). Paid-only: Tail Workers (per docs) and Workers Trace Events Logpush. On 2026-12-01 Workers Logs, Workers Traces, Cloudflare Traces and Issues move to a pooled "Cloudflare Observability" meter: Free = 0.5 GB/day ingestion, 7-day retention, ingestion simply stops at the daily limit and resumes 00:00 UTC.

### Cited Findings
- Workers Logs [FREE-FOREVER until the Dec 1 change]: Free 200,000 log events/day, 3-day retention; Paid 20M/month then +$0.60/M, 7 days. New Workers have `observability` on by default; `head_sampling_rate` 0-1; `invocation_logs = false` disables invocation logs; account cap of 5 billion logs/day then 1% sampling; 256 KB per log (truncated). The docs do not say what happens when the Free 200,000/day is exceeded. — [Workers Logs (Oct 12, 2026)](https://developers.cloudflare.com/workers/observability/logs/workers-logs/); [Pricing](https://developers.cloudflare.com/workers/platform/pricing/)
- Unified pricing effective 2026-12-01 (page updated Oct 5, 2026): one account-level allowance shared by Cloudflare Traces, Workers Logs, Workers Traces, Containers logs, R2 Data Access Logs, AI Gateway logs and Issues. Free: 0.5 GB per day ingestion, seven-day retention, additional ingestion "Not available". Paid: 50 GB per billing cycle + 10 GB-month storage, then $0.25/GB and $0.10/GB-month. - Workers Traces [FREE-BETA, open beta]: automatic spans for fetch, bindings, RPC and handlers with no code change; enable `observability.traces.enabled = true` (plain `observability.enabled` still means logs only while tracing is in "early beta"); default sampling 1; 7-day retention; custom-span APIs (`startSpan`, `startActiveSpan`, `getActiveSpan`, `setAttributes`, `recordException`); from Dec 1, 2026 stored traces count against the pooled allowance; persisted traces have a Free daily ingestion limit after which new traces stop. — [Workers Traces (Oct 2, 2026)](https://developers.cloudflare.com/workers/observability/traces/); [Known limitations](https://developers.cloudflare.com/workers/observability/traces/known-limitations/); [Cloudflare Traces configuration](https://developers.cloudflare.com/observability/traces/configuration/)

## 9. Free trials, credits and no-account trial deploys

### Takeaway
Besides the standing Free plan there are three first-party trial-style routes: a 12-month student offer of Workers Paid features (US .edu, card required for new accounts), Cloudflare Drop (static site live for 1 hour without an account, claim to keep), and temporary accounts for agents (`wrangler deploy --temporary`, 60 minutes, claim to keep).

### Cited Findings
- Student offer [TRIAL]: "12 months of free access" to Cloudflare's paid developer features plan for US students at least 18 with a verified .edu billing email; increased allotments (e.g. Workers 10M requests/month, Workers Logs 20M events and 7-day retention, Logpush 10M events, Durable Objects 1M requests/day, Queues 1M ops/month) with standard overage rates above them; new .edu accounts must add a credit card; after 12 months the account reverts to the Free plan without charge; the post (published 2025-09-22, modified 2026-07-15) states no end date. — [Blog: free access for students](https://blog.cloudflare.com/workers-for-students/)
- Cloudflare Drop (2026-07-08): upload a folder or ZIP of static files with no account; temporary live preview stays up 1 hour; "Claim" by signing in or creating an account (new accounts verify email) to keep it; afterwards add a domain, observability, access control. — [Changelog 2026-07-08](https://developers.cloudflare.com/changelog/post/2026-07-08-cloudflare-drag-and-drop/)
- Temporary accounts (2026-06-19): `wrangler deploy --temporary` (Wrangler >= 4.102.0) deploys to a temporary preview account that lives 60 minutes and must be claimed; supports Workers, Static Assets, KV, D1, Durable Objects, Hyperdrive, Queues, SSL/TLS; not for production or CI/CD; a REST provisioning API exists for platforms. — [Changelog 2026-06-19](https://developers.cloudflare.com/changelog/post/2026-06-19-temporary-accounts-for-agents/); [Claim deployments (Jul 14, 2026)](https://developers.cloudflare.com/workers/platform/claim-deployments/)

### Inferences
- For a "free guide", only the standing Free plan is durable; the student offer helps a narrow audience and the 1-hour/60-minute routes are demo paths.

### Gaps
- Whether the student offer remains open for new sign-ups in Oct 2026 beyond the page's lack of an end date; any non-US student program.

## 10. Superseded limits and source conflicts (changes seen 2025-2026)

### Takeaway
Several widely quoted Free-plan numbers changed in the last 13 months; the Oct 2026 docs pages are authoritative, and three source conflicts remain open (Tail Workers on Free, OTel export on Free, blog-vs-docs subrequest numbers).

### Cited Findings
- SUPERSEDED Worker size: 3 MB (Free) / 10 MB (Paid) compressed -> 64 MiB uncompressed on all plans, no compressed limit (2026-09-04). — [Changelog 2026-09-04](https://developers.cloudflare.com/changelog/post/2026-09-04-increased-worker-size-limit/)
- SUPERSEDED startup time: 400 ms -> 1 second (2025-10-10). — [Changelog 2025-10-10](https://developers.cloudflare.com/changelog/post/2025-10-10-increased-startup-time/)
- SUPERSEDED subrequest ceiling: fixed 1,000 per invocation -> Paid default 10,000 (up to 10M), Free unchanged at 50 external / 1,000 internal (2026-02-11). — [Changelog 2026-02-11](https://developers.cloudflare.com/changelog/post/2026-02-11-subrequests-limit/)
- SUPERSEDED connection limit semantics: 6 connections for the whole lifetime -> 6 only while waiting for headers (2026-04-09). — [Changelog 2026-04-09](https://developers.cloudflare.com/changelog/post/2026-04-09-relaxed-connection-limiting/)
- SUPERSEDED runtime-update grace period: 30 s -> 20 min (2026-10-12). — [Changelog 2026-10-12](https://developers.cloudflare.com/changelog/post/2026-10-12-longer-runtime-update-grace-period/)
- SUPERSEDED rollback depth: 10 -> 100 versions (2025-09-11, title) and WebSocket message size 1 MiB -> 32 MiB (2025-10-31, confirmed by the WebSockets docs). — [Workers changelog RSS](https://developers.cloudflare.com/changelog/rss/workers.xml); [WebSockets](https://developers.cloudflare.com/workers/runtime-apis/websockets/)
- SUPERSEDED log capture per invocation: 128 KB -> 256 KB (2025-04-07). — [Changelog 2025-04-07](https://developers.cloudflare.com/changelog/post/2025-04-07-increase-trace-events-limit/)
- Paid-only raises that leave Free unchanged: static asset files 20,000 -> 100,000 (Workers) and Pages files 20,000 -> 100,000 (2026-01-23). — [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/#static-assets); [Changelog 2026-01-23](https://developers.cloudflare.com/changelog/post/2026-01-23-pages-file-limit-increase/)
- SUPERSEDING on 2026-12-01: Free Workers Logs "200,000 events/day, 3 days" -> pooled 0.5 GB/day, 7 days. — [Observability pricing](https://developers.cloudflare.com/observability/pricing/)
- Naming/recommendation changes: "preview URLs" -> "Version URLs"; aliased Version URLs for branch testing -> Worker Previews (2026-09-22); Sandbox SDK 0.x -> Sandboxes; OpenNext -> vinext for new Next.js apps; Quick Editor devtools -> log viewer (2026-02-16, title). — [Version URLs](https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/); [Compare workflows](https://developers.cloudflare.com/workers/previews/compare-workflows/); [OpenNext](https://developers.cloudflare.com/workers/framework-guides/web-apps/opennext/); [Workers changelog RSS](https://developers.cloudflare.com/changelog/rss/workers.xml)
- Conflict A: the Birthday Week limits post (2026-10-02) says all customers can "make up to 1 millions subrequests per request (up from 1,000)" and Pages "up to 100,000 static assets", while the per-plan docs tables (updated Sep-Oct 2026) keep Free at 50 external subrequests and 20,000 files; it also confirms startup 400 ms -> 1 s, 32 MiB WebSocket messages, 64 MiB Workers, and says Dynamic Workers are for paid accounts. — [Blog: Enterprise-for-all update](https://blog.cloudflare.com/enterprise-for-all-update/); [Workers Limits](https://developers.cloudflare.com/workers/platform/limits/); [Pages Limits](https://developers.cloudflare.com/pages/platform/limits/)
- Conflict B (Tail Workers) and Conflict C (OTel export on Free): see section 6.
- Free-limit enforcement is tightening elsewhere on the platform (context only): D1 queries on Free fail past the daily row limits from 2026-09-01; three Workers AI models now require Workers Paid (2026-07-28). — [D1 changelog](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/); [Workers AI changelog](https://developers.cloudflare.com/changelog/post/2026-07-28-models-require-workers-paid/)

### Inferences
- A guide written now should quote the Oct 2026 docs tables and avoid the 3 MB, 400 ms and 1,000-subrequest figures still common in older articles.
- Treat marketing-style blog statements ("all customers") as secondary to the plan-specific docs tables.

### Gaps
- The Birthday Week wrap-up and "commitment to free" pages were summarised by a fetch tool, not read raw; the docs pages cited alongside are the authoritative numbers.
