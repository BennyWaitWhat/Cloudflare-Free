# Cloudflare free media, real-time and email offerings (state as of 2026-10-14)

*Scope: Images, Stream, Realtime (SFU, TURN, RealtimeKit), Email Routing, Email Workers, sending email from Workers / Cloudflare Email Service, DMARC Management, Email Security. Labels: FREE-FOREVER = standing allowance; FREE-BETA = free only while in beta; TRIAL = one-off evaluation; PAID-ONLY = no free tier. Verification note: Images, TURN, RealtimeKit and Stream-WebRTC figures were seen verbatim in docs-search output; other numbers come from page-fetch summaries and are corroborated by a second page where possible (plans.md, changelog, FAQ). All dates 2026 unless stated. Final status: complete; open conflicts are listed in each Gaps block (biggest: RealtimeKit free tier).*

## 1. Cloudflare Images (Free plan, transformations, binding, cf.image, limits)

### Takeaway
Images Free is a FREE-FOREVER allowance of 5,000 unique transformations per calendar month on images stored OUTSIDE Images (R2, your origin); past that, new transformations fail with error 9422 (cached ones keep serving) and you are never billed. Hosted images (storage, delivery, variants, signed URLs, hosted-image binding) are PAID-ONLY.

### Cited Findings
#### Allowance, billing and behavior at the limit
- Everyone is on the Images Free plan by default; it covers transformations of images stored outside Images (example: R2). Allowance: "up to 5,000 unique transformations each month for free." Overview page: "Available on Free and Paid plans." — [Images pricing (updated Oct 12, 2026)](https://developers.cloudflare.com/images/pricing/), [Images overview](https://developers.cloudflare.com/images/)
- At the limit: transformations already in cache keep being served; new ones return error `9422`; if the source is on the same domain as the transformation, `onerror` can redirect to the original; "You will not be charged for exceeding the limits in the Free plan." — [Images pricing](https://developers.cloudflare.com/images/pricing/)
- Error text: `9422` = "The transformation request is rejected because the usage limit was reached"; fix: "If you need to request more than 5,000 unique transformations, upgrade to an Images Paid plan." Error `9432` = "The Images Binding is not available using legacy billing" (accounts still on the legacy Image Resizing subscription must switch to the Images subscription); `9413` = over 100 MP. — [Troubleshooting](https://developers.cloudflare.com/images/reference/troubleshooting/)
- Reset: billing is per calendar month; the first request for each unique source+parameter combination in a month counts once, later repeats add nothing. Different parameter sets count separately (100x100 vs 200x200 = two). The `format` parameter does not add billable transformations (AVIF vs WebP is one). `.info()` is not billed. — [Images pricing](https://developers.cloudflare.com/images/pricing/)
- Each distinct `width=auto` width counts as a separate billable transformation for remote images. — [Images features](https://developers.cloudflare.com/images/optimization/features/)
- Paid boundary: Images Transformed = first 5,000 unique included then $0.50 per 1,000/month; Images Stored = $5 per 100,000 images stored/month; Images Delivered = $1 per 100,000 delivered/month. Storage and Delivered are Paid-only. Cloudflare's plans page lists the same figures with no free allowance for stored/delivered. — [Images pricing](https://developers.cloudflare.com/images/pricing/), [Cloudflare plans](https://www.cloudflare.com/plans.md)
- Hosted-image rules: delivery-URL optimization of hosted images counts as Images Delivered (billed only for HTTP 200 responses over 1,024 bytes); optimizing hosted images via the binding counts as Images Transformed. "Hosted image operations require a paid Images plan with storage" (binding `env.IMAGES.hosted`). — [Images pricing](https://developers.cloudflare.com/images/pricing/), [Hosted images binding](https://developers.cloudflare.com/images/storage/binding/)
- Worked example: 2,000 R2 images in five sizes = 10,000 unique transformations; on Paid 5,000 billable = $2.50. — [Images pricing](https://developers.cloudflare.com/images/pricing/)
- Stream's video Media Transformations share the same subscription and metric: 5,000 free unique transformations per month combined, then $0.50/1,000. — [Stream pricing](https://developers.cloudflare.com/stream/pricing/)

#### How transformations are invoked and what each method requires
- URL (remote images): `https://<ZONE>/cdn-cgi/image/<OPTIONS>/<SOURCE-IMAGE>` (source = absolute path on the origin or full http(s) URL). Hosted: `https://imagedelivery.net/<ACCOUNT_HASH>/<IMAGE-ID>/<VARIANT-OR-OPTIONS>`. Workers: Images binding or `cf.image` on a `fetch` subrequest. — [Images features](https://developers.cloudflare.com/images/optimization/features/)
- URL method needs a Cloudflare zone: "To serve transformations on your zone, you must first enable the feature" (dashboard Images > Transformations > select zone). Default allowed sources = same zone only; extra origins via Sources (root domain does not match subdomains; `*.b.com` matches both); an "any origin" setting exists but is flagged less secure; only the initial URL is checked (redirects are followed). — [Transformations overview](https://developers.cloudflare.com/images/optimization/transformations/overview/), [Sources](https://developers.cloudflare.com/images/optimization/transformations/sources/)
- `cf.image` in Workers: "available on any zone that hosts a Worker, including `*.workers.dev` subdomains"; "Each transformation is billed to the account that owns the Worker"; do not bind the image Worker to `/*`; dashboard editor preview does not simulate transforms. — [Transform via fetch](https://developers.cloudflare.com/images/optimization/transformations/transform-via-workers/)
- Images binding: `[images] binding = "IMAGES"`, "enabled on a per-Worker basis"; methods `.input()`, `.text()`, `.transform()`, `.draw()`, `.output()`, `.response()`, `.info()`; input up to 20 MB; text up to 1,000 chars / 4096x4096; custom fonts up to 20 MB; responses are not cached automatically (Workers Cache strongly recommended); `wrangler dev` is low-fidelity (width, height, rotate, format), `--remote` is high-fidelity, local dev is not billed. No zone and no plan requirement is stated. Binding calls are billed as unique transformations. — [Images binding](https://developers.cloudflare.com/images/optimization/binding/)
- Pricing table: "Optimize images stored outside of Images" = Images Transformed = "Free and Paid plans". — [Images pricing](https://developers.cloudflare.com/images/pricing/)

#### Limits and formats
- Remote (your storage) images: file size 100 MB; area 100 MP (e.g. 10,000x10,000); dimension 12,000 px (excluding WebP/AVIF); AVIF dimension 1,200 px. Hosted images: file size 10 MB; same area/dimension; metadata 1,024 bytes. Animated GIF/WebP: 100 MP summed over frames, over 50 MP delivered untransformed. — [Images limits](https://developers.cloudflare.com/images/get-started/limits/)
- Input: PNG, JPEG, GIF (animated ok), WebP (animated ok), SVG, HEIC; AVIF INPUT is "Available on an Enterprise plan." Output: PNG, JPEG, GIF, WebP, SVG, AVIF (AVIF can be slow; large images fall back to WebP/JPEG). SVG is not resized. — [Images limits](https://developers.cloudflare.com/images/get-started/limits/)
- Options: `format` = auto, avif, webp, jpeg, baseline-jpeg, json; `quality` 1-100 (default 85); `fit` = scale-down (default), contain, cover, crop, aspect-crop, pad, squeeze, scale-up; `gravity=face|auto`; `upscale=generate` (AI ESRGAN upscaling); `segment=foreground` (background removal via BiRefNet on Workers AI); `border` Workers-only; `onerror=redirect` only for remote images via URL and same-zone sources. No option is labeled paid-only. — [Images features](https://developers.cloudflare.com/images/optimization/features/)
- Caching: optimized images follow the original's cache rules with a 1-hour minimum; individual optimized images cannot be purged (purge the original); `/cdn-cgi/` URLs cannot be purged. — [Images features](https://developers.cloudflare.com/images/optimization/features/)

#### Status and 2025-2026 changes
- SUPERSEDED (Jul 1, 2026): the Images binding used to bill every call; it is now billed per unique transformation and `.info()` is free. — [Changelog](https://developers.cloudflare.com/changelog/post/2026-07-01-binding-unique-transformations/)
- 2026 additions: hosted images via binding (Jun 10); `composite`, percentage overlay widths, `aspect-crop`/`scale-up`, `upscale` (Jun 16); transformation flows incl. Fastly provider flows (May 27); `.text()` rasterization, metadata filtering, `.signedUrl()`, `.createDirectUpload()`, `headers` option (Sep 2); account-level transformation analytics at Images & Stream > Transformations > Analytics, sampled (Sep 23). 2025: HEIC support (Jul 8, 2025), Images binding launched (Feb 24, 2025). — [Images changelog](https://developers.cloudflare.com/changelog/product/images/), [Analytics post](https://developers.cloudflare.com/changelog/post/2026-09-23-transformation-analytics/)

### Inferences
- A $0 site gets about 5,000 unique variants a month (e.g. 1,000 images x 5 fixed widths); use a small fixed width set and `format=auto` (does not multiply) and avoid `width=auto`.
- Idea: store originals in R2, serve responsive AVIF/WebP via `/cdn-cgi/image/...` on your zone (or the Images binding / `cf.image` in a Worker, which avoids needing a custom zone), with `onerror=redirect` so the page still shows originals if the 5,000 cap is hit.
- Because the pricing table lists binding/URL transformation of external images as Free-and-Paid and the only documented binding block is error 9432 (legacy billing), the binding very likely works on a Free account, but this is not stated explicitly.
- Minimum Images Paid cost is probably $5/month (sold in $5 increments per 100,000 images) but no page states a floor.

### Gaps
- Not explicitly confirmed: Images binding on a Workers Free account; whether the binding needs a zone; exact minimum monthly price of Images Paid.
- The dedicated "Transform via URL" doc page returned 404 (docs restructured); URL syntax taken from the Features page.

## 2. Cloudflare Stream (storage, delivery, Stream Live, player, WebRTC)

### Takeaway
PAID-ONLY: no free storage/delivery allowance, free minutes or trial exists in the Stream docs or Cloudflare's plans page; cost is $5/month per 1,000 minutes of storage (prepaid) plus $1 per 1,000 minutes delivered. The only free pieces are the shared 5,000 free Media Transformations per month and WebRTC (WHIP/WHEP) delivery through 2026-10-14, billed from 2026-10-15.

### Cited Findings
- Billing dimensions: minutes stored and minutes delivered only; on-demand and live billed the same; ingress and encoding free; no separate egress fees. — [Stream pricing (updated Sep 8, 2026)](https://developers.cloudflare.com/stream/pricing/)
- Storage is prepaid: "purchased in increments of $5 per month for each 1,000 minutes"; billed by duration rounded up to the second. Delivery is post-paid at $1 per 1,000 minutes (Stream Player, HLS/DASH manifests, WebRTC/WHEP, MP4 downloads, simulcast outputs count; preloading is billable, browser-cached playback is not). — [Stream pricing](https://developers.cloudflare.com/stream/pricing/)
- No free tier: the pricing page (also checked as raw markdown) has no free allowance, trial or minimum-plan text; Cloudflare's plans page lists minutes stored at $5.00 per thousand and minutes delivered at $1.00 per thousand with no free allowance shown for either; the Stream product page carries no prices and links to the plans page. — [Stream pricing](https://developers.cloudflare.com/stream/pricing/), [Cloudflare plans](https://www.cloudflare.com/plans.md), [Stream product page](https://www.cloudflare.com/developer-platform/products/cloudflare-stream/)
- Behavior at the storage limit: new uploads and new live streams are blocked until you buy more storage or delete videos; uploads are refused when total duration would exceed purchased capacity (checked when the Direct Creator Upload URL is created); over-limit uploads get HTTP 429 or 413; Enterprise may exceed quota. "Videos are removed if the subscription is not renewed within 30 days." — [Stream pricing](https://developers.cloudflare.com/stream/pricing/), [Stream FAQ](https://developers.cloudflare.com/stream/faq/)
- Other limits: a single upload at most 30 GB by default; up to 120 videos queued/encoding at once. — [Stream FAQ](https://developers.cloudflare.com/stream/faq/)
- Storage counts originals, RTMP/SRT live recordings and reserved `maxDurationSeconds` of unfinished direct uploads; does not count errored/expired/deleted videos, MP4 download files, extra renditions or WebRTC broadcasts. A live broadcast with no viewers costs $0 delivery but its recording consumes storage. — [Stream pricing](https://developers.cloudflare.com/stream/pricing/)
- Stream Live WebRTC (WHIP publish / WHEP playback, sub-second latency, thousands of concurrent viewers): "Stream Live WebRTC is going GA: Billing for WebRTC delivery will begin on October 15th, 2026." It follows standard pricing ($1 per 1,000 minutes delivered) and is not recorded (no storage). Page still lists beta-era limitations (no recording, no live HLS playback of WHIP inputs, no RTMP/SRT simulcast, no viewer counts, no broadcast metrics). Tested clients: OBS 31+, Larix, FFmpeg 8.1+, whip-whep (JS), Eyevinn libs, react-native-whip-whep; codecs VP9, VP8, H.264 constrained baseline 3.1. — [Stream WebRTC](https://developers.cloudflare.com/stream/webrtc-beta/)
- Media Transformations for video (URL `/cdn-cgi/media` or Workers `MEDIA` binding): $0.50 per 1,000 unique operations with 5,000 free per month shared with Images; still frame = 1 operation, optimized video/audio extraction = 1 operation per output second; binding operations are not billed during the binding beta and afterwards every operation will be billed individually (no uniqueness discount). Limits: input under 100 MB, input duration max 10 minutes, MP4 H.264 + AAC/MP3 (GIF ok). — [Stream pricing](https://developers.cloudflare.com/stream/pricing/), [Transform videos](https://developers.cloudflare.com/stream/transform-videos/)
- Changelog 2026: Stream bindings `env.STREAM` (May 7); `MEDIA` binding (Mar 18); disable/enable live inputs (Feb 24); `rotate_keys` for live inputs (Jul 31). Birthday Week 2026 only added the "Streamline" example post (Oct 2). SUPERSEDED: Media Transformations input cap 40 MB -> 100 MB and output 30 s -> 1 min (Jun 10, 2025); Media and Image Transformations unified on one metric after Nov 1, 2025. — [Stream changelog](https://developers.cloudflare.com/changelog/product/stream/), [Birthday Week 2026 wrap-up](https://blog.cloudflare.com/birthday-week-2026-wrap-up/)

### Inferences
- Practical minimum to use Stream is $5/month (one 1,000-minute block) plus $1 per 1,000 minutes watched; derived from the "increments of $5" wording, not an explicit minimum.
- For a strictly $0 build, video options are limited to Media Transformations over clips in R2 (5,000 shared ops/month) or RealtimeKit/SFU for live; Stream itself is not free.
- Idea: if the app needs hosted video later, buy one block; use Media Transformations for poster frames (1 operation each) and WHIP/WHEP for in-browser "go live" once WebRTC billing is acceptable.

### Gaps
- Not stated: whether an account with no purchased storage can create WebRTC live inputs (storage is not consumed by WebRTC, but the Get Started page gives no subscription prerequisite either way).
- No Stream free trial found anywhere in first-party sources; no explicit "minimum monthly commitment" sentence.
- The WebRTC page's limitation list may be stale relative to the "going GA" banner.

## 3. Cloudflare Realtime: SFU, TURN, RealtimeKit

### Takeaway
SFU + TURN: FREE-FOREVER 1,000 GB/month of egress shared across both, then $0.05/GB; STUN is free and unlimited. RealtimeKit is unresolved: the docs and plans pages list only per-minute rates (no free allowance), while the RealtimeKit marketing page still says "Beta and free to use" with 10,000 free participant-minutes; treat any RealtimeKit free tier as unconfirmed.

### Cited Findings
#### SFU and TURN
- $0.05 per GB egress for SFU and TURN; first 1,000 GB each month free; one shared allowance and one bill line item; ingress (publishing into Cloudflare) is free; only Cloudflare-to-client egress is charged. Plans page: "TURN / SFU Data Egress (Free) 1,000 GB / month; Paid $0.05 / GB". — [Realtime SFU/TURN pricing](https://developers.cloudflare.com/realtime/sfu/pricing/), [Cloudflare plans](https://www.cloudflare.com/plans.md)
- TURN FAQ (verbatim): "$0.05 per GB of data used"; "There is a free tier of 1,000 GB before any charges start"; STUN at `stun.cloudflare.com` "free and unlimited"; TURN-to-SFU and TURN-to-Stream (WHIP/WHEP) traffic is not charged. — [TURN FAQ](https://developers.cloudflare.com/realtime/turn/faq/)
- WebSocket adapter egress (to your WebSocket endpoint) is billed at the same rate and shares the free tier; audio ingested from WebSocket into the SFU is not charged as ingress. The pricing page does not describe overage mechanics beyond the per-GB rate (no hard cap, throttle or payment-method rule documented) and does not say GB vs GiB. — [Realtime SFU/TURN pricing](https://developers.cloudflare.com/realtime/sfu/pricing/)
- TURN limits: no maximum allocation duration (credentials up to 48 h, refresh needed); no published credential-issuance cap (start ~500/s and ramp); no hard bandwidth caps but sustained >50-100 Mbps from one client or >5-10 kpps may drop packets; UDP supported, TCP relaying (RFC 6062) not; relay addresses IPv4 only; expired credentials stop billing and disconnect. Custom TURN hostname via CNAME to `turn.cloudflare.com`: "no additional charge" (plan availability not stated). — [TURN FAQ](https://developers.cloudflare.com/realtime/turn/faq/), [TURN custom domains](https://developers.cloudflare.com/realtime/turn/custom-domains/)
- SFU limits: 50 API requests/second per session; up to 64 tracks per API request; no fixed tracks-per-session cap; WebSocket audio ingest message 32 KB; timeouts: 30 s no packets (track GC), 30 s session reuse window, 5 s transport ops, 15 s adapter retry; codecs H.264, H.265, VP8, VP9, AV1 and Opus, G.711 A/mu-law. Sessions-per-app and any quota numbers are not listed. — [SFU limits](https://developers.cloudflare.com/realtime/sfu/platform/limits/)
- SFU setup: dashboard Realtime > Serverless SFU > create app, save App ID and App Secret; no plan requirement listed on the get-started page. — [SFU get started](https://developers.cloudflare.com/realtime/sfu/get-started/)
- Status: Cloudflare's Apr 9, 2025 launch post announced "General Availability of our SFU and TURN services" at "5 cents per GB after 1,000 GB of free usage each month"; the SFU changelog separately dates TURN GA to 2024-09-25. WebSocket adapter GA Sep 30, 2026 (15 s retry); DataChannels got unordered/partially-reliable modes (Aug 13), `canReply` (Jul 23), `waitForAck` (Jun 10). — [Realtime launch blog](https://blog.cloudflare.com/introducing-cloudflare-realtime-and-realtimekit/), [SFU changelog](https://developers.cloudflare.com/realtime/sfu/platform/changelog/), [WebSocket adapter GA](https://developers.cloudflare.com/changelog/post/2026-09-30-websocket-adapter-ga/)
- Partner offer: Hugging Face FastRTC developers get "10 GB of TURN bandwidth each month" with a Hugging Face access token (stated Apr 9, 2025; current status not re-verified). — [Realtime launch blog](https://blog.cloudflare.com/introducing-cloudflare-realtime-and-realtimekit/)
- WHIP/WHEP: the Realtime docs (overview, SFU index, changelog) never mention WHIP/WHEP; it is documented only as a Stream Live feature. The Realtime overview recommends Stream Live for webinars with a large watch-only audience. — [Realtime overview](https://developers.cloudflare.com/realtime/), [Stream WebRTC](https://developers.cloudflare.com/stream/webrtc-beta/)

#### RealtimeKit
- Docs pricing (updated Sep 3, 2026): Audio/Video participant $0.002/min; Audio-only $0.0005/min; Export (recording, RTMP, HLS) $0.010/min; audio-only export $0.003/min; Raw RTP into R2 $0.0005/min; real-time transcription = standard Workers AI pricing. Participant type is set by the preset's Meeting Type. The page has no Beta, "no cost", GA or free-allowance text. Cloudflare's plans page also shows RealtimeKit with paid per-minute rates only and no free allowance. — [RealtimeKit pricing](https://developers.cloudflare.com/realtime/realtimekit/pricing/), [Cloudflare plans](https://www.cloudflare.com/plans.md)
- Conflicting evidence: realtime.cloudflare.com (undated) says "RealtimeKit is currently in Beta and free to use" and tabulates free monthly inclusions of 10,000 A/V participant-minutes, 10,000 audio-only participant-minutes, 100 A/V export minutes and 100 audio-only export minutes, with the calculator "based on the pricing model planned for general availability (GA)... actual GA pricing may differ." — [RealtimeKit site](https://realtime.cloudflare.com/)
- Timeline evidence: the Apr 9, 2025 launch post said RealtimeKit was a closed beta with "no cost to test it out during the beta." Web-search summaries of cached docs preview deployments say an Aug 24-25, 2026 version of the pricing page still said Beta/no cost and an Aug 27, 2026 version dropped that language (so billing likely began about late Aug 2026); those preview URLs now return 404 and I could not read them directly, so this is secondary. No Realtime changelog entry announces RealtimeKit GA or billing. — [Launch blog](https://blog.cloudflare.com/introducing-cloudflare-realtime-and-realtimekit/), [Realtime changelog](https://developers.cloudflare.com/changelog/product/realtime/)
- Billing rules (FAQ): billed per exact second a participant is in an active session even with no media; each tab with the same token bills separately; creating meetings/tokens is free; no-shows not billed; composite recording is billed as export minutes (not participant minutes) and includes the keep-alive (default 60 s, max 600 s). API token needs Realtime > Realtime Admin permission; no plan tier requirement listed. — [RealtimeKit FAQ](https://developers.cloudflare.com/realtime/realtimekit/faq/)
- Transcription via Workers AI: post-meeting 46.63 Neurons/audio-minute (whisper-large-v3-turbo, GA Jun 8, 2026); real-time 836.36 Neurons/audio-minute (Deepgram Nova-3, 10 languages, Mar 6, 2026); Workers Free includes 10,000 Neurons/day, beyond that needs Workers Paid ($0.011 per 1,000 Neurons). — [RealtimeKit transcription](https://developers.cloudflare.com/realtime/realtimekit/ai/transcription/), [Realtime changelog](https://developers.cloudflare.com/changelog/product/realtime/)
- SDKs (Core + UI Kit): Web Components (HTML/Vue/Svelte), React, Angular, Android, iOS, React Native; Flutter has Core/UI Kit release notes and was listed in the Apr 2025 launch (not on the SDK-selection page). Features: presets/roles, chat, polls, plugins, collaborative stores, webinars, audio calls, webhooks, recording to your own R2, per-participant WebM track recording (May 28, 2026). — [SDK selection](https://developers.cloudflare.com/realtime/realtimekit/sdk-selection/), [RealtimeKit overview](https://developers.cloudflare.com/realtime/realtimekit/), [Realtime docs index](https://developers.cloudflare.com/realtime/llms.txt)
- RealtimeKit limits page lists only rate limits: all APIs 3,500 requests per 5 minutes; recording APIs 1,000 per 50 s; per-participant SDK limits (store writes 5/s, `sendTextMessage` 180/min, image/file messages 20/min...). Max participants, meeting length and concurrency are not published. — [RealtimeKit limits](https://developers.cloudflare.com/realtime/realtimekit/limits/)

### Inferences
- Rough arithmetic (decimal GB assumed, not a Cloudflare statement): 1,000 GB covers about 133,000 subscriber-minutes of 1 Mbps video (7.5 MB/min), so a small voice/video feature can stay inside the free tier for a long time.
- Workers AI free Neurons imply roughly 12 minutes/day of real-time transcription or about 214 minutes/day of post-meeting transcription (10,000 Neurons / 836.36 or 46.63 per minute) on Workers Free.
- Idea: peer-to-peer WebRTC with Cloudflare STUN/TURN as the relay fallback, SFU for group rooms or an AI voice agent via the WebSocket adapter; RealtimeKit only if you accept possible per-minute billing.
- Label: SFU/TURN = FREE-FOREVER; STUN = FREE-FOREVER; RealtimeKit = AMBIGUOUS (marketing page FREE-BETA vs docs usage-billed). Plan as if RealtimeKit is paid unless the dashboard shows free credits.

### Gaps
- Unresolved: whether RealtimeKit currently has any free allowance. A dashboard check (Realtime > RealtimeKit usage/billing) is the only way to settle it.
- Not published: overage behavior for SFU/TURN (hard stop vs auto-bill; payment-method requirement), GB vs GiB, SFU sessions-per-app, RealtimeKit participants per meeting/duration/concurrency.
- Hugging Face FastRTC 10 GB offer is from a 2025 post only.

## 4. Email Routing and Email Workers (inbound)

### Takeaway
FREE-FOREVER: Email Routing is on Free and Paid plans with unlimited inbound mail; it needs a domain using Cloudflare DNS (Cloudflare MX records, SPF/DKIM added at onboarding) and verified destination addresses. Email Workers use normal Workers billing and limits, so Workers Free CPU/request caps are the real ceiling.

### Cited Findings
- Availability and cost: Email Routing is "Available on Free and Paid plans"; pricing table shows Inbound (Email Routing) Unlimited on both Workers Free and Workers Paid; Email Routing Workers are billed under Workers pricing. — [Email Service overview](https://developers.cloudflare.com/email-service/), [Email Service pricing (updated Jun 9, 2026)](https://developers.cloudflare.com/email-service/platform/pricing/)
- Limits: 200 routing rules per domain (one pattern -> one destination address or one Worker); 200 destination addresses per account (shared by all domains); inbound message size 25 MiB (larger rejected); `reply()` throws above 100 `References` entries; 30 domains per zone combined across Routing and Sending. Higher limits via a Limit Increase Request Form. — [Email Routing limits](https://developers.cloudflare.com/email-routing/limits/), [Email Service limits](https://developers.cloudflare.com/email-service/platform/limits/)
- One pattern to several recipients needs a Worker calling `forward()` once per verified destination. — [Email Routing limits](https://developers.cloudflare.com/email-routing/limits/)
- Prerequisites: "You must be using Cloudflare DNS to use Email Service"; dashboard Compute > Email Service > Email Routing > Onboard Domain; add and confirm a destination address (account-level, reusable); Cloudflare adds 3 MX records (route1-3.mx.cloudflare.net), SPF TXT and DKIM TXT at the apex; "Cannot use Email Routing with external mail servers"; keep only one SPF record; Routing and Sending are onboarded and managed separately; propagation up to 24 h (typically 5-15 min). — [Route emails](https://developers.cloudflare.com/email-service/get-started/route-emails/), [Domains](https://developers.cloudflare.com/email-service/configuration/domains/)
- Catch-all: forwards every address on the domain (including misspellings) to one destination. Subaddressing (`user+tag@`, RFC 5233) supported since Jul 21, 2025, with sub-addressed recipients falling back to the base rule. Rule actions: send to an email, send to a Worker, or drop. — [Email Routing addresses](https://developers.cloudflare.com/email-service/configuration/email-routing-addresses/), [Email lifecycle](https://developers.cloudflare.com/email-service/concepts/email-lifecycle/), [Email Service changelog](https://developers.cloudflare.com/changelog/product/email-service/)
- Authentication: SPF or DKIM required for forwarding since Jul 3, 2025 (DMARC recommended); messages failing the sender's DMARC policy are rejected; forwards get ARC seal and SRS envelope rewrite. — [Email Service changelog](https://developers.cloudflare.com/changelog/product/email-service/), [Email lifecycle](https://developers.cloudflare.com/email-service/concepts/email-lifecycle/)
- Email Workers: `email(message, env, ctx)` handler; `forward(rcptTo, headers?)` to verified destinations (only `X-` headers can be added); `reply()` threaded reply (needs valid DMARC on the inbound mail, recipient must be the original sender, sender domain must match, once per message); `setReject(reason)` permanent SMTP rejection. — [Email Workers](https://developers.cloudflare.com/email-routing/email-workers/)
- Email Workers limits: they count toward standard Workers CPU and memory limits; on Free, complex handlers can fail with `EXCEEDED_CPU`; no numeric Email Workers-specific rate limits are published. For context Workers Free = 100,000 requests/day and 10 ms CPU per invocation. Local testing with `wrangler dev` (Apr 8, 2025); Worker routes managed through the top-level `addresses` Wrangler field (Sep 4, 2026). — [Email Routing limits](https://developers.cloudflare.com/email-routing/limits/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Email Service changelog](https://developers.cloudflare.com/changelog/product/email-service/)
- History: Email Routing open beta Feb 8, 2022, left beta Oct 25, 2022 (GA); subdomain support Oct 2023. — [Cloudflare blog: Email Routing posts](https://blog.cloudflare.com/tag/email-routing/)

### Inferences
- Idea: `support@`, `hello@` and `+tag` addresses on the site's domain forwarded to a personal inbox for free; an Email Worker parses inbound mail into D1/Queues (ticket inbox, reply-by-email comments, bot commands).
- Because inbound is unmetered, the practical free cap is the Workers Free request/CPU budget, not an email count.
- Using Email Routing means giving up external MX hosting for that domain (use a separate domain/subdomain if you also need Google Workspace or similar).

### Gaps
- No published numeric rate limit for inbound routing or Email Workers; no catch-all-specific limits found.
- Behavior when the 200-rule or 200-address caps are hit is not documented.

## 5. Sending email from Workers: `send_email` binding and Cloudflare Email Service (Email Sending)

### Takeaway
Email Sending is in PUBLIC BETA (since 2026-04-16; still beta at the last changelog entry, 2026-09-25). Sending to arbitrary recipients needs Workers Paid ($5/month minimum): 3,000 emails/month included, then $0.35 per 1,000. Sending to your account's verified destination addresses is free on every plan, unmetered, and is the only sending a Workers Free account can do.

### Cited Findings
- Structure and status: Email Service = Email Sending ("Beta for outbound transactional emails", requires Workers Paid) + Email Routing ("Available on Free and Paid plans"). Methods: Workers binding (`send_email`, `env.EMAIL.send()`), REST API (`/email/sending/send`), authenticated SMTP (`smtp.mx.cloudflare.net:465`). — [Email Service overview](https://developers.cloudflare.com/email-service/)
- Timeline: public beta Apr 16, 2026 ("available on the Workers paid plan"); display names May 28; SMTP submission beta Jun 8; lifecycle events to Queues Jul 15; email preview in Activity log (~7 days retention) Jul 17; suppressions scoped per account or sending domain Sep 25. Eleven changelog entries; none mentions GA, free tier or pricing changes. Earlier context: a Sep 2025 article reported a private beta from Nov 2025 with pricing not finalized (secondary, superseded by the public beta). — [Email Service changelog](https://developers.cloudflare.com/changelog/product/email-service/), [Public beta post](https://developers.cloudflare.com/changelog/post/2026-04-16-email-sending-public-beta/), [gihyo.jp (Sep 2025)](https://gihyo.jp/article/2025/09/cloudflare-email-service)
- Pricing table: Outbound is "Not available" on Workers Free and "3,000 included per month, then $0.35 per 1,000 emails" on Workers Paid; "Sending to arbitrary recipients requires the Workers Paid plan"; "Sends to verified destination addresses in your account are free on all plans, including when only Email Routing is configured." The 3,000 are per account per month on the subscription billing cycle. Counted: emails accepted by Email Service (including later hard bounces). Not counted: emails rejected at the API (including suppression-list blocks) and verified-destination sends. — [Email Service pricing](https://developers.cloudflare.com/email-service/platform/pricing/)
- Workers Paid has "a minimum charge of $5 USD per month for an account." — [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)
- Limits: no published daily number; new accounts start with a "conservative daily quota" that rises with sending behavior/deliverability; per-second limits unpublished; error codes `E_RATE_LIMIT_EXCEEDED` and `E_DAILY_LIMIT_EXCEEDED` exist. Per email: 50 recipients (to+cc+bcc), subject 998 chars, 5 MiB total including attachments (25 MiB for verified destinations only), up to 32 attachments, custom headers 16 KB. Before a sending domain is onboarded you can send only to verified destination addresses; afterwards any recipient. Verified-destination sends do not count toward monthly or daily quotas. Suppression bulk import 1,000 items/request, 10 requests/min (429 beyond). Senders must follow CAN-SPAM/GDPR/CASL and honor unsubscribes. — [Email Service limits](https://developers.cloudflare.com/email-service/platform/limits/), [Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/)
- Prerequisites: Cloudflare DNS; Compute > Email Service > Email Sending > Onboard Domain; Cloudflare adds records on a `cf-bounce` subdomain (3 MX for bounces, SPF TXT, DKIM TXT) plus a DMARC TXT at `_dmarc`; REST/SMTP need account ID and an API token with Email Sending: Edit. — [Send emails](https://developers.cloudflare.com/email-service/get-started/send-emails/), [Domains](https://developers.cloudflare.com/email-service/configuration/domains/)
- Binding restrictions (`send_email` entries): no restriction attribute = "can send to any verified destination address in your account"; `destination_address` pins one recipient (and fills `to` if omitted); `allowed_destination_addresses` and `allowed_sender_addresses` are allowlists; the sender must belong to an onboarded domain. Errors: `E_SENDER_NOT_VERIFIED`, `E_SENDER_DOMAIN_NOT_AVAILABLE`, `E_RECIPIENT_NOT_ALLOWED`, `E_RECIPIENT_SUPPRESSED`. Legacy `EmailMessage` (raw MIME) remains supported; structured `send()` is recommended. — [Send bindings](https://developers.cloudflare.com/email-service/configuration/send-bindings/), [Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/)
- Legacy framing still in Wrangler docs: a Worker can email "an email address verified on Email Routing", requiring Email Routing enabled and at least one verified address. — [Wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/)
- Integrations: Agents SDK `onEmail` hook, Email MCP server, Wrangler email commands. Messages sent via the binding appear as "dropped" in the Email Routing summary even when delivered (use sending metrics/logs). — [Public beta post](https://developers.cloudflare.com/changelog/post/2026-04-16-email-sending-public-beta/), [Email Routing limits](https://developers.cloudflare.com/email-routing/limits/)
- Birthday Week 2026 (46 announcements) contained no Email, Images or Realtime item. — [Birthday Week 2026 wrap-up](https://blog.cloudflare.com/birthday-week-2026-wrap-up/)

### Inferences
- On $0, a Worker can email only the account owner's verified addresses (contact-form notifications, monitoring alerts, admin digests) at no metered cost; mail to end users (verification links, receipts, magic links) requires Workers Paid while the service is in beta.
- Example Paid cost (my arithmetic from the published rates): 10,000 emails/month = $5 base + (10,000 - 3,000) x $0.35/1,000 = about $7.45; 100,000 = about $38.95.
- Idea: contact form -> `env.EMAIL.send()` to the owner (free); inbound Email Worker replies via `reply()` to support requests on the same domain.

### Gaps
- No GA date or post-beta pricing; behavior after the 3,000 included emails (block vs auto-bill) is not stated; daily quota numbers unpublished.
- The send-bindings page only mentions verified destinations while pricing/limits pages allow any recipient after onboarding on Workers Paid; likely legacy wording left in place, but unreconciled.
- The limits page (fetch summary) says "You can send only from routing domains"; meaning unclear versus the separate Sending onboarding.
