> Cross-cutting facts (apply to every section): the Workers Free plan is the default plan ("By default, users have access to the Workers Free plan", which "includes limited usage of Workers, Pages Functions, Workers KV and Hyperdrive"); Workers Free = 100,000 requests/day and 10 ms CPU per invocation — [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/). ## Workers KV on Free

### Takeaway
Classic Workers KV is a permanent Workers Free feature: 100,000 reads/day, 1,000 writes/day, 1,000 deletes/day, 1,000 list requests/day and 1 GB storage, all resetting at 00:00 UTC; at a daily limit further operations of that type fail with an error (no auto-billing). KV is eventually consistent (other locations can lag 60 s or more). "Workers KV Instant" (Oct 1, 2026) is a separate private-beta mode with no free allowance.

### Cited Findings
- Free vs Paid quotas. Free: keys read 100,000/day; keys written 1,000/day; keys deleted 1,000/day; list requests 1,000/day; stored data 1 GB. Paid: 10M reads/month then +$0.50/M; 1M writes/month then +$5.00/M; 1M deletes/month then +$5.00/M; 1M lists/month then +$5.00/M; 1 GB then +$0.50/GB-month. — [KV pricing](https://developers.cloudflare.com/kv/platform/pricing/) (page last updated Apr 21, 2026)
- Reset and behavior at the limit: all Free limits reset daily at 00:00 UTC, and "if you exceed any one of these limits, further operations of that type will fail with an error". — [KV pricing](https://developers.cloudflare.com/kv/platform/pricing/)
- What consumes the quota: billing is per key (bulk reads bill per key read); each key-value pair in a REST API bulk write counts as one write; dashboard and wrangler operations count; reads of non-existent keys (null / HTTP 404) count; no egress charge. — [KV pricing](https://developers.cloudflare.com/kv/platform/pricing/)
- Limits table (Free column): writes to the same key 1 per second; operations per Worker invocation 1,000 (a bulk request counts as 1); namespaces per account 1,000; storage per account 1 GB; storage per namespace 1 GB; keys per namespace unlimited; key size 512 bytes; key metadata 1,024 bytes; value size 25 MiB; minimum cacheTtl 30 seconds. Paid differs only by unlimited reads/writes/storage. REST API access is subject to the global Cloudflare REST API rate limits. — [KV limits](https://developers.cloudflare.com/kv/platform/limits/) (page last updated Oct 8, 2026)
- Consistency model: eventually consistent. Writes go to central stores; the location that made the write usually (not guaranteed) sees it immediately; other locations may take 60 seconds or more; negative lookups are cached; default cacheTtl is 60 s; not suited to atomic/transactional use or same-key write-heavy workloads (use Durable Objects). — [How KV works](https://developers.cloudflare.com/kv/concepts/how-kv-works/) (Apr 21, 2026)
- Changes 2025-2026 (all still current): namespace cap raised from 200 to 1,000 for both Free and Paid on 2025-01-28 — [changelog](https://developers.cloudflare.com/changelog/post/2025-01-27-kv-increased-namespaces-limits/); minimum cacheTtl reduced from 60 s to 30 s on 2026-01-30 (default stays 60 s) — [changelog](https://developers.cloudflare.com/changelog/post/2026-01-30-kv-reduced-minimum-cachettl/); namespace jurisdictions (eu, us, fedramp; set only at creation) became GA on 2026-10-02 — [changelog](https://developers.cloudflare.com/changelog/post/2026-10-02-kv-jurisdictions-ga/). No change to the Free quotas was found in KV's 2025-2026 changelog list. — [KV changelog](https://developers.cloudflare.com/changelog/product/kv/)
- Workers KV Instant: private beta (enroll through account team or sign-up form); limits 1 write/s per namespace, 1 MB storage per namespace, 10,000 keys per namespace, 300-byte keys, no metadata, list returns everything with no pagination. — [KV limits](https://developers.cloudflare.com/kv/platform/limits/)
- KV Instant blog (Oct 1, 2026): built on Quicksilver v2, namespace created with mode "instant", changes immediate (no TTL wait), sub-2 ms p99 reads; pricing stated in the post: Class B reads $0.20 per million keys, Class A (put/delete/list) $0.10 per operation, storage $100 per MB per month (vs classic $0.50/M reads, $5.00/M Class A, $0.50/GB-month); the post says storage and Class A are "significantly more expensive" than classic KV and recommends KV Instant only for small, rarely-updated config. No free allowance or Free-plan availability is mentioned. — [Introducing Workers KV Instant](https://blog.cloudflare.com/workers-kv-instant/)
- Cross-check on invocation limits: Workers docs list 1,000 subrequests to internal services on Free (default 10,000 on Paid), whereas the KV page lists 1,000 operations per invocation for both plans. — [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) vs [KV limits](https://developers.cloudflare.com/kv/platform/limits/)

- 1,000 writes/day is the binding constraint (about 0.7 writes/minute average): fine for config/content, not for counters, rate limiting, sessions with frequent writes or logs. Reads of missing keys cost a read, so negative-cache in the Worker.

## D1 on Free

### Takeaway
D1 is a permanent Workers Free feature: 5 million rows read/day, 100,000 rows written/day, 5 GB total storage over up to 10 databases (each max 500 MB), 7-day Time Travel and 50 queries per Worker invocation. Daily limits reset at 00:00 UTC; when exceeded, D1 returns errors until the reset (no auto-billing) and Cloudflare's Sept 1, 2026 notice confirms enforcement is active for Free accounts. Read replication (Sessions API) adds no extra charge.

### Cited Findings
- Billing metrics, Workers Free: rows read 5 million/day; rows written 100,000/day; storage 5 GB total. Workers Paid: first 25 billion rows read/month then $0.001/M; first 50 million rows written/month then $1.00/M; first 5 GB then $0.75/GB-month. Free limits reset daily at 00:00 UTC. — [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/) (Apr 21, 2026)
- Behavior at the limit: when the daily read and/or write limit is reached you cannot run queries and the D1 API returns errors saying the daily limit was exceeded; when the storage cap is reached you must delete databases/data before you can insert, create/alter tables, or create indexes/triggers; upgrading to Workers Paid removes the limits, typically within minutes. "Will D1 always have a Free plan? Yes." — [D1 pricing FAQ](https://developers.cloudflare.com/d1/platform/pricing/)
- Enforcement notice: "Beginning September 1, 2026, D1 queries on the Workers Free plan will fail when an account exceeds the daily row read or row write limits" via both the Workers Binding API and REST API until midnight UTC; stored data is not affected; email alerts are sent; error text: "Your account has exceeded D1's free tier daily row read limit (or row write limit). Upgrade to a paid plan or wait until tomorrow (midnight UTC)". — [changelog 2026-09-01](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/)
- Counting rules: rows read = rows scanned (not returned), so unindexed filters read whole tables; rows written count INSERT/UPDATE/DELETE; each index adds a written row per indexed write; row size/columns do not matter; DDL can count as reads+writes; dashboard/Wrangler queries count; empty database about 12 KB; no egress/throughput charge; storage = sum of all databases (tables and indexes). — [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/)
- Limits table: databases per account 10 (Free) / 50,000 (Paid); max database size 500 MB (Free) / 10 GB (Paid, cannot be raised); max storage per account 5 GB (Free) / 1 TB (Paid); Time Travel 7 days (Free) / 30 days (Paid); max 10 Time Travel restores per 10 minutes per database; queries per Worker invocation 50 (Free) / 1,000 (Paid); max 100 columns per table; max string/BLOB/row size 2 MB; max SQL statement 100 KB; max 100 bound parameters; max query duration 30 s; max import file (`d1 execute --file`) 5 GB (uploaded via R2); six simultaneous D1 connections per invocation. — [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) (Apr 21, 2026)
- Concurrency: each database is single-threaded (throughput = 1 / average query time); excess concurrent requests are queued, then an "overloaded" error is returned. — [D1 limits FAQ](https://developers.cloudflare.com/d1/platform/limits/)
- Time Travel: always on, no extra cost; restore to any minute within 30 days (Paid) or 7 days (Free); restore is destructive/in-place but returns an undo bookmark; needs Wrangler v3.4.0+ and a production-backend database; export to R2 via Workflows is the documented way to keep history longer; cloning/forking not yet supported. — [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) (Apr 21, 2026)
- Read replication / Sessions API: enable per database in the dashboard (Settings > Enable Read Replication) or via REST `read_replication.mode: auto`; queries must go through `db.withSession()` (constraints `first-primary`, `first-unconstrained`, or a bookmark) or they run only on the primary; replicas auto-created in every supported region; sequential consistency within a session; disabling takes up to 24 hours; no extra storage/compute cost (billing remains rows_read/rows_written); the page (updated Aug 10, 2026) states no plan restriction. — [D1 read replication](https://developers.cloudflare.com/d1/best-practices/read-replication/) and [D1 Worker API](https://developers.cloudflare.com/d1/worker-api/d1-database/)
- Read replication status: announced as "D1 Read Replication Public Beta" on 2025-04-10 with replicas "at no additional cost"; no GA announcement appears in D1's 2025-2026 changelog list (entries: 2025-09-11 automatic read retries, 2025-11-05 jurisdictions, 2026-09-01 free-tier enforcement, 2026-10-02 US jurisdiction). — [changelog 2025-04-10](https://developers.cloudflare.com/changelog/post/2025-04-10-d1-read-replication-beta/) and [D1 changelog](https://developers.cloudflare.com/changelog/product/d1/)
- Import/export: import with `wrangler d1 execute <db> --remote --file=x.sql` (SQL text only; raw .sqlite3 files must be converted; files up to 5 GiB); export with `wrangler d1 export <db> --remote --output=x.sql` (options for single table, schema only, data only); limitations: export is not supported for databases with virtual tables (FTS5), and a running export blocks other database requests. — [D1 import/export](https://developers.cloudflare.com/d1/best-practices/import-export-data/) (Apr 21, 2026)
- Superseded history: the Jan 13, 2025 release note said Free-tier limits would be enforced "from 2025-02-10" (minimum Paid billing $5/month); the Sept 1, 2026 changelog post above re-states a "beginning September 1, 2026" enforcement date, so the effective enforcement date is best treated as Sept 1, 2026 or earlier; either way enforcement is active on 2026-10-14. — [D1 release notes](https://developers.cloudflare.com/d1/platform/release-notes/) and [changelog 2026-09-01](https://developers.cloudflare.com/changelog/post/2026-09-01-d1-free-tier-limit-enforcement/)
- Discrepancy to note: Workers docs list 1,000 subrequests to internal services on Free, while D1's own limits page lists 50 queries per invocation on Free (1,000 on Paid, although Workers docs say the Paid default is 10,000). Use D1's documented figure (50) when designing for Free. — [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) vs [D1 limits](https://developers.cloudflare.com/d1/platform/limits/)

- Rows read is the real budget: scanning a 100k-row table 50 times uses the whole 5M/day; index every filter column. Rows written (100k/day) is the other ceiling, and each index roughly doubles write cost for that column.
- 5 GB cap = 10 databases x 500 MB, so per-tenant databases are not viable on Free.
- D1 reads/writes can be offloaded with KV / Workers Cache so the 5M/100k budgets last.

## R2 on Free: allowances, prerequisites, public access and bucket features

### Takeaway
R2 has a permanent monthly free allowance on Standard storage only: 10 GB-month storage, 1 million Class A and 10 million Class B operations per month, and zero egress fees; Infrequent Access has no free tier. Using R2 requires adding an "R2 subscription" through a dashboard checkout flow; whether a payment card is mandatory is unresolved (docs silent; a first-party marketing line and third-party reports conflict). Unlike KV/D1/Hyperdrive, going over the free amount is billed pay-as-you-go rather than blocked.

### Cited Findings
- Free tier (monthly): storage 10 GB-month; Class A 1 million requests; Class B 10 million requests; egress free. "The free tier only applies to Standard storage, and does not apply to Infrequent Access storage." All included usage is monthly. — [R2 pricing](https://developers.cloudflare.com/r2/pricing/) (page last updated Oct 1, 2026)
- Rates beyond free: Standard storage $0.015/GB-month, Class A $4.50/M, Class B $0.36/M. Infrequent Access: storage $0.01/GB-month, Class A $9.00/M, Class B $0.90/M, data retrieval $0.01/GB, 30-day minimum storage duration (billed even if deleted earlier). Usage rounds up to the next billing unit (1,000,001 ops bills as 2 million); GB-month = average of daily peak storage over 30 days. — [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
- Behavior when the allowance is exceeded: overage is billed (the pricing page's asset-hosting example bills $104.40 for 290M Class B operations over the free amount); the docs describe no hard cap or failure. Budget alerts exist for pay-as-you-go accounts. — [R2 pricing](https://developers.cloudflare.com/r2/pricing/) and [Budget alerts changelog](https://developers.cloudflare.com/changelog/post/2026-04-13-billable-usage-dashboard-and-budget-alerts/)
- Operation classes: Class A = ListBuckets, PutBucket, ListObjects, PutObject, CopyObject, CompleteMultipartUpload, CreateMultipartUpload, LifecycleStorageTierTransition, ListMultipartUploads, UploadPart, UploadPartCopy, ListParts, PutBucketEncryption, PutBucketCors, PutBucketLifecycleConfiguration. Class B = HeadBucket, HeadObject, GetObject, UsageSummary, GetBucketEncryption, GetBucketLocation, GetBucketCors, GetBucketLifecycleConfiguration. Free = DeleteObject, DeleteBucket, AbortMultipartUpload. Unauthorized (HTTP 401) requests are not charged. Egress via Workers API, S3 API and r2.dev is free (other metered services connected to R2 may charge). — [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
- Prerequisite: "You need a Cloudflare account with an R2 subscription"; if you do not have one go to Storage & databases > R2 > Overview and "complete the checkout flow to add an R2 subscription"; "R2 is free to get started with included free monthly usage". — [R2 get started](https://developers.cloudflare.com/r2/get-started/) (Apr 21, 2026)
- Payment-method evidence (conflicting): the R2 docs corpus (763 KB llms-full.txt) contains no sentence about a payment method/card — [R2 llms-full.txt](https://developers.cloudflare.com/r2/llms-full.txt); the generic billing docs say "a primary payment method is required to purchase Cloudflare products and services" — [Billing docs](https://developers.cloudflare.com/billing/get-started/create-billing-profile/); the R2 product page carries a generic site-wide line "Start building for free — no credit card required" — [R2 product page](https://www.cloudflare.com/developer-platform/products/r2/); web-search summaries of third-party guides (not Cloudflare sources, pages not read in full; results included tech-insider.org, dev.to and flexxible docs) say a card or PayPal is requested before the first bucket can be created, and a Centmin Mod forum thread is summarized as recording a Sept 2025 incident where first-time R2 enablement failed without a payment method already on file — [Centmin Mod thread](https://community.centminmod.com/threads/cloudflare-queues-delivery-latency.29331/next) and [tech-insider guide](https://tech-insider.org/au/how-to-set-up-cloudflare-r2-2026/); the Basin pricing pages say an active R2 subscription AND "a linked payment card" are required — [Basin Catalog pricing](https://developers.cloudflare.com/basin-catalog/platform/pricing/).
- Platform limits: storage per bucket and objects per bucket unlimited; buckets per account 1,000,000; bucket-management operations 50/s per bucket; custom domains per bucket 100; object key 1,024 bytes; object metadata 8,192 bytes; object size up to 5 TiB (4.995 TiB); single-part upload max 5 GiB (4.995 GiB); multipart max 4.995 TiB with up to 10,000 parts; writes to the same key limited to 1 per second (HTTP 429 above that); Cloudflare REST API for R2 limited to 1,200 requests per 5 minutes (use S3 or Workers API for object traffic). — [R2 limits](https://developers.cloudflare.com/r2/platform/limits/) (Jun 8, 2026)
- r2.dev public development URL: "not intended for production usage", variable rate limit (hundreds of requests/second) after which requests are throttled with HTTP 429, bandwidth may also be throttled; WAF, caching, access control and Bot Management are unavailable on r2.dev; pointing your own CNAME at r2.dev is an unsupported path; enabling needs typing `allow` in the dashboard. — [R2 limits](https://developers.cloudflare.com/r2/platform/limits/) and [Public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/) (Sep 25, 2026)
- Custom domains: the domain must exist as a zone in the same Cloudflare account as the bucket; a domain not on Cloudflare DNS must use a partial (CNAME) setup; enables Cloudflare Cache / Smart Tiered Cache (only default file types cached unless Cache Everything), WAF, Access, Bot Management, min-TLS/cipher settings; up to 100 per bucket; bucket root listing not available; r2.dev and custom domains can be enabled independently. — [Public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/)
- Partial (CNAME) setup "is only available to customers on a Business or Enterprise plan" (and not for Registrar domains), so on a Free zone the practical route is a full setup (Cloudflare nameservers). — [CNAME setup (Partial)](https://developers.cloudflare.com/dns/zone-setups/partial-setup/) (Aug 14, 2026)
- Presigned URLs: operations GET, PUT, HEAD, DELETE; expiry from 1 second to 7 days (604,800 s); generated locally with AWS SigV4 using an R2 API token (no R2 call); they work only on the S3 API domain (`<ACCOUNT_ID>.r2.cloudflarestorage.com`) and cannot be used with custom domains (for those, use WAF HMAC validation, which needs Pro or above); browser use needs a CORS policy. — [Presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)
- S3 API compatibility: implemented operations include AbortMultipartUpload, CompleteMultipartUpload, CopyObject, CreateBucket, CreateMultipartUpload, DeleteBucket, DeleteBucketCors, DeleteObject(s), Get/PutBucketCors, Get/PutBucketLifecycleConfiguration, GetBucketLocation, GetBucketEncryption, GetObject, HeadBucket, HeadObject, ListBuckets, ListMultipartUploads, ListObjects(V2), ListParts, PutObject, UploadPart, UploadPartCopy; not implemented include bucket ACLs, bucket policy, versioning, tagging, website, logging, replication, notification config and S3 Object Lock (R2 has its own event notifications and bucket locks); checksum support includes CRC-64/NVME. — [R2 S3 API](https://developers.cloudflare.com/r2/api/s3/api/)
- CORS: configured per bucket (dashboard / API / PutBucketCors) for both public buckets and presigned URLs; the configuration call is a Class A operation. — [R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/) (Sep 23, 2026)
- Event notifications: messages go to a Cloudflare Queue (prerequisites: bucket, queue, and a consumer Worker or HTTP pull consumer); up to 100 rules per bucket; event types object-create and object-delete (incl. lifecycle deletes); prefix/suffix filters; generally available since 2024-09-26; Queues throughput 5,000 messages/s per queue. — [Event notifications](https://developers.cloudflare.com/r2/buckets/event-notifications/) and [R2 release notes](https://developers.cloudflare.com/r2/platform/release-notes/)
- Lifecycle rules: up to 1,000 rules per bucket; delete or transition (Standard to IA only, not back) by age/prefix; objects typically removed within 24 hours of expiry; default rule aborts incomplete multipart uploads after 7 days; a Standard-to-IA transition costs one Class A operation. — [Object lifecycles](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)
- Bucket locks: retention rules (by duration, until a date, or indefinite) per prefix to block deletion/overwrite; up to 1,000 rules per bucket; launched 2025-03-06; no separate fee is listed. — [Bucket locks](https://developers.cloudflare.com/r2/buckets/bucket-locks/) and [changelog 2025-03-06](https://developers.cloudflare.com/changelog/post/2025-03-06-r2-bucket-locks/)
- Local uploads: writes upload data near the client then replicates asynchronously; immediately available and strongly consistent; "no additional cost" (standard Class A rates); not supported on jurisdiction-restricted buckets; launched in open beta on 2026-02-03 (the docs page updated Sep 18, 2026 carries no beta label). — [Local uploads](https://developers.cloudflare.com/r2/buckets/local-uploads/) and [changelog 2026-02-03](https://developers.cloudflare.com/changelog/post/2026-02-03-r2-local-uploads/)
- Storage classes: Standard (default, no minimum duration) and Infrequent Access (30-day minimum, retrieval fee); both 11 nines durability and no minimum object size; change class with CopyObject `x-amz-storage-class`. — [Storage classes](https://developers.cloudflare.com/r2/buckets/storage-classes/)
- Newer R2 features: Data Access Logs went GA on 2026-09-04 (events appear in Workers Observability, 7-day retention, best-effort delivery, non-jurisdictional buckets; "Beginning December 1, 2026, they use Cloudflare Observability pricing") — [Data Access Logs](https://developers.cloudflare.com/r2/buckets/data-access-logs/); dashboard can empty a bucket / delete folders since 2026-04-27 — [R2 release notes](https://developers.cloudflare.com/r2/platform/release-notes/). The R2 release-notes feed shows no change to the Free allowance in 2025-2026. — [R2 release notes feed](https://developers.cloudflare.com/r2/platform/release-notes/index.xml)

- Class A is the scarcest resource: 1M/month is about 33k writes/day (lists, multipart parts and lifecycle transitions all count); 10M Class B/month is about 333k reads/day — put a custom domain with Cloudflare Cache in front of public objects so cache hits never reach R2.

- Local uploads current stage (beta vs GA) is unclear; Bucket locks / lifecycle have no stated extra fees but were not checked against a billing page.

## R2 migration tools: Sippy and Super Slurper

### Takeaway
Both tools are free to use; you only pay the R2 Class A operations they generate (plus the source provider's own egress/request charges). Sippy is GA and now supports Azure Blob and any S3-compatible source; Super Slurper does one-time bulk copies.

### Cited Findings
- Super Slurper "is free to use. You are only charged for the Class A operations" it makes to R2 (objects under 100 MiB use one Class A op, larger use multipart = several); the source bucket may charge extra. — [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
- Sippy is free to use; you pay only for operations Sippy makes to R2 (objects under 200 MiB use one Class A op, larger use multipart); after migration objects are served from R2 and billed normally. — [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
- Super Slurper sources: Amazon S3, Cloudflare R2, Google Cloud Storage and all S3-compatible providers (tested: Backblaze B2, DigitalOcean Spaces, Scaleway, Wasabi); preserves custom metadata, never deletes source objects, TLS in transit; objects larger than 1 TB are skipped (use rclone for those); overwrite or skip option for existing keys. — [Super Slurper](https://developers.cloudflare.com/r2/data-migration/super-slurper/)
- Sippy: serves an object from R2 if present, otherwise returns it from the source and copies it to R2 at the same time; puts and deletes work as usual; setup needs an existing R2 bucket and read-only credentials for the source (enable in bucket Settings > On Demand Migration or `wrangler r2 bucket sippy enable`); supports jurisdictional buckets with the `cf-r2-jurisdiction` header. — [Sippy](https://developers.cloudflare.com/r2/data-migration/sippy/) (Sep 18, 2026)
- Sippy status and sources: GA since 2024-08-21; since 2026-07-24 it also supports Azure Blob Storage and any S3-compatible provider (in addition to Amazon S3 and GCS). — [R2 release notes](https://developers.cloudflare.com/r2/platform/release-notes/) and [changelog 2026-07-24](https://developers.cloudflare.com/changelog/post/2026-07-24-r2-sippy-azure-s3-compatible-support/)
- Super Slurper limit history: objects up to 1 TB supported since 2024-06-12; GCS source added 2024-04-03. — [R2 release notes](https://developers.cloudflare.com/r2/platform/release-notes/)

### Inferences
- Inventory: Super Slurper and Sippy = free tools (label FREE; operations draw down the same 1M Class A/month allowance; both require an R2 subscription because they write to R2). GA. Idea: Sippy for a zero-downtime lazy move of an existing image bucket; Super Slurper for a one-off bulk copy. Sources: [R2 pricing](https://developers.cloudflare.com/r2/pricing/), [Sippy](https://developers.cloudflare.com/r2/data-migration/sippy/), [Super Slurper](https://developers.cloudflare.com/r2/data-migration/super-slurper/).

## Hyperdrive on Workers Free

### Takeaway
Hyperdrive is a permanent Workers Free feature (added to Free on 2025-04-08): 100,000 database queries/day (cached and uncached both count), 10 configurations per account and about 20 origin connections per configuration; when exceeded, operations fail with an error until the 00:00 UTC reset. Postgres and MySQL (MySQL GA 2026-08-07) are supported; pooling and caching cost nothing extra.

### Cited Findings
- Pricing: included in Free and Paid Workers plans; Free = 100,000 database queries/day, Paid = unlimited; limits reset daily 00:00 UTC; "further operations of that type will fail with an error" when exceeded; a "database query" is any statement through Hyperdrive (SELECT, INSERT/UPDATE/DELETE, DDL); limits adjust automatically on upgrade. — [Hyperdrive pricing](https://developers.cloudflare.com/hyperdrive/platform/pricing/) (Jun 18, 2026)
- Cached and uncached queries both count; pooling and caching add no charge; no egress charge; FAQ confirms availability on Workers Free. — [Hyperdrive pricing FAQ](https://developers.cloudflare.com/hyperdrive/platform/pricing/) and [Hyperdrive FAQ](https://developers.cloudflare.com/hyperdrive/reference/faq/)
- Limits: configured databases 10 per account (Free) / 25 (Paid); username and database name max 63 bytes; initial connection timeout 15 s; idle timeout 10 min; max origin connections per configuration about 20 (Free) / about 100 (Paid) (soft; configurable down to a minimum of 5); no limit on concurrent Worker client connections; max query duration 60 s (longer queries terminated); max cached response 50 MB (larger responses returned but not cached). — [Hyperdrive limits](https://developers.cloudflare.com/hyperdrive/platform/limits/) (Jun 9, 2026) and [release notes 2025-07-03](https://developers.cloudflare.com/hyperdrive/platform/release-notes/)
- Query caching: on by default; defaults `max_age` = 60 s and `stale_while_revalidate` = 15 s; maximum `max_age` is 1 hour; writes do not invalidate cached reads; only read-only queries are cached and queries using VOLATILE or (since 2026-02-23) STABLE PostgreSQL functions such as NOW() are not cached; disable per configuration with `--caching-disabled` (use a second cache-disabled binding for read-after-write); available on the Free plan because caching is part of Hyperdrive. — [Query caching](https://developers.cloudflare.com/hyperdrive/concepts/query-caching/) (Jul 5, 2026) and [changelog 2026-02-23](https://developers.cloudflare.com/changelog/post/2026-02-23-hyperdrive-stable-functions-uncacheable/)
- Supported databases: PostgreSQL 9.0 to 18.x and MySQL 5.7 to 8.x (MariaDB also), self-hosted or managed (AWS, Azure, GCP, Oracle, Aurora, Neon, Supabase, Timescale, CockroachDB, PlanetScale, etc.); SQL Server and MongoDB not supported; D1 is not supported (and not needed); TLS always on (require / verify-ca / verify-full); unsupported Postgres features include SQL-level PREPARE/DEALLOCATE, advisory locks and LISTEN/NOTIFY. — [Supported databases](https://developers.cloudflare.com/hyperdrive/reference/supported-databases-and-features/) (Sep 30, 2026)
- Status history: Hyperdrive Free plan introduced 2025-04-08 (MySQL support announced the same day) — [changelog](https://developers.cloudflare.com/changelog/post/2025-04-08-hyperdrive-free-plan/); "MySQL support in Hyperdrive is now generally available" on 2026-08-07 at the same pricing as Postgres — [changelog](https://developers.cloudflare.com/changelog/post/2026-08-07-hyperdrive-mysql-ga/).
- Private databases: two documented routes. (1) Cloudflare Tunnel plus Cloudflare Access: needs a TLS-enabled database in the private network, `cloudflared` running there, and "a hostname on your Cloudflare account" to route requests; Hyperdrive auto-creates the Access application, service token and policies. (2) Workers VPC service (documented as recommended since 2026-04-29): pick a Cloudflare Tunnel and enter origin host and TCP port, with no Access application or service token to configure. — [Private database via Tunnel](https://developers.cloudflare.com/hyperdrive/configuration/connect-to-private-database/) (Oct 12, 2026), [release notes 2025-01-28](https://developers.cloudflare.com/hyperdrive/platform/release-notes/) and [changelog 2026-04-29](https://developers.cloudflare.com/changelog/post/2026-04-29-hyperdrive-vpc-private-databases/)
- Workers VPC pricing: "free during the open beta period" with standard Workers pricing for requests/compute; "requires a Workers plan" (Free plan not named; read via a fetch-tool summary). — [Workers VPC pricing](https://developers.cloudflare.com/workers-vpc/reference/pricing/) (Sep 16, 2026)
- Paid add-on: PlanetScale Postgres/MySQL databases created from the Cloudflare dashboard are billed through the Cloudflare invoice at PlanetScale's standard pricing, separate from Hyperdrive (third-party database, pay-as-you-go). — [Hyperdrive pricing](https://developers.cloudflare.com/hyperdrive/platform/pricing/) and [changelog 2026-06-18](https://developers.cloudflare.com/changelog/post/2026-06-18-planetscale-databases-cloudflare-billing/)

## Workers Cache API (caches.default / cache.put / cache.match) and the new Workers Cache

### Takeaway
The classic Cache API has no separate price or daily quota: on Free it allows 50 Cache API calls per request (shared with the 50-subrequest limit) and objects up to 512 MB, and entries are local to one data center. Docs still say custom-domain Workers have "functional" cache operations, but the explicit "*.workers.dev has no impact" warning was deleted from the docs on 2025-03-05, so workers.dev now appears to work (unverified by test). Since 2026-07-06 the zoneless "Workers Cache" (`cache.enabled`) is available on every plan, works on workers.dev, and has no separate fee (all requests still bill/count as Worker requests).

### Cited Findings
- Cache API behavior: programmatic interface to Cloudflare's cache; contents do not replicate outside the originating data center; `cache.put` is incompatible with tiered caching; `cache.delete` purges only the local data center (global purge needs standard purge options); `caches.default` is the cache shared with `fetch`, `caches.open()` creates namespaced caches. — [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/) (Aug 14, 2026) and [How the cache works](https://developers.cloudflare.com/workers/reference/how-the-cache-works/) (Jul 6, 2026)
- Where it works: "Workers deployed to custom domains have access to functional `cache` operations. So do Pages functions, whether attached to custom domains or `*.pages.dev` domains"; operations in the dashboard editor and Playground previews have no impact; not available for Workers fronted by Cloudflare Access. — [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/)
- workers.dev evidence: the docs commit "EW-6697 Remove workers.dev Cache API restriction" (2025-03-05) deleted the phrase "and any `*.workers.dev` deployments will have no impact" from that paragraph, and a later note says the redirect/query-string restriction "does not apply on `.workers.dev` domains, which include the query string in the cache key by default". — [docs commit 935b0366c6](https://github.com/cloudflare/cloudflare-docs/commit/935b0366c6) and [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/). Contradicting older material: a 2023 community answer says the Cache API is not enabled on workers.dev — [community thread](https://community.cloudflare.com/t/cloudflare-worker-cache-does-not-work/298125) (pre-dates the 2025 docs change).
- Methods: `put` throws for non-GET requests, 206 responses and `Vary: *`, returns 413 if Cache-Control says not to cache or the response is too large, and silently skips Set-Cookie responses; `match` never contacts the origin, returns undefined on a miss, lacks `ignoreSearch`/`ignoreVary`, honors Range / If-Modified-Since / If-None-Match; `stale-while-revalidate` and `stale-if-error` are not supported with put/match; Cache-Tag purging no longer labelled Enterprise-only (docs edit 2025-04-10). — [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/) and [docs commit a6a5c42e14](https://github.com/cloudflare/cloudflare-docs/commit/a6a5c42e14)
- Limits: maximum object size 512 MB (Free and Paid); Cache API calls (`put`/`match`/`delete`) per request 50 on Free / 1,000 on Paid, sharing the quota with `fetch` subrequests; `.put()` with a chunked body blocks later `.put()` calls until it completes; failure mode when exceeding the call limit is not described. — [Workers limits: Cache API limits](https://developers.cloudflare.com/workers/platform/limits/)
- Pricing: no cache fee is listed; a Cache API call is a subrequest-style call inside a Worker request that already counts toward the 100,000 requests/day on Free. — [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) and [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/)
- NEW "Workers Cache" (launched 2026-07-06; blog says "available today to every Worker on any plan" and "The cache works on workers.dev"): enable with `"cache": {"enabled": true}` in Wrangler config (current compatibility date); Cloudflare checks the cache before running the Worker; tiered (lower + upper tier) with request collapsing; cached by `Cache-Control`; only GET/HEAD; purge or soft-invalidate with `ctx.cache.purge()` / `ctx.cache.invalidate()` (invalidate added 2026-09-29); zone Cache Rules / Page Rules do not apply. — [Workers Cache](https://developers.cloudflare.com/workers/cache/), [launch post](https://blog.cloudflare.com/workers-cache/) (read via a fetch-tool summary) and [changelog 2026-09-29](https://developers.cloudflare.com/changelog/post/2026-09-29-workers-cache-invalidate/)
- Workers Cache pricing: "no separate Workers Cache SKU and no per-GB cache storage fee"; all requests (hit or miss, including normally-free static-asset and worker-to-worker requests) bill at the standard Workers request rate; CPU time bills only when the Worker runs. — [Workers Cache - Pricing](https://developers.cloudflare.com/workers/cache/) and [launch post](https://blog.cloudflare.com/workers-cache/)
- Workers Cache limitations: at launch all responses follow the Free plan's cacheable size limit (512 MB) regardless of plan; `purge()` always uses Free-tier purge rate limits; only GET/HEAD `fetch` invocations are cached (cron, queue consumers, Workflows, Tail Workers, Durable Objects, custom RPC methods and WebSocket upgrades always bypass the cache); statuses 520-526 and 206 are never stored; dashboard UI and cache analytics are "coming soon"; docs recommend Workers Cache over the Cache API for new Workers. The docs and blog do not label it beta or GA. — [Workers Cache limitations](https://developers.cloudflare.com/workers/cache/limitations/) (Oct 3, 2026)

### Inferences
- Inventory:

| Item | Label | Free allowance / reset | At limit | Prereqs | Status | Paid-only part | Website+app idea | Source |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Cache API (`caches.default`) | FREE (no quota of its own) | 50 calls per request on Free; 512 MB per object; per-data-center | failure mode not documented; shares subrequest limit | Worker on a custom domain / route (documented); workers.dev appears to work since Mar 2025 but untested | GA | 1,000 calls per request on Paid | wrap D1/Hyperdrive reads so repeats skip the 5M-row budget | [Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/), [limits](https://developers.cloudflare.com/workers/platform/limits/) |
