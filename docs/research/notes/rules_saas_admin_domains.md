# Cloudflare Free plan: Rules products, Cloudflare for SaaS, custom pages, logs/analytics APIs, notifications, account/admin, Registrar/domains (state as of 2026-10-14)

> Scope: Rules-engine products, Cloudflare for SaaS, custom error/challenge pages, logs and analytics APIs, notifications, account/admin features, Registrar and domain options. First-party Cloudflare offerings only, Free plan viewpoint. Research only (no resources created or changed).
> Method: almost every fact below was read verbatim from the raw Markdown (`.../index.md`) of Cloudflare docs pages and changelog posts. Docs pages carry a "Last updated" stamp; the ones used are dated Apr-Oct 2026, so they reflect the state after Birthday Week 2026 (Sep 28 - Oct 2, 2026). Blog posts were read through a summarizing fetch and are marked "(blog, summarized)". No official Developer Week 2026 recap was found; the changelog RSS feeds for Rules, Logs, Cloudflare for SaaS, Registrar, Audit Logs, Fundamentals, Analytics, Billing, Organizations and Terraform were scanned for 2025-2026 changes instead.
> Label legend: FREE-FOREVER = permanent free allowance (quota or monthly allowance); BETA-FREE = free while in beta; TRIAL = free trial or credits; PAID-ONLY = no Free-plan access; "free allowance + overage" = free up to an allowance, then metered billing.

## 1. Rules products on the Free plan (counts, capabilities, regex, paid boundary)

### Takeaway
Every Rules product except two is usable on the Free plan with a flat per-zone rule quota: 10 Cache, 10 Configuration, 10 Origin (destination-port override only), 10 Single Redirect, 10 Compression, 10 "Active Transform Rules", 10 Cloud Connector (beta), and 3 Page Rules (deprecated), plus account-level Bulk Redirects (15 rules, 5 lists, 10,000 URLs) and Lists (1 custom IP list, 10,000 items). The two paid-only products are Snippets (0 on Free) and Custom Errors (0 rules, 0 assets, no Error Pages on Free). Regex is Business-and-up everywhere (wildcards are free), Origin Rule Host/SNI/DNS overrides are Enterprise-only, and every Rules product needs the hostname's DNS record proxied on a zone you own (nothing here works on workers.dev, pages.dev or r2.dev).

### Cited Findings
**Shared facts (apply to every quota-type Rules bullet below unless it says otherwise)**
- Rules are "available on all plans" and require the domain's DNS records to be proxied through Cloudflare. — [Cloudflare Rules](https://developers.cloudflare.com/rules/) (updated Apr 16, 2026)
- Quota semantics: the per-plan figures are caps on the number of rules (no reset period); none of the Rules pages describes overage billing, throttling, or the error returned when a cap is hit (the documentation is silent; see Gaps). — [Redirects availability](https://developers.cloudflare.com/rules/url-forwarding/), [Origin Rules availability](https://developers.cloudflare.com/rules/origin-rules/)
- Execution order of Rules products: Single Redirects, URL Rewrite Rules, Configuration Rules, Origin Rules, Bulk Redirects, Managed Transforms, Request Header Transform Rules, Cache Rules, Snippets, Cloud Connector. All of them take precedence over Page Rules. For terminating actions (block, redirect, challenge) evaluation stops at the first match; for non-terminating actions the last change wins. — [Redirects, Execution order](https://developers.cloudflare.com/rules/url-forwarding/)
- Rule templates: dashboard Rules > Overview > Templates provides prebuilt one-click templates (redirects, rewrites, header changes) plus a public Examples gallery; templates only create ordinary rules that use the normal quota (no separate quota or plan gate is stated). — [Transform Rules](https://developers.cloudflare.com/rules/transform/), [Examples gallery](https://developers.cloudflare.com/rules/examples/), [Page Rules migration guide](https://developers.cloudflare.com/rules/reference/page-rules-migration/)
- Modern Rules (Configuration, Compression, Origin, Redirects, Transform) are described as generally available and adopted by tens of thousands of customers. — [Page Rules migration guide](https://developers.cloudflare.com/rules/reference/page-rules-migration/) (updated Apr 16, 2026)
- Validate-before-deploy: adding `dry_run=true` to Rulesets API mutations validates a change without deploying it (changelog title "Validate Rulesets changes before deployment", Sep 17, 2026). — [Rulesets API](https://developers.cloudflare.com/ruleset-engine/rulesets-api/), [Rules changelog feed](https://developers.cloudflare.com/changelog/rss/rules.xml)

**Cache Rules** — FREE-FOREVER, GA
- Free: 10 rules per zone (Pro 25, Business 50, Enterprise 300); create in dashboard, API or Terraform. — [Cache Rules](https://developers.cloudflare.com/cache/how-to/cache-rules/) (updated Aug 14, 2026)
- Paid/Enterprise-only parts inside Cache Rules: "is in list" operator for the Hostname field (Enterprise), Caching on Port (Enterprise-only), Proxy Read Timeout (Enterprise-only), toggling Origin Cache Control (Enterprise; Free/Pro/Business have it on and cannot disable it), extra custom-cache-key options (Enterprise); Bot Management fields need a Bot Management subscription; Cache Reserve eligibility is settable but plan-based cacheable file limits still apply. A custom cache key containing headers/cookies breaks dashboard single-file purge (use API, prefix, tag, host or purge-everything instead). — [Cache Rules settings](https://developers.cloudflare.com/cache/how-to/cache-rules/settings/)
- Migration note: selecting "Eligible for cache" in a Cache Rule enables Cache Everything by default (unlike Page Rules), so replicate old Page Rule behavior with a "bypass everything" rule first. — [Migration from Page Rules](https://developers.cloudflare.com/cache/how-to/cache-rules/page-rules-migration/)
- Idea: cache static assets and public API GETs on the app domain with a custom Edge TTL and bypass /admin and /api.

**Configuration Rules** — FREE-FOREVER, GA
- Free: 10 rules (Pro 25, Business 50, Enterprise 300). — [Configuration Rules](https://developers.cloudflare.com/rules/configuration-rules/) (updated Aug 14, 2026)
- Settings a rule can change (page updated Oct 7, 2026): Automatic HTTPS Rewrites, Browser Integrity Check, Disable Real User Monitoring (RUM), Disable Zaraz, Email Obfuscation, Fonts, Hotlink Protection, I'm Under Attack, Markdown for Agents (HTML to Markdown for `Accept: text/markdown`), Opportunistic Encryption, Polish (Off/Lossless/Lossy/WebP), Request Body Buffering (Standard/Full/None), Response Body Buffering (Standard/None), Rocket Loader, SSL. The settings page states no per-plan restriction on the settings (underlying features such as Polish may carry their own plan requirement). Request/response body buffering settings were added Jan 27, 2026. — [Configuration Rules settings](https://developers.cloudflare.com/rules/configuration-rules/settings/), [Rules changelog feed](https://developers.cloudflare.com/changelog/rss/rules.xml)
- Idea: turn off Rocket Loader/Email Obfuscation, or enable I'm Under Attack, only on /login or /api.

**Origin Rules** — FREE-FOREVER (restricted), GA
- Free: 10 rules. Overrides on Free: destination port Yes; Host header No; SNI No; DNS record No (Host, SNI and DNS-record overrides are Enterprise only). A Host header override also sets SNI to the same value. — [Origin Rules](https://developers.cloudflare.com/rules/origin-rules/) (updated Aug 14, 2026)
- Consequence: the hostname cannot be changed with a URL Rewrite Rule; the only tool is an Origin Rule DNS-record override, which is Enterprise-only. — [URL Rewrite Rules](https://developers.cloudflare.com/rules/transform/url-rewrite/) (updated May 5, 2026)
- Idea: send /api/* to a non-standard origin port while the public site stays on 443.

**Transform Rules (URL Rewrite, Request Header, Response Header)** — FREE-FOREVER, GA
- Availability table: Free Yes; Active Transform Rules 10 (Pro 25, Business 50, Enterprise 300); Regex support Free No, Pro No, Business Yes, Enterprise Yes. The table gives one "Active Transform Rules" figure and the three sub-pages state no per-type quota. Users need the Firewall role or an Administrator role. — [Transform Rules](https://developers.cloudflare.com/rules/transform/) (updated Aug 14, 2026)
- URL Rewrite: static or dynamic rewrite of path and/or query string, server-side (visitor URL does not change); cannot rewrite the hostname. — [URL Rewrite Rules](https://developers.cloudflare.com/rules/transform/url-rewrite/)
- Request Header Transform: set static, set dynamic (expression), remove. Restrictions: headers starting `x-cf-` or `cf-` cannot be modified/removed (except `cf-connecting-ip` can be removed); values of `x-forwarded-for`, `true-client-ip`, `x-real-ip`, `x-forwarded-proto` cannot be changed; `cookie` cannot be set but can be removed; an expression evaluating to empty or undefined removes the header. — [Request Header Transform Rules](https://developers.cloudflare.com/rules/transform/request-header-modification/)
- Response Header Transform: Set static/dynamic, Add static/dynamic, and remove. — [Response Header Transform Rules](https://developers.cloudflare.com/rules/transform/response-header-modification/)
- Idea: add security/CORS headers for the API and map pretty paths (/app/* to /index.html) with wildcard expressions, no regex needed.

**Managed Transforms** — FREE-FOREVER (some items plan-gated), GA
- One-click header changes; enabling one deploys hidden internal Transform Rules that do NOT count against the Transform Rule cap, are not listed in the dashboard, and apply to all inbound requests of the zone. — [Managed Transforms](https://developers.cloudflare.com/rules/transform/managed-transforms/) (updated Apr 16, 2026)
- Catalog (reference updated Sep 24, 2026): Add bot protection headers (requires Enterprise + Bot Management); Add TLS client auth headers (cf-cert-* for mTLS); Add visitor location headers (cf-ipcity, cf-ipcountry, cf-ipcontinent, cf-iplongitude, cf-iplatitude, cf-region, cf-region-code, cf-metro-code, cf-postal-code, cf-timezone); Add "True-Client-IP" header (Enterprise only); Remove visitor IP headers; Add leaked credentials checks header (`Exposed-Credential-Check` 1 = Pro and above, 2 and 3 = Enterprise, 4 = all plans, so Free only ever gets 4 = previously leaked password; WAF leaked-credentials detection must also be on); Add malicious uploads detection header (values 1/2/3; no plan note on the page); Remove "X-Powered-By" response header; Add security response headers (`x-content-type-options: nosniff`, `x-xss-protection: 1; mode=block`, `x-frame-options: SAMEORIGIN`, `referrer-policy: same-origin`, `expect-ct: max-age=86400, enforce`). — [Available Managed Transforms](https://developers.cloudflare.com/rules/transform/managed-transforms/reference/)
- Idea: enable "Add visitor location headers" so the app/Worker receives country/city/lat-long headers at zero rule cost.

**Redirect Rules (Single Redirects)** — FREE-FOREVER, GA
- Zone-level. Free: 10 rules (Pro 25, Business 50, Enterprise 300); wildcard support Yes on all plans (a wildcard pattern can cover thousands of URLs in one rule); regex Free No, Pro No, Business Yes, Enterprise Yes. Quotas follow the zone plan. — [Redirects](https://developers.cloudflare.com/rules/url-forwarding/) (updated Aug 14, 2026)
- Idea: www to apex, legacy path to new route, locale redirects, all with wildcard patterns.

**Bulk Redirects (lists)** — FREE-FOREVER, GA
- Account-level (works across all domains in the account); quotas follow the highest plan on the account. Free: 15 Bulk Redirect Rules, 5 Bulk Redirect Lists, 10,000 URL redirects across lists (Pro 15/5/25,000; Business 15/5/50,000; Enterprise 50/25/1,000,000 default, several million via account team). Static only: no string replacement, no regex. Runs after the WAF (a WAF block stops the redirect). — [Redirects](https://developers.cloudflare.com/rules/url-forwarding/), [Bulk Redirects](https://developers.cloudflare.com/rules/url-forwarding/bulk-redirects/) (updated Jun 26, 2026)
- Idea: upload a CSV of up to 10,000 old-URL to new-URL mappings that applies to every domain you own.

**Lists (custom lists referenced in rule expressions)** — FREE-FOREVER (restricted), GA
- Free: 1 custom list (any type), max 10,000 items across custom lists, IP lists Yes, hostname lists No, ASN lists No, Managed IP Lists No (those are Enterprise). Pro and Business: 10 lists / 10,000 items; Enterprise: 1,000 lists / 500,000 items. "Any account with at least one paid plan will get the highest quota" for its tier. Lists are account-level and reusable across zones; roles allowed: Super Administrator, Administrator, Firewall. Not every product supports lists in expressions. — [Lists](https://developers.cloudflare.com/waf/tools/lists/) (updated Aug 14, 2026)
- Idea: keep one IP allow/block list and reference it from every zone's WAF and rate-limit rules.

**Page Rules** — FREE-FOREVER but DEPRECATED
- Docs label Page Rules "(deprecated)". Free 3 / Pro 20 / Business 50 / Enterprise 125. Only the highest-priority matching rule applies; disabled rules still count against the cap; a proxied DNS record is required (a reserved-IP placeholder such as 192.0.2.1 works for hostnames with no real origin). — [Page Rules](https://developers.cloudflare.com/rules/page-rules/) (updated Aug 14, 2026)
- Migration: Cloudflare says it "will handle the migration of your existing Page Rules automatically", "planned for late 2025 or beyond" with advance notice; no concrete date is published (guide updated Apr 16, 2026). Page Rules settings with no replacement include Disable Performance, Disable Railgun, Disable Security. Requests handled by Workers suppress Page Rules actions but not modern Rules. — [Page Rules migration guide](https://developers.cloudflare.com/rules/reference/page-rules-migration/)
- Idea: do not build on them; use the 10-per-product modern rules instead of 3 total.

**Compression Rules** — FREE-FOREVER, GA
- Available in all plans: Free 10 rules (Pro 25, Business 50, Enterprise 300). Match on file extension and response content type; when several algorithms are listed Cloudflare picks the first one the browser's `accept-encoding` supports (gzip and Brotli are named; zstd is not mentioned on the page); no compression if the visitor supports none of them or if the origin sends `cache-control: no-transform`. — [Compression Rules](https://developers.cloudflare.com/rules/compression-rules/) (updated Aug 14, 2026)
- Idea: force Brotli for JS/CSS/JSON from the app origin, gzip for legacy paths.

**URL normalization** — FREE-FOREVER, GA
- "Available in all Cloudflare plans." Normalizes incoming URLs (e.g., `/hello` vs `/%68ello`) before WAF custom rules, Workers and Access see them, and optionally what the origin receives; baseline normalization (e.g., `//page` to `/page`) always applies and cannot be disabled; it never redirects the visitor. — [URL normalization](https://developers.cloudflare.com/rules/normalization/) (updated Apr 16, 2026)
- Idea: leave it on so path-based WAF/Rules cannot be bypassed with encoded or double-slash URLs.

**Custom Error Rules / custom error assets / Error Pages** — PAID-ONLY (details in section 3)
- Free: No, 0 rules, 0 assets. — [Custom Errors](https://developers.cloudflare.com/rules/custom-errors/) (updated Sep 8, 2026)

**Snippets** — PAID-ONLY
- Free: No, 0 snippets, 0 subrequests; Pro 25 snippets / 2 subrequests; Business 50 / 3; Enterprise 300 / 5. All-plan limits: 5 ms max execution time, 2 MB memory, 32 KB total package. One snippet rule per snippet; domain must be proxied. "Snippets are included at no cost on all paid plans"; Version Management does not support Snippets. — [Snippets](https://developers.cloudflare.com/rules/snippets/), [When to use Snippets vs Workers](https://developers.cloudflare.com/rules/snippets/when-to-use/)
- GA on Apr 9, 2025 ("at no extra cost on all Pro, Business, and Enterprise plans"); Snippets gained Custom Lists, Bot Score and WAF Attack Score matching on May 9, 2025. — [Snippets GA](https://developers.cloudflare.com/changelog/post/2025-04-09-snippets-ga/), [Rules changelog feed](https://developers.cloudflare.com/changelog/rss/rules.xml)
- Free alternative for edge logic: a Worker on the Workers free tier (other researcher's scope).

**Cloud Connector** — BETA-FREE
- "Cloud Connector (Beta)... available in beta to all customers"; Free Yes, 10 rules (Pro 25, Business 50, Enterprise 300). Routes matching traffic to R2 or an external provider; Cloud Connector rules run last in the request pipeline and win over other rules changing the same setting (e.g., Host header); it modifies the Host header automatically and adjusts SSL/TLS only for AWS S3 endpoints; it does NOT configure caching or URL rewrites (add a Cache Rule and a URL Rewrite Rule). Bucket must be publicly accessible. — [Cloud Connector](https://developers.cloudflare.com/rules/cloud-connector/) (updated Aug 18, 2026)
- Providers: Cloudflare R2, Amazon S3, Google Cloud Storage, Microsoft Azure Blob Storage, Oracle Cloud Object Storage (OCI support added Aug 13, 2026, public buckets only via the S3 Compatibility API). For R2 the bucket must be public and exposed through a custom domain that lives in the same zone as the rule; `r2.dev` buckets are not supported. — [Supported providers](https://developers.cloudflare.com/rules/cloud-connector/providers/), [OCI support](https://developers.cloudflare.com/changelog/post/2026-08-13-oci-object-storage-cloud-connector/)
- Idea: serve `/files/*` or `assets.example.com` straight from a public R2 bucket through the proxied domain with no Worker.

**Cloudflare Trace** — BETA-FREE
- "Cloudflare Trace (Beta)", available on all plans; simulates an HTTP/S request through Cloudflare to the origin and shows which rules, caching and security settings would apply; works even for non-proxied hostnames; only Administrator or Super Administrator roles. Not supported: hostnames using Data Localization Suite, Spectrum apps; does not show legacy Firewall rules, Load Balancing, IP Access rules, old rate limiting, old WAF managed rules, content security rules. Docs contrast it with Log Explorer (Trace = what-if simulation, Log Explorer = real historical traffic). — [Trace](https://developers.cloudflare.com/rules/trace-request/) (updated Aug 25, 2026), [Trace limitations](https://developers.cloudflare.com/rules/trace-request/limitations/)
- Idea: test every redirect/cache/transform rule against sample URLs before shipping.

**Regex vs wildcard on Free**
- The `matches` (regex) operator "requires a Cloudflare Business or Enterprise plan"; the `wildcard`/`strict wildcard` operators are documented without a plan restriction. WAF custom rules on Free: 5 rules, regex No (Pro 20, Business 100, Enterprise 1,000). — [Operators](https://developers.cloudflare.com/ruleset-engine/rules-language/operators/), [WAF custom rules](https://developers.cloudflare.com/waf/custom-rules/) (WAF is the security researcher's scope)

**Recent Rules-language additions (2025-2026; plan gating not checked)**: concat() now takes up to 32 arguments (16 before; Sep 22, 2026), coalesce() (Oct 1, 2026), trim functions (Oct 14, 2026), hash_in_range() GA for HTTP products (Oct 2, 2026), dynamic-value comparisons (Oct 1, 2026), array/map functions (Jan 20, 2026), sha256()/encode_base64() (Jan 22, 2026), failed-detections field (Oct 9, 2026). — [Rules changelog feed](https://developers.cloudflare.com/changelog/rss/rules.xml), [Birthday Week 2026 pledge update, concat limit](https://blog.cloudflare.com/enterprise-for-all-update/) (blog, summarized)

### Inferences
- Total Free budget per proxied zone = 10 Cache + 10 Configuration + 10 Origin + 10 Single Redirect + 10 Compression + 10 Transform (whether this is 10 combined or 10 per type is not stated) + 3 Page Rules + 10 Cloud Connector, plus account-wide 15 Bulk Redirect rules / 5 lists / 10,000 URLs and 1 custom IP list of 10,000 items shared by all zones.
- Nothing in this group is metered: no Free-plan Rules product carries overage billing, so the only "cost" of exceeding is needing a paid zone plan (Pro 25 / Business 50 / Enterprise 300).
- Because Host header override is Enterprise-only, Snippets are paid-only and regex is Business+, any hostname rewriting, custom edge logic or regex routing on a Free zone has to move into a Worker (free tier) or the app itself.
- The 2025-02-12 limit increase and 2026 additions mean any pre-2025 Free numbers (Bulk Redirects 20 URLs, Cloud Connector 5) are superseded (see section 7).

### Gaps
- Whether the Free "10 Active Transform Rules" is a combined cap or per type (URL Rewrite / Request Header / Response Header): the docs show one figure; the safe assumption for the guide is 10 combined.
- Exact error text and behavior when a quota is exceeded is not documented on any of these pages.
- Plan availability of the newest Rules-language functions and of the "Markdown for Agents" configuration setting was not checked.
- No concrete Page Rules sunset or automatic-migration date is published (page still says "late 2025 or beyond").

## 2. Cloudflare for SaaS (custom hostnames) on the Free plan

### Takeaway
Cloudflare for SaaS works on a Free-plan zone: 100 custom hostnames are included, then $0.10 per additional hostname up to 50,000 (above that, contact sales). Enabling it on a non-Enterprise zone requires entering payment information. Free includes custom analytics, custom origin server per hostname (added to Free in May 2025), a fallback origin and automatically issued DV certificates; custom certificates, CSR, selectable CA, wildcard hostnames, mTLS, SNI rewrite, apex proxying/BYOIP and custom metadata are Enterprise-only or Enterprise add-ons. A Worker can serve as the fallback origin for multi-tenant apps.

### Cited Findings
- Plans table (updated Aug 14, 2026): Availability Free Yes, Pro Yes, Business Yes, Enterprise contact account team; Hostnames included 100 / 100 / 100 / custom; Max hostnames 50,000 / 50,000 / 50,000 / unlimited (contact sales above 50,000); Price per additional hostname $0.10 / $0.10 / $0.10 / custom. Label: free allowance + overage. — [Cloudflare for SaaS plans](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/plans/)
- Free column of the feature matrix: Custom analytics Yes; Custom origin Yes; SNI Rewrite for Custom Origin No; Custom certificates No; CSR support No; Selectable CA No; Wildcard custom hostnames No; Non-SNI support for SaaS zone No (Pro/Business/Enterprise Yes); mTLS support No; WAF for SaaS = "WAF rules with current zone plan"; Apex proxying/BYOIP No (Enterprise paid add-on); Custom metadata No (Enterprise paid add-on). — [plans page](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/plans/)
- Prerequisite to enable (page updated Apr 29, 2026): dashboard SSL/TLS > Custom Hostnames > Enable; for non-Enterprise zones "Enter payment information" (Enterprise can instead preview as a non-contract service with no metered fees). Billing in general: Cloudflare charges the primary payment method on file at the end of each 30-day (monthly) billing period for usage-based charges; failed payments trigger a retry process. — [Enable](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/enable/), [How billing works](https://developers.cloudflare.com/billing/understand/how-billing-works/)
- The SaaS zone itself can be on a Free plan ("Add your zone to Cloudflare on a Free plan"), then enable Cloudflare for SaaS. Fallback origin: create a proxied A/AAAA/CNAME record, designate it as the fallback origin (status must show Active; changing it later is non-disruptive); optional proxied CNAME target such as `customers.<saas>.com` (a wildcard like `*.customers.saasprovider.com` works). Do not create a custom hostname equal to the zone name. — [Configuring Cloudflare for SaaS](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/) (updated Jun 19, 2026)
- Certificate issuance: choose a certificate validation method (automatic HTTP, TXT, or Delegated DCV) and a hostname validation method (pre-validation or real-time); the customer then CNAMEs to your target; the hostname is production-ready when `result.status` and `result.ssl.status` are both `active` and DNS points at the SaaS target. Cloudflare issues two certificates per hostname (primary P-256 ECDSA, fallback RSA 2048); only Enterprise can set `certificate_authority`, upload a custom certificate, or enable wildcard; empty CA means "default CA" with a CAA check; minimum TLS version defaults to the zone's. Customers who need an A record (not CNAME) need Apex proxying (Enterprise add-on). — [Configuring Cloudflare for SaaS](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/)
- Custom origin server: send specific custom hostnames to different origins instead of the fallback (each origin must be a hostname with a proxied A/AAAA/CNAME record, no IP addresses, no wildcard DNS record); for Azure/AWS/GCP endpoints use an Origin Rule to fix the Host header if needed. It was Enterprise-only until May 27, 2025, when it became available on Free, Pro and Business. — [Custom origin server](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/custom-origin/), [changelog 2025-05-27](https://developers.cloudflare.com/changelog/post/2025-05-19-paygo-updates/)
- Workers with custom hostnames (multi-tenant): use a Worker as the fallback origin: give the fallback origin an originless DNS record (example `service.example.com AAAA 100::`) and add a Worker route `*/*` on the SaaS zone, which also captures traffic from custom hostnames; with a Worker route matching, the per-hostname `custom_origin_server` setting is bypassed, so route per tenant inside the Worker using the Host header or `request.cf.hostMetadata` (custom metadata, an Enterprise add-on). Page updated Jun 19, 2026. — [Workers as your fallback origin](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/worker-as-origin/) (retrieved via docs search)
- Workers platform limits relevant to this pattern: Workers Free 100 Workers per account; 1,000 routes per zone; 100 custom domains per zone (use a wildcard route if more are needed). — [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) (retrieved via docs search; Workers is another researcher's scope)
- Not compatible: custom hostnames behind another CDN (hostname validation fails); customers already on Cloudflare cannot control Argo, Early Hints, Client-side security, Spectrum or wildcard DNS for hostnames managed by your Custom Hostnames config. Multiple SaaS providers can hold the same domain's custom hostname simultaneously (traffic follows the customer's CNAME target). — [Cloudflare for SaaS overview](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/), [Hostname validation](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/domain-support/hostname-validation/) (retrieved via docs search)
- Alert available: "SSL for SaaS Custom Hostnames Alert" (listed as included with a Cloudflare for SaaS purchase). — [Available alerts](https://developers.cloudflare.com/notifications/notification-available/)
- GA status: not labelled beta anywhere on the SaaS pages (treat as GA). Reset period: the 100 included hostnames are a standing allowance (no reset); the $0.10 overage rate is billed on the normal monthly cycle (period for the SaaS line item is not stated on the plans page).

### Inferences
- A multi-tenant app on a Free SaaS zone can onboard up to 100 customer vanity domains with no hostname charge, but a payment method must be on file to enable the product; hostnames 101 to 50,000 would cost $0.10 each (about $5 per extra 50 hostnames).
- Wildcard custom hostnames are Enterprise-only, so each tenant host (www.tenant.com, tenant.com) is a separate custom hostname and counts separately against the 100.
- The `*/*` Worker route pattern is the practical multi-tenant router on Free, since custom metadata (per-hostname JSON) is an Enterprise add-on.

### Gaps
- Exact billing cadence for hostnames over 100 (monthly vs other) and what happens to a Free zone with no valid payment method after enabling are not stated on the pages read.
- Whether the 100 included hostnames are measured per zone or per account was not found.

## 3. Custom error and challenge pages on Free

### Takeaway
On Free you cannot customize any Cloudflare-generated error, challenge or WAF block page: Custom Errors (Error Pages, Custom Error Rules, custom error assets) are "available to all paid plans" with 0 on Free, and the WAF "custom response for blocked requests" is "only available on Pro plans and above". The Free workaround is to serve branded pages from the origin, Pages or a Worker, and to rely on Cloudflare's default pages (which can be returned as HTML, JSON or Markdown depending on the client's request).

### Cited Findings
- Custom Errors availability (updated Sep 8, 2026): Free No / 0 rules / 0 assets / Error Pages No; Pro Yes 25 rules / 25 assets / Error Pages Yes / Origin Error Pages No; Business 50 / 50 / Yes / No; Enterprise 300 / 300 / Yes / Yes. Label: PAID-ONLY. — [Custom Errors](https://developers.cloudflare.com/rules/custom-errors/)
- "To customize a challenge page or the default Cloudflare WAF block page, use an Error Page" (paid); Error Pages exist at zone level and (paid) account level, zone wins; a Custom Error Rule (status 400 and above; inline response or stored asset; keeps upstream headers except Content-Type and Content-Length) overrides Error Pages for 500-class and 1000-class errors; Error Pages do not apply to 500, 501, 503, 505; assets must stay under about 1.5 MB after inlining; requires proxied DNS. — [Custom Errors](https://developers.cloudflare.com/rules/custom-errors/)
- Precedence: a custom response configured in a WAF rule's Block action beats both Error Pages and Custom Error Rules; with nothing configured Cloudflare serves its default page in the client's requested format (HTML, JSON or Markdown). — [Custom Errors](https://developers.cloudflare.com/rules/custom-errors/)
- WAF custom response for Block (HTML/text/JSON/XML body up to 2 KB, status 400-499) is "only available on Pro plans and above"; same note on rate limiting rules (body up to 30 KB). Free therefore has no custom block response either. — [Create a custom rule](https://developers.cloudflare.com/waf/custom-rules/create-dashboard/), [Rate limiting rules](https://developers.cloudflare.com/waf/rate-limiting-rules/create-zone-dashboard/) (retrieved via docs search; WAF is the security researcher's scope)
- GA history: Custom Errors beta (stored assets, account-level rules) Feb 11, 2025; GA Apr 24, 2025 ("available on all paid plans"); Error Pages is the new name for "Custom Pages"; Pro limits went from 5 to 25 on Feb 12, 2025. — [Custom Errors GA](https://developers.cloudflare.com/changelog/post/2025-04-24-custom-errors-ga/), [Rules limits increase](https://developers.cloudflare.com/changelog/post/2025-02-12-rules-upgraded-limits/)
- What Free does have: Response Header Transform Rules (available on Free, part of the 10 Active Transform Rules) can change response headers, but they change headers only and cannot replace an error page body. — [Response Header Transform Rules](https://developers.cloudflare.com/rules/transform/response-header-modification/), [Transform Rules](https://developers.cloudflare.com/rules/transform/)

### Inferences
- A branded 404/maintenance/offline page on Free has to come from the application stack; Cloudflare-generated 52x/1xxx/challenge/WAF-block pages remain Cloudflare-branded until a zone is upgraded to Pro.

### Gaps
- Legacy "Custom Pages" docs were not separately checked for Free (current docs fold them into Error Pages, which are paid-only).

## 4. Logs, analytics APIs and notifications on Free

### Takeaway
Free gets: the GraphQL Analytics API (300 queries per 5 minutes per user; adaptive datasets retained at least 31 days on every plan since Oct 2, 2026), Logpush (newly available on Free since Sep 30, 2026 with 25 GB/month internal + 25 GB/month external exports and 1 GB/month transforms included per account, then metered; max 4 jobs per zone), Audit Logs (all plans, 18 months), custom dashboards, sampled HTTP-request analytics in the new Logs UI, and email/webhook alerts for the "All plans" alert types. Paid-only: Instant Logs (Business+), Logpull (Enterprise), Log Explorer unsampled datasets ($1/GB add-on), PagerDuty (Business+), WAF security-event alerts (Business+).

### Cited Findings
**GraphQL Analytics API** — FREE-FOREVER
- Single endpoint `https://api.cloudflare.com/client/v4/graphql` (POST); 70+ datasets. Limits (page updated Oct 2, 2026): up to 10 zones per zone-scoped query, 1 account per account-scoped query; user quota 300 GraphQL queries per 5-minute window (about 1 per second, or burst 300 then wait 5 minutes); per-dataset node limits (how far back, max range, max fields, max records); optional account-based rate limiting. Adaptive datasets (`httpRequestsAdaptiveGroups`, `firewallEventsAdaptive`) retain at least 31 days on every plan; aggregated datasets (e.g., `httpRequests1hGroups`) keep their own per-plan limits; exact Free boundaries per zone come from the `settings` discovery node (`enabled`, `availableFields`, `maxPageSize`, `notOlderThan`, `maxDuration`). — [GraphQL limits](https://developers.cloudflare.com/analytics/graphql-api/limits/), [Settings node](https://developers.cloudflare.com/analytics/graphql-api/features/discovery/settings/)

**Logpush** — free allowance + overage (new)

- Idea: pipe account audit logs to R2 via Logpush for a change-history trail on the production account.

**Notifications (Alerts)** — FREE-FOREVER (email/webhook) with paid-only parts
- Delivery methods (updated Oct 2, 2026): Email (all plans); Webhooks (all plans; accounts without a paid zone can configure up to 100 webhook destinations); PagerDuty (Business and higher); connected services including coding agents. — [Alerts](https://developers.cloudflare.com/notifications/), [webhook note](https://developers.cloudflare.com/images/storage/upload-images/configure-webhooks/)

- Idea: route HTTP DDoS, Universal SSL, Pages and Cloudflare Status alerts to a webhook into the team's Slack/Discord, free on every plan.

### Inferences
- A Free-plan site gets 30+ days of aggregate analytics via GraphQL and can ship raw HTTP request logs through Logpush within a 25 GB/month allowance, so it only loses live tailing (Instant Logs) and unsampled search (Log Explorer) compared with paid plans.

## 6. Domains: Cloudflare Registrar, free hostnames, proxied-zone-only features

### Takeaway
Cloudflare Registrar is available on all plans and sells domains at cost (registry plus ICANN fee, no markup) with free WHOIS redaction, auto-renew on by default and free one-click DNSSEC; no free domain exists, only occasional first-year discounts (Birthday Week 2026: .io, .dev, .app, .tech). Free Cloudflare-provided hostnames that need no purchase are workers.dev, pages.dev, r2.dev (non-production) and trycloudflare.com (temporary, accountless). All Rules products, custom errors, Cloudflare for SaaS and WAF/caching on R2 need a proxied zone on a domain you own.

### Cited Findings
**Registrar (at-cost)**
- "Available on all plans"; buy and renew at cost with no markup; WHOIS redacted by default; auto-renew by default at the registry list price; free one-click DNSSEC. Page updated Apr 24, 2026. — [Cloudflare Registrar](https://developers.cloudflare.com/registrar/)
- Free elements: WHOIS (and RDAP) personal-data redaction at no cost where the registry allows (state/province and country still show); DNSSEC free; domain lock on by default; Registrar is not subscription-based. Paid/Enterprise: Custom Domain Protection (registry lock and out-of-band verification) is Enterprise-only. — [WHOIS redaction](https://developers.cloudflare.com/registrar/account-options/whois-redaction/), [Registrar product page](https://www.cloudflare.com/products/registrar/) (fetched summary), [FAQ](https://developers.cloudflare.com/registrar/faq/)
- Pricing: "always at or below what registries and ICANN charge us"; search and a new pricing page show first-year and renewal price; Birthday Week 2026 first-year discounts on select extensions (.io, .dev, .app, .tech); no free domains or credits are mentioned; refunds are not given (fees pass straight to the registry). — [Simplifying domains for people and agents](https://blog.cloudflare.com/simplifying-domains/) (blog, summarized, Sep 30, 2026), [FAQ](https://developers.cloudflare.com/registrar/faq/)
- Supported TLDs: docs say "over 400" (updated May 15, 2026), the Sep 30, 2026 blog says "420+ extensions", the product-page FAQ says "over 430" (a 2025 changelog said 300+); IDNs (unicode) are not supported; most TLDs register for a maximum of 10 years; `.us` has extra requirements. — [Top Level Domains supported](https://developers.cloudflare.com/registrar/top-level-domains/), [Register a new domain](https://developers.cloudflare.com/registrar/get-started/register-domain/), [.ai and .shop added](https://developers.cloudflare.com/changelog/post/2025-03-27-ai-domains-available/)

- Renewals: auto-renew attempted about 30 days before expiry with three retries; disable via the Auto-renew toggle at least 30 days before expiration; expired domains have a grace period then redemption (restore fee may apply). — [FAQ](https://developers.cloudflare.com/registrar/faq/), [Renew domains](https://developers.cloudflare.com/registrar/account-options/renew-domains/)
- Transfers in: domain must be active on Cloudflare full DNS setup, older than 60 days with no transfer in the last 60 days and no registrant change in 60 days, DNSSEC disabled at the old registrar first; costs one extra year at cost (no transfer fee and no extra year for .uk and .nz); up to 10 days; wait 45 days after a renewal to avoid paying for a year the registry won't add. Transfers out follow ICANN 60-day rules with an auth code from Manage Domains. — [Transfer a domain to Cloudflare](https://developers.cloudflare.com/registrar/get-started/transfer-domain-to-cloudflare/), [Transfer out](https://developers.cloudflare.com/registrar/account-options/transfer-out-from-cloudflare/), [FAQ](https://developers.cloudflare.com/registrar/faq/)

Changelog post dated Apr 15, 2025 (its URL slug reads 2026-04-15); docs updated Sep 16, 2026. — [Registrar API guide](https://developers.cloudflare.com/registrar/registrar-api/), [Registrar API beta](https://developers.cloudflare.com/changelog/post/2026-04-15-registrar-api-beta/), [Simplifying domains](https://blog.cloudflare.com/simplifying-domains/) (blog, summarized)
- Is there a free domain from Cloudflare? No evidence found: product page makes no free-domain claim and the at-cost model means you pay registry plus ICANN fees; the only price break found is first-year discounts on select TLDs. — [Registrar product page](https://www.cloudflare.com/products/registrar/) (fetched summary), [Simplifying domains](https://blog.cloudflare.com/simplifying-domains/) (blog, summarized)

- `trycloudflare.com` (Quick Tunnels): temporary URL for a local service via `cloudflared tunnel --url ...`, no Cloudflare account or domain needed, for testing/development only, disappears when `cloudflared` stops; since Oct 2, 2026 `--allowed-mail` restricts access by email one-time PIN. — [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) (updated Sep 30, 2026), [Protected Quick Tunnels](https://developers.cloudflare.com/changelog/post/2026-10-02-protected-quick-tunnels/)

**Free features that only work on a proxied zone on your own domain (not on workers.dev, pages.dev, r2.dev)**
- Explicit "requires proxied DNS records" statements: Rules overview (all Rules features), Cache Rules, Configuration Rules, Origin Rules, Transform Rules, Single and Bulk Redirects, Compression Rules, URL normalization, Cloud Connector, Custom Errors, Page Rules. — [Rules overview](https://developers.cloudflare.com/rules/), [Cache Rules](https://developers.cloudflare.com/cache/how-to/cache-rules/), [Configuration Rules](https://developers.cloudflare.com/rules/configuration-rules/), [Origin Rules](https://developers.cloudflare.com/rules/origin-rules/), [Transform Rules](https://developers.cloudflare.com/rules/transform/), [Redirects](https://developers.cloudflare.com/rules/url-forwarding/), [Compression Rules](https://developers.cloudflare.com/rules/compression-rules/), [URL normalization](https://developers.cloudflare.com/rules/normalization/), [Cloud Connector](https://developers.cloudflare.com/rules/cloud-connector/), [Custom Errors](https://developers.cloudflare.com/rules/custom-errors/), [Page Rules](https://developers.cloudflare.com/rules/page-rules/)
- Cloudflare for SaaS needs a zone on Cloudflare (the SaaS zone, which can be Free) plus payment info. — [Configuring Cloudflare for SaaS](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/), [Enable](https://developers.cloudflare.com/cloudflare-for-platforms/cloudflare-for-saas/start/enable/)
- Zone-scoped logs and analytics (Logpush HTTP requests per zone, GraphQL zone datasets) are per zone; Registrar domains are automatically zones on Cloudflare DNS. — [Logpush](https://developers.cloudflare.com/logs/logpush/), [Register a new domain](https://developers.cloudflare.com/registrar/get-started/register-domain/)
- Works without a proxied zone: Trace (simulates unproxied hostnames), Workers on workers.dev, Pages on pages.dev, Quick Tunnels, Dashboard SSO, Audit Logs, alerts, API/Terraform. — [Trace](https://developers.cloudflare.com/rules/trace-request/), [workers.dev](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/), [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

### Inferences
- The lowest-cost path to use "every Rules product" is to register (or move) one real domain, keep at least one proxied DNS record per hostname, and accept the registry's at-cost yearly fee (the only unavoidable cash cost in this scope; no per-TLD price was retrievable).
- Using workers.dev/pages.dev alone means none of the Rules, Custom Errors, Cloud Connector or WAF-on-R2 features can be exercised.

### Gaps
- Per-TLD at-cost prices (e.g., .com yearly) were not retrievable: the Registrar product page gives no figures and domains.cloudflare.com and the learning page returned HTTP 403.
- Exact TLD count varies by source (400+, 420+, 430+); the authoritative list is cloudflare.com/tld-policies (not fetched).

## 7. Other free zone/account platform features, 2025-2026 launches and superseded limits

### Takeaway
2025-2026 moved many formerly Enterprise-only items down to Free: Logpush (Sep 30, 2026), dashboard SSO (Sep 25, 2025), SaaS custom origin server (May 27, 2025), 30-day analytics retention (Oct 2, 2026), Custom Dashboards (Apr 22, 2026), Terraform/RBAC messaging, Free multi-account creation (Aug-Sep 2026), plus a new Free tier for logs/traces observability (0.5 GB/day from Dec 1, 2026).
