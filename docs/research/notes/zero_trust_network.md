# Cloudflare Zero Trust (Cloudflare One) Free plan, Tunnel, Mesh, WARP / 1.1.1.1, Spectrum and related free network services (state as of 2026-10-14)

> FINAL (research complete). Method: Cloudflare developer docs (most pages stamped "Last updated" Apr to Oct 2026), Cloudflare product pages, Cloudflare blog and changelog. Pages were read through a summarizing fetch tool plus the Cloudflare docs search tool (raw chunks); where a number rests only on a fetch-tool summary or a search-result summary, the bullet says so.
> Label legend: [FREE-FOREVER] free-forever allowance (no end date stated); [FREE-BETA] free during beta; [TRIAL] trial/credits; [PAID-ONLY] no free tier.
> Naming changes to know (2026): "WARP client" is now "Cloudflare One Client"; "WARP Connector" is now "Cloudflare Mesh" node; Magic WAN is "Cloudflare WAN", Magic Firewall is "Cloudflare Network Firewall", Magic Network Monitoring is "Network Flow"; docs tiers are called Free / Standard (pay-as-you-go) / Enterprise. Dashboard nav changed 2025-11-17 and again 2026-10-12 ("Traffic policies" is now "Traffic controls"). See section 5 for the dated change list.
> Scope guard: Email Security, WAF/app security, developer-platform products and free programs are other researchers' areas; they appear only as one-line cross-references.

## 1. Zero Trust Free plan: seat limit, payment method, and what each product includes on Free (plus the paid boundary)

### Takeaway
The Free plan is real and still "forever": $0, a 50-user cap, 24-hour logs and community support, but Cloudflare's own onboarding docs say you must still enter payment details (you are not charged). Access, Gateway (DNS/network/HTTP), the Cloudflare One Client, DEX, Tunnel and Mesh work on Free; Browser Isolation, File sandboxing, full DLP, Access mTLS, egress/dedicated IPs, resolver/internal DNS, Zero Trust Logpush and the WAN/Magic family are paid or Enterprise.

### Cited Findings

#### Plan model, price, seat cap
- Free plan is listed at "$0" and "forever", "Best for teams under 50 users or enterprise proof-of-concept tests"; the capabilities row "Usage" shows "50 user limit" for Free versus "No user limit" for Pay-as-you-go and Enterprise. — [Cloudflare Access product page](https://www.cloudflare.com/sase/products/access/)
- Pay-as-you-go is "$7" per user/month (paid annually), described as best for teams over 50 users; Enterprise ("Contract Plan") is custom priced. — [Cloudflare Access product page](https://www.cloudflare.com/sase/products/access/)
- The Free plan originated with the Oct 2020 Cloudflare for Teams launch: the post "Zero Trust For Everyone" (structured-data date 2020-10-13) says the Free plan "protects up to 50 users at no cost", with "up to 50 seats of Access and Gateway" and DNS filtering for multiple network locations (standalone Gateway was then priced at $5 per user). — [Cloudflare blog: Zero Trust For Everyone](https://blog.cloudflare.com/teams-plans/)
- A second Cloudflare blog page (structured-data date 2020-10-15; the URL slug suggests a later small-business post, so its true date is uncertain) says up to 50 seats of Access are free, Access for SaaS is included in the Free plan for up to 50 users, and that WARP required buying a paid Gateway/Teams Standard plan; the WARP claim is SUPERSEDED by current docs listing the Cloudflare One Client under "All plans". — [Cloudflare blog: small business setup](https://blog.cloudflare.com/zero-trust-week-setting-up-cloudflare-one-as-a-small-business/)
- Docs landing page: Cloudflare One is "Available on all plans"; "Cloudflare Zero Trust offers both Free and Paid plans. Access to certain features depends on a customer's plan type"; limits "may be increased on Enterprise accounts". — [Cloudflare One docs](https://developers.cloudflare.com/cloudflare-one/)
- The public plans page https://www.cloudflare.com/plans/zero-trust-services/ is JavaScript-rendered; the fetch tool only saw "Start a proof of concept with our free plan today" and "Contact us ... SASE packaging". The Access product page above is the readable first-party source for the plan table. — [Plans page](https://www.cloudflare.com/plans/zero-trust-services/)

#### Payment method
- Onboarding: create a Cloudflare account (enable 2FA), select Zero Trust, choose a team name (becomes the App Launcher subdomain; max 63 chars), then the docs say to complete onboarding by selecting a subscription plan and entering payment details; "If you chose the Zero Trust Free plan, this step is still needed but you will not be charged." (verified verbatim from a raw docs chunk). — [Get started](https://developers.cloudflare.com/cloudflare-one/setup/)
- Cloudflare automatically adds the Cloudflare identity provider as the default login method; a one-time PIN or third-party IdP can be added at any time. — [Get started](https://developers.cloudflare.com/cloudflare-one/setup/)
- Conflicting third-party claim: comparison sites say no credit card is needed on Free; they do not cite Cloudflare and the Cloudflare docs above say otherwise. — [CostBench free-plan page (third-party)](https://costbench.com/software/business-vpn/cloudflare-zero-trust/free-plan/)
- A Zero Trust organization with an active subscription (Free counts) is a prerequisite for Mesh. — [Mesh get started](https://developers.cloudflare.com/mesh/get-started/)

#### Seats and what happens at the cap
- A seat is consumed by an active user after an Access authentication event (App Launcher or an app) or when a device associated with the user connects to Cloudflare One; one seat per user no matter how many apps. When all seats are consumed, "additional users who attempt to log in are blocked" (blocked, not auto-billed, per the seat doc). — [Seat management](https://developers.cloudflare.com/cloudflare-one/team-and-resources/users/seat-management/)
- "Remove" frees a seat (user shows Inactive; re-authenticating consumes a seat again); "Revoke" ends sessions but does not free it; optional auto-removal of inactive users after a 1-month to 1-year window (checked daily); "Inactive users do not count towards billing"; service tokens reach apps without consuming seats; user records cannot be deleted or archived. — [Seat management](https://developers.cloudflare.com/cloudflare-one/team-and-resources/users/seat-management/)
- Plan changes: change or cancel at any time; downgrades apply next billing cycle; upgrades bill immediately. — [Getting started FAQ](https://developers.cloudflare.com/cloudflare-one/faq/getting-started-faq/)

#### Support, SLA, logs by plan
- Free: support is "Community forums and Discord server"; no uptime/SLA row shown for Free; Pay-as-you-go has chat and ticket support and a "100% uptime guarantee (SLA)"; Enterprise adds phone support and professional services. — [Cloudflare Access product page](https://www.cloudflare.com/sase/products/access/)
- Log retention (docs table, updated 2026-04-17): Free = Access 24 hours, DNS 24 hours, Network 24 hours, HTTP 24 hours, DEX logs 7 days, device posture 30 days, admin logs 18 months. Standard = 30 days for Access/DNS/network/HTTP. Enterprise = 180 days Access and DNS, 30 days network/HTTP. Footnote: Enterprise per-query plans cannot store DNS logs at Cloudflare but can export via Logpush. The table also has "Access" and "Gateway" columns (apparently single-product subscriptions) that the page does not define. — [Zero Trust logs](https://developers.cloudflare.com/cloudflare-one/insights/logs/)
- Product page agrees: Free "up to 24 hours", Pay-as-you-go "up to 30 days", Enterprise "Up to 6 months; Logpush to SIEM/cloud storage". — [Cloudflare Access product page](https://www.cloudflare.com/sase/products/access/)
- Zero Trust Logpush export carries an "Enterprise-only" label (page updated 2026-04-29). General Logpush became available to Free, Pro and Business customers on 2026-10-02 (self-serve, pay-as-you-go), but that post does not mention Zero Trust datasets. — [ZT Logpush](https://developers.cloudflare.com/cloudflare-one/insights/logs/logpush/); [Pledge update blog](https://blog.cloudflare.com/enterprise-for-all-update/); [Logpush docs](https://developers.cloudflare.com/logs/logpush/)

#### Account limits (docs page is not split by plan except DEX; "may be increased on Enterprise") — [Account limits](https://developers.cloudflare.com/cloudflare-one/account-limits/)
- Access: 500 applications; 50 service tokens; 50 identity providers; 500 reusable policies; 300 rule groups (1,000 rules each); 1,000 rules per application; 1,000 emails or IPs per rule; 50 domains per application; 5,000 infrastructure targets; 5 audit Logpush jobs; 50 mTLS root certs; MCP portals 20 (80 servers per portal, 5 custom domains per portal, 24 h session inactivity timeout).
- Gateway: 500 each of DNS, network, HTTP, egress and resolver policies; 250 DNS locations (1,500 source CIDRs each); 100 lists (1,000 entries each for Standard users, 5,000 Enterprise); PAC files and proxy endpoints 50 (Standard) vs 1,000/500 (Enterprise); 5 DNS and 5 HTTP Logpush jobs; 256 concurrent HTTP/2 streams.
- Gateway certificates: 10 active, 3 generated per day, 5 custom. Cloudflare One Client: 1,000 combined Split Tunnel + Local Domain Fallback entries per device profile, 30 Device IP profiles. DEX: Free 10 tests and 100 remote captures per day (Standard 30/200, Enterprise 50/800). Tunnel/Mesh limits are in section 2.
- Plan-specific Free cap on locations: the product page row "Network-level policies for physical locations" says Free up to 3, Pay-as-you-go up to 50, Enterprise up to 250, so the docs figure of 250 DNS locations is the Enterprise ceiling, not the Free allowance. — [Cloudflare Access product page](https://www.cloudflare.com/sase/products/access/)

#### Per-product records (Free plan)
- **Access: self-hosted (public) applications + policies** [FREE-FOREVER within the 50-seat cap], GA. Allowance: limits above (500 apps etc.); exceeding seats blocks new logins; other limit-exceeded behavior not documented. Prereqs: Zero Trust org (card on file at onboarding), "An active domain on Cloudflare" on full or partial (CNAME) setup, and an origin (typically a Tunnel); apps are deny-by-default and need an Allow policy. Paid parts: mTLS, Logpush, longer logs. Idea: gate an admin panel or staging site with Google/GitHub/one-time-PIN login. — [Self-hosted public app](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/); [Seat management](https://developers.cloudflare.com/cloudflare-one/team-and-resources/users/seat-management/)
- **Access: identity providers** [FREE-FOREVER]. Docs list Cloudflare IdP (default), one-time PIN (email code to approved addresses), generic OIDC, generic SAML and named providers such as Microsoft Entra ID; the page says Cloudflare "can integrate with the majority of OAuth providers" and sets no IdP limit (account-limits says 50). It does not name GitHub or Google (use the dashboard provider list or generic OIDC). New orgs default to the Cloudflare IdP instead of one-time PIN (changelog entries dated 2026-05-19 and 2026-06-18; existing orgs unchanged); an Authentik IdP was added 2026-03-17. — [Identity providers](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/); [Pledge update blog](https://blog.cloudflare.com/enterprise-for-all-update/)
- **Access: service tokens** [FREE-FOREVER]. 50 per account, expire per the duration chosen at creation, no seat consumed; "Strict service token authentication" shipped 2026-10-02 (default on for new orgs) and automatic cleanup of inactive tokens 2026-09-22. Free's substitute for mTLS. Idea: machine-to-machine calls to an Access-protected API. — [Service tokens](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/); [Account limits](https://developers.cloudflare.com/cloudflare-one/account-limits/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)
- **Access: mTLS** [PAID-ONLY for Free]: "available with Enterprise and pay-as-you-go Zero Trust plans. It is not included in the Free plan." — [Access mTLS](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/mutual-tls-authentication/)
- **Access: SaaS apps, App Launcher, clientless access, browser-based SSH/VNC, device-posture integration, Terraform, split tunneling** appear in the Access feature table with no per-plan restriction shown in the page text; individual docs pages for browser-rendered SSH/VNC/RDP, infrastructure (SSH) access and posture checks carry no plan restriction either. Browser-based RDP went GA for all customers 2025-09-22; file-transfer controls for browser RDP (beta) are on all Zero Trust plans (2026-07-07); private-hostname apps on all ports are GA across all plans (2025-10-28); Access Analytics dashboard for all Cloudflare One customers (2025-05-16). Infrastructure (SSH) access needs cloudflared or Mesh plus the Cloudflare One Client in Traffic and DNS mode; limit 5,000 targets. Browser rendering works only for self-hosted public apps and Allow/Block policies. — [Cloudflare Access product page](https://www.cloudflare.com/sase/products/access/); [Browser rendering](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/browser-rendering/); [Infrastructure apps](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/); [Posture checks](https://developers.cloudflare.com/cloudflare-one/reusable-components/posture-checks/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)
- **Access: MCP server portals / AI controls** [FREE-FOREVER, GA]. Open beta for all customers on all plans from 2025-08-26; GA 2026-09-24. A portal merges up to 80 remote HTTP MCP servers behind one endpoint; prereqs: an active domain on Cloudflare and a configured IdP; portal-log Logpush is Enterprise-only. — [MCP portals](https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)
- **Access on Workers**: one-click Access for workers.dev and preview URLs (Oct 2025) and "enable Access on a Worker or all Workers" (2026-08-14); plan not stated in those entries (developer-platform researcher covers Workers). — [Workers Access changelog](https://developers.cloudflare.com/changelog/product/workers/6/); [2026-08-14 entry text](https://developers.cloudflare.com/changelog/product-group/cloudflare-one/3/)
- **Gateway: DNS filtering** [FREE-FOREVER]. Locations accept IPv4, IPv6, DoH and DoT endpoints (each location gets a unique DoH hostname such as `<subdomain>.cloudflare-gateway.com/dns-query`); Free cap is 3 locations (product page); 24 h logs; UK NCSC PDNS threat feed usable on any plan; scheduled DNS policies in the UI for all Gateway customers (2025-10-20). Paid: resolver policies and Internal DNS (Enterprise), dedicated resolver IPs and BYOIP DNS (Enterprise). Idea: filter the team office/home network or browsers via DoH. — [Resolver endpoints](https://developers.cloudflare.com/cloudflare-one/traffic-controls/resolver-endpoints/); [Connectivity options](https://developers.cloudflare.com/cloudflare-one/networks/connectivity-options/); [Gateway changelog](https://developers.cloudflare.com/cloudflare-one/changelog/gateway/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)
- **Gateway: network (L4) and HTTP (L7) filtering, TLS decryption** [FREE-FOREVER]. Needs the Cloudflare One Client (or proxy endpoint) and, for HTTP policies, TLS decryption with a Cloudflare root cert on devices; HTTPS inspection defaults to ports 80/443 unless protocol detection "inspect on all ports" (beta) is on. Protocol detection became available on Free and Pay-as-you-go 2025-05-27; Gateway Authorization Proxy and hosted PAC files are GA for all plan types (2026-04-29). — [Gateway overview](https://developers.cloudflare.com/cloudflare-one/traffic-controls/); [TLS decryption](https://developers.cloudflare.com/cloudflare-one/traffic-controls/http-policies/tls-decryption/); [TLS inspection learning path (port 80/443 default, inspect-on-all-ports beta)](https://developers.cloudflare.com/learning-paths/secure-internet-traffic/build-http-policies/tls-inspection/); [Protocol detection changelog](https://developers.cloudflare.com/changelog/post/2025-05-27-Protocol-Detection-availability/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)

### Inferences
- Plan a guide around "card on file, $0 charged" for Free, and warn that a 51st active user is blocked (not billed); moving to Standard is $7/user/month and removes the cap.
- Free logs last 24 hours, so anything needing audit history (Access/Gateway forensics) must either upgrade or be exported by other means.
- "Standard" in the docs almost certainly means pay-as-you-go (the DEX table uses Free/Standard/Enterprise), but the docs never define it.
- Account-limits numbers are ceilings shared across plans; only DEX and the "locations" row are documented as lower for Free, so other Free ceilings could be lower than the table without being published.

### Gaps
- No first-party doc states an explicit Free ceiling for Access applications, Gateway policies, lists, tunnels or service tokens; the account-limits table is the only number source.
- Not confirmed on Free: Gateway AV scanning, and whether General Logpush for Zero Trust logs changed in Oct 2026 (ZT docs still say Enterprise-only as of 2026-04-29).
- Community threads about exceeding 50 seats and the Cloudflare One 2026 name-update post returned HTTP 403 to my fetcher; search-result summaries claimed community answers say Free cannot add seats beyond 50 and moving to Standard bills all 51 seats, but I could not verify them.
- I did not create an account, so the live signup flow (whether a card prompt can be skipped) is unverified.
- Log Explorer on the product page appears as "free for the first 10 GB then $1/GB/month" but the table text was garbled; observability researcher should confirm.

## 2. Cloudflare Tunnel (cloudflared), TryCloudflare / Quick Tunnels, private network routing, Mesh (ex WARP Connector)

### Takeaway
Named Cloudflare Tunnel is "Available on all plans" with no metered fee documented (1,000 tunnels, 25 replicas per tunnel, 1,000 routes), public hostnames require a domain on Cloudflare, and Quick Tunnels need no account or domain (dev only, now with free email-PIN protection since 2026-10-02). Cloudflare Mesh (renamed from WARP Connector) is free for 50 nodes and 50 users per the launch blog and is labeled beta in the docs.

### Cited Findings

#### Named Tunnel
- Tunnel [FREE-FOREVER]: connects infrastructure through an outbound-only, post-quantum encrypted connection; each tunnel keeps four long-lived connections to two Cloudflare data centers; run multiple cloudflared replicas for availability; the page says "Available on all plans" and states no pricing or usage limits. — [Tunnel docs](https://developers.cloudflare.com/tunnel/)
- Limits (account limits page): 1,000 cloudflared tunnels per account; 25 active replicas per tunnel; 1,000 routes (CIDR + hostname) per account shared with Mesh; 1,000 virtual networks. What happens beyond a limit is not documented. — [Account limits](https://developers.cloudflare.com/cloudflare-one/account-limits/)
- Prerequisites to publish a web app: a Cloudflare account, a domain on Cloudflare ("required to publish applications") and a server with Internet access to run cloudflared; the quick-start page mentions no Zero Trust org or payment method. Public hostnames create a proxied CNAME to `<UUID>.cfargotunnel.com` in the zone; full DNS setup is the best experience, partial (CNAME) setup is possible but partial setup zones need Business or Enterprise. — [Create a tunnel](https://developers.cloudflare.com/tunnel/get-started/); [Routing](https://developers.cloudflare.com/tunnel/concepts/routing/); [Tunnels FAQ](https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/); [Partial setup](https://developers.cloudflare.com/dns/zone-setups/partial-setup/setup/)
- Restriction that matters for a website: on Free, Pro and Business plans the service-specific terms "require you to use a specific paid service to serve video and other large files" over public hostname routes; this does not apply to private network routes. — [Tunnels FAQ](https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/)
- If cloudflared stops, DNS records remain and visitors see error 1016. — [Routing](https://developers.cloudflare.com/tunnel/concepts/routing/)
- Recent operational changes: cloudflared connectivity pre-checks at startup (2026-05-27); granular permissions for Tunnel and Mesh (2026-05-21); `cloudflared proxy-dns` removed from releases starting 2026-02-02; API list/get responses drop CIDR-encoded route endpoints and the `connections` field from 2026-10-05; cloudflared will deprecate 32-bit Windows and Intel macOS builds in 2027. — [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)

#### Quick Tunnels (TryCloudflare)
- Quick Tunnels [FREE-FOREVER, dev only]: creates a temporary `trycloudflare.com` URL for a local HTTP service; "You do not need a Cloudflare account or domain"; command `cloudflared tunnel --url http://localhost:8080`; URL changes every run and dies when cloudflared stops. Limits: no uptime guarantee; up to 200 in-flight requests per tunnel (extra requests get HTTP 429); Server-Sent Events not supported. — [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)
- Protected Quick Tunnels (new, 2026-10-02, cloudflared 2026.9.3 or later): add `--allowed-mail` (single address, repeated flag, comma list, or `'*@example.com'`); visitors get an emailed one-time PIN; neither side needs a Cloudflare account; sessions last up to four hours; list changes require restarting cloudflared; "Email protection for Quick Tunnels is free, like Quick Tunnels themselves." — [Blog: Protected Quick Tunnels](https://blog.cloudflare.com/protected-quick-tunnels/); [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

#### Private network routing and hostname routing
- Private CIDR and hostname routes connect users (running the Cloudflare One Client) to private apps through a tunnel. Hostname routing (route a hostname or `*.domain` to a tunnel) launched 2025-09-18 and is "free for all Cloudflare One customers"; default initial resolved IPv4 range moved from a CGNAT range to `172.64.128.0/20` (2026-08-11). — [Hostname routing changelog](https://developers.cloudflare.com/changelog/post/2025-09-18-tunnel-hostname-routing/); [Connect a private hostname](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/connect-private-hostname/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)

#### Mesh (formerly WARP Connector and peer-to-peer)
- Mesh [FREE-BETA per docs; launch blog says "50 nodes and 50 users free", "included with every Cloudflare account"]: docs say "Cloudflare Mesh is available in beta to Cloudflare One accounts, including accounts on the Free plan" (page updated 2026-09-16); the launch blog and changelog (both 2026-04-14, Agents Week) do not state a stage and make no future-pricing statement. — [Mesh platform](https://developers.cloudflare.com/mesh/platform/); [Launch blog](https://blog.cloudflare.com/mesh/); [Changelog entry](https://developers.cloudflare.com/changelog/post/2026-04-14-cloudflare-mesh/)
- Allowance and limits: 50 Mesh nodes per account (raised from 10 on 2026-04-14, so the old 10-node WARP Connector limit is superseded); routes shared with Tunnel (1,000). — [Changelog entry](https://developers.cloudflare.com/changelog/post/2026-04-14-cloudflare-mesh/); [Account limits](https://developers.cloudflare.com/cloudflare-one/account-limits/)
- What it does: every enrolled server, laptop and phone gets a private Mesh IP (TCP/UDP/ICMP); nodes run the Cloudflare One Client headless on Linux (RHEL 9/10, Debian 12/13, Fedora 43/44, Ubuntu 22.04/24.04/26.04; AMD64 or ARM64; 75 MB disk, 35 MB RAM) or the `cloudflare/mesh` container image (added 2026-08-07); nodes must use the MASQUE protocol (hostname routes, IPv6 CIDR routes and HA do not work on WireGuard); CIDR routes, hostname routes (2026-07-02), IPv6 routes (2026-05-06) and active-passive HA replicas exist; Gateway network policies, posture and Access rules apply. Mesh suits bidirectional long-lived private IP traffic; Tunnel suits publishing specific apps/hostnames/IPs through an outbound-only connector. — [Mesh overview](https://developers.cloudflare.com/mesh/); [Mesh get started](https://developers.cloudflare.com/mesh/get-started/); [Mesh platform](https://developers.cloudflare.com/mesh/platform/); [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)
- Workers VPC (beta, free to all Workers plans while in beta) can bind to a Tunnel or the whole Mesh network (`cf1:network`) so Workers reach private services. — [Workers VPC networks](https://developers.cloudflare.com/workers-vpc/configuration/vpc-networks/); [Launch blog](https://blog.cloudflare.com/mesh/)
- Rename date discrepancy: the changelog dates the WARP Connector to Mesh rename 2026-04-14, while a search-result summary of a Cloudflare Community post (page itself returned 403) dates the product renames to 2026-02-18. — [Changelog](https://developers.cloudflare.com/cloudflare-one/changelog/)

### Inferences
- Tunnel carries no per-GB or per-tunnel price anywhere in the docs; the realistic ceilings are the account limits and the terms about video/large files on public hostnames.
- A named tunnel for a public website needs a Cloudflare zone (a Free zone on full setup is fine); no-domain options are Quick Tunnels (public) or private routes/Mesh (private).
- Mesh's "50 nodes and 50 users" free allowance and the Free plan's 50-user cap look aligned, but no source says whether Mesh users consume Zero Trust seats.

### Gaps
- Post-beta Mesh pricing is undisclosed; docs call it beta while launch posts do not, so its status may be inconsistent.
- No source states exactly what happens when the 1,000-tunnel or 50-node limit is hit.
- TryCloudflare-specific terms of service were not located beyond the "testing and development" note.

## 3. Consumer and free network services: 1.1.1.1 resolver, 1.1.1.1 for Families, WARP app / WARP+, Spectrum

### Takeaway
The 1.1.1.1 public resolver (including the Families variants and the free 1.1.1.1/WARP app) is free, account-free and has no SLA; WARP+ Unlimited is a paid app-store subscription; Spectrum has no free tier (Pro/Business paid add-on for SSH/Minecraft/RDP only, Enterprise for TCP/UDP).

### Cited Findings
- 1.1.1.1 public resolver [FREE-FOREVER]: "1.1.1.1 is free", "Available on all plans", supports DoH and DoT, does not sell user data, also reachable as a Tor hidden service; setup needs no special software. — [1.1.1.1 docs](https://developers.cloudflare.com/1.1.1.1/)
- Endpoints: unfiltered 1.1.1.1 / 1.0.0.1 and 2606:4700:4700::1111 / ::1001, DoH `https://cloudflare-dns.com/dns-query`, DoT `one.one.one.one`; 1.1.1.1 for Families (malware) 1.1.1.2 / 1.0.0.2 and 2606:4700:4700::1112 / ::1002, DoH `https://security.cloudflare-dns.com/dns-query`, DoT `security.cloudflare-dns.com`; Families (malware + adult content) 1.1.1.3 / 1.0.0.3 and 2606:4700:4700::1113 / ::1003, DoH `https://family.cloudflare-dns.com/dns-query`, DoT `family.cloudflare-dns.com`. Android Private DNS accepts DoT or DNS-over-HTTP/3. — [Network operators](https://developers.cloudflare.com/1.1.1.1/infrastructure/network-operators/); [Android setup](https://developers.cloudflare.com/1.1.1.1/setup/android/)
- Other protocol notes: DNSSEC-validating resolver; Oblivious DoH target at `odoh.cloudflare-dns.com` (the underlying RFC is experimental and not IETF-endorsed; page updated 2026-10-02). 2026 changes: DoH JSON `data` field format changed for additional record types on 2026-07-28 ("breaking changes"; JSON schema not guaranteed stable, wireformat is the stable choice) and RFC 8509 root-key sentinel support added 2026-09-24. — [FAQ](https://developers.cloudflare.com/1.1.1.1/faq/); [ODoH](https://developers.cloudflare.com/1.1.1.1/encryption/oblivious-dns-over-https/); [1.1.1.1 changelog](https://developers.cloudflare.com/1.1.1.1/changelog/)
- Privacy: Public Resolver logs and truncated IPs are deleted within 25 hours; client IPs not stored in non-volatile storage (sampled packets up to 0.05% of traffic aside); no sale or sharing of personal data and no ad targeting; anonymized data shared with APNIC for research; practices audited by a top-four accounting firm; aggregated data may be kept indefinitely. — [Public resolver privacy](https://developers.cloudflare.com/1.1.1.1/privacy/public-dns-resolver/)
- Terms and SLA: governed by Cloudflare's Website and Online Services Terms; "no service level agreements (SLAs) are provided" and Cloudflare Gateway is recommended if you need SLAs and dedicated support. — [Terms of use](https://developers.cloudflare.com/1.1.1.1/terms-of-use/); [SLA and support](https://developers.cloudflare.com/1.1.1.1/infrastructure/sla-and-support/)
- Rate limiting: typical Internet-facing use is not rate limited; security scanning, proxied traffic, very high per-IP rates and high rates of uncacheable responses (for example SERVFAIL) may be limited; no numeric thresholds published; customizable DNS policies, analytics and custom rate limits are Zero Trust (Gateway) features. — [Network operators](https://developers.cloudflare.com/1.1.1.1/infrastructure/network-operators/)
- Consumer WARP app (1.1.1.1: Faster Internet) [FREE-FOREVER]: downloaded "for free" on iOS and Android, defaults to WARP mode; modes are DNS only (formerly 1.1.1.1), Traffic and DNS (formerly 1.1.1.1 with WARP; MASQUE with post-quantum encryption), Traffic only, Local proxy (desktop); the 1.1.1.1 app also switches between 1.1.1.1 Families options. Docs for this consumer product are separate from the Cloudflare One Client. — [WARP modes](https://developers.cloudflare.com/warp-client/warp-modes/); [iOS setup](https://developers.cloudflare.com/warp-client/get-started/ios/); [WARP client docs](https://developers.cloudflare.com/warp-client/)
- WARP+ Unlimited [PAID-ONLY]: a paid monthly subscription bought through the Apple App Store or Google Play (price shown in-app, not in docs); gives access to a larger network of cities (potentially lower latency); one license key works on up to five devices. No bandwidth caps or device limits are stated for free WARP. — [WARP modes](https://developers.cloudflare.com/warp-client/warp-modes/)
- Spectrum [PAID-ONLY]: "Available on Paid plans"; Free = not available; Pro and Business = paid add-on limited to Minecraft and SSH (Pro) and Minecraft, SSH and RDP (Business), one app each; TCP, UDP, HTTP and HTTPS applications are Enterprise-only paid add-ons. The Spectrum product page lists a monthly data allowance of 5 GB (Pro) or 10 GB (Business) with $1/GB overage (page text was garbled, so treat as indicative). — [Spectrum docs](https://developers.cloudflare.com/spectrum/); [Protocols per plan](https://developers.cloudflare.com/spectrum/protocols-per-plan/); [Spectrum get started](https://developers.cloudflare.com/spectrum/get-started/); [Spectrum product page](https://www.cloudflare.com/application-services/products/cloudflare-spectrum/)

### Inferences
- 1.1.1.1 Families is fixed-category filtering with no customization; custom blocklists, per-location policies and logs need a Zero Trust Gateway DNS location (Free, up to 3 locations).
- For a Free-zone user needing non-HTTP exposure (SSH, game server), Spectrum is unavailable, so Tunnel/Mesh/Quick Tunnel or Access browser-rendered SSH are the free routes.

### Gaps
- WARP+ price, and any current bandwidth/fair-use limits on free consumer WARP, are not in the docs I could fetch.
- No numeric 1.1.1.1 rate limits published.
- Exact Spectrum add-on prices for Pro/Business are not in the docs (only the allowance/overage hints from the product page).

## 4. How these could support a website + app

### Takeaway
On a Free account the highest-value combos are Access (admin/staging protection), Tunnel (expose a home or dev origin with no open ports), Quick Tunnels (share a prototype or receive webhooks), Gateway + Cloudflare One Client (team device filtering) and Mesh (private server-to-server access).

### Cited Findings
- Access in front of a site needs an active domain on Cloudflare, an IdP (the Cloudflare IdP is default, one-time PIN available) and Allow policies (deny by default); service tokens give machine access without seats. — [Self-hosted public app](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/); [Service tokens](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/)
- Access can protect Workers (workers.dev and preview URLs, one Worker or all Workers). — [Changelog 2026-08-14 text](https://developers.cloudflare.com/changelog/product-group/cloudflare-one/3/)
- Tunnel publishes `app.example.com` to a local service via a proxied CNAME to the tunnel; Quick Tunnels give a random trycloudflare.com URL with optional email-PIN protection; Mesh/Workers VPC let Workers or teammates reach private services. — [Create a tunnel](https://developers.cloudflare.com/tunnel/get-started/); [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/); [Mesh blog](https://blog.cloudflare.com/mesh/)
- Gateway DNS locations (up to 3 on Free) can filter an office/home network; the Cloudflare One Client adds network/HTTP policies and device posture. — [Cloudflare Access product page](https://www.cloudflare.com/sase/products/access/); [Resolver endpoints](https://developers.cloudflare.com/cloudflare-one/traffic-controls/resolver-endpoints/)

### Inferences
- Admin panel / staging site: Access self-hosted app + Tunnel to a dev box, one-time PIN or GitHub/Google login, service token for CI smoke tests.
- Preview sharing: `cloudflared tunnel --url ... --allowed-mail '*@yourdomain.com'` for client previews and webhook testing without a domain.
- Team devices: Cloudflare One Client + Gateway DNS/HTTP policies and posture for up to 50 users; only 24 h of logs.
- Private backends: Tunnel private routes or Mesh nodes so only enrolled devices and Workers (via Workers VPC) can reach databases and internal APIs.
- Public traffic carrying video/large files over a Free-zone Tunnel public hostname conflicts with the terms noted in section 2; serve media from R2/Stream or similar instead.

### Gaps
- Product-by-product "guide steps" were not researched (out of scope); account and billing sequencing (card on file at Zero Trust onboarding, domain onboarding for public hostnames) should be confirmed against the live dashboard.
